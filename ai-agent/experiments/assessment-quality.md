# Оценка знаний: development, 13 ноября 2026

**Текущая локальная Qwen3 4B не прошла приёмку оценщика.** Контракт/защитные проверки реализованы, смысловое качество не подтверждено. Прогон не связан с MCP/Go/админкой. Эти результаты не относятся к качеству чат-агента из прежнего сравнения оркестрации.

Модель qwen3:4b-q4_K_M, локальная Ollama, context 4096, think=false, temperature=0, seed=42; модельный timeout 20 с, общий 25 с. Прогрев вынесен за бюджет. [Полный текущий отчёт](assessment-development-knowledge-assessment-v3-20261113T162716093408Z.json) сохраняет digest модели, prompt/hash, dataset/hash, HTTP-ответы и длительность. Набор [knowledge-v1](../evals/knowledge-v1.json) и разметка черновые, требуют проверки команды.

Итог: 2/6 полных совпадений, оба — правила без LLM. **Содержательные модельные случаи: 0/4 успешных; 0/9 критериев засчитано**, потому что оценка не опубликована. Две ошибки AI_TIMEOUT и две AI_INVALID_RESPONSE; 503 считается провалом доступности/оценки. Guards отдельно: 2/2, 6/6 критериев unclear совпали. Ноль опубликованных ложных pass в этом прогоне объясняется отказами, не доказывает правильность оценщика.

Повторяющаяся проблема — модель выбирала цитаты, отсутствующие дословно в answer. Валидатор отклонял их; одна коррекция не помогла либо закончился общий deadline. Проверка substring защищает подлинность цитаты, но сама по себе не проверяет её смысл относительно рубрики. Нельзя ослаблять проверку ради красивой метрики.

## История development

- Первый полный v1-прогон показал один ложный pass и трудности с неоднозначным ответом. Его полный raw-файл был случайно перезаписан повторным запуском; он не используется как воспроизводимый baseline. [Сохранившийся прерванный повтор](assessment-interrupted-v1.json) явно complete=false и не является полным прогоном. Численные сравнения с ним не заявляются.
- [Полный v2](assessment-development-v2.json): 2/6 совпали, только rule guards; три таймаута и неправильная оценка неоднозначного ответа. Длинные генерируемые причины оказались слишком медленными на этой машине.
- v3 сократил внутренний output до reason_code и quote, Python формирует краткое обоснование. Он не решил проблему достоверности цитат. Входы, ожидаемые метки и бюджеты времени не менялись.

После этой итерации настройка остановлена: компонент не объявляется качественным только по зелёным unit-тестам. Candidate holdout 2 примера **не запускался live** и не использовался для настройки. Полный запланированный набор 20 development / 10 holdout для всего агента ещё не готов. Отсутствие LLM-вызовов в offline тестах обязательно; они проверяют контракт, а не способность модели оценивать смысл.

## Следующее решение команды

Согласовать рубрики и разметку с наставником, расширить development по ошибкам, сравнить подходящие доступные LLM на одинаковых входах и бюджетах. До просмотра holdout зафиксировать модель/промпт/корпус и пороги качества. При 503 сохранять ответ и направлять на ручную проверку. Переход этапа в любом случае одобряет наставник, а применяет Go. Подключение нового провайдера или платные вызовы этим блоком не выполнялись.

Проверки кода этого среза: Ruff format/check, строгий mypy, 205 pytest-тестов при остановленной Ollama; покрытие всего Python-кода с experiments — 90,22%, gate 85%. OpenSpec strict validation и согласованность JSON-примеров со схемами прошли. Это показатели реализации контракта и отказов, а не качества LLM. Полный just check локально не запускался: код Go/UI не менялся, их общие проверки оставлены CI.
