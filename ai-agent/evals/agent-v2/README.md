# Agent-v2: development текущего агента

25 development-кейсов, статус `draft_requires_team_review`. **Holdout в этой версии нет:** исходный agent-v1/holdout не копируется, не меняется и не исполняется. Новый набор согласует тестовое окружение с SDD 007/008, не объявляя эти тесты живой проверкой Go или сайта.

- [Данные и ожидания](development.json), [manifest с SHA](manifest.json).
- [Поведение и границы изменения](../../../openspec/changes/implement-python-agent/development-v2-scope.md).
- [Harness](../HARNESS.md): запуск с `--dataset agent-v2`; старое поведение доступно с `--dataset agent-v1` (значение по умолчанию для совместимости).

Все данные demo.example, контакты, права, бюджеты, сроки и инструкции синтетические, не регламенты Авито. Каталог содержит 11 инструментов; submit объявляется только при явном fixture permission access:submit. Даже в этом случае реального Go AccessIntent/ACL и внешней записи нет. prepare создаёт только синтетический receipt черновика; выполнение остаётся ручным действием пользователя на сайте. Agent оценивает, наставник одобряет.

## Дополнительные случаи

- dev-21: search → полная страница Confluence; ответ по body, не только excerpt.
- dev-22: свои access requests; submitted не означает выдачу прав.
- dev-23: catalog → submit по полным данным пользователя и явному fixture permission; проверяются точные параметры и номер, не выдача прав.
- dev-24: benefits-context → prepare; черновик и ручное подтверждение, без ложного успеха операции.
- dev-25: Jira по ключу DEL-1; issue_id берётся только из UUID результата, никаких изменений задачи.

Минимальные counts/точные аргументы и факты сохранены в JSON. Несколько fixtures одного non-search tool различаются нормализованными аргументами; search scripted, не retrieval benchmark. Допустимые source IDs не дают права цитировать не вызванный источник. Обязательные facts и forbidden claims проверяются отдельно от HTTP/schema; unknown tool/args не подменяются успехом.

Сравнивать эффект исправления можно только **до/после на этом же наборе**, с полными сохранёнными trials. Исторические 12/18 на agent-v1 не являются знаменателем нового 25-кейсового набора. Два частных оценивания не доказывают общую точность assessment. Human/mentor review и приёмка сайта остаются отдельными.

`tool-schemas.json` сохраняет точные схемы инструментов на момент создания
набора; его SHA совпадает с неизменённым manifest. Загрузчик проверяет
целостность snapshot и валидирует fixtures текущими runtime-контрактами.
Расширение текущих схем не переписывает прежние trials: новый отчёт хранит
SHA runtime отдельно от SHA схем набора. Сценарий прямого submit в dev-23
остаётся тестом прежнего adapter-контракта; текущий Go запрещает прямую
отправку и использует ручное подтверждение `request_access`.
