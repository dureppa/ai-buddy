## Что исправили и что откатили

- **MCP-сервер:** Host без порта теперь допускается только для loopback; реальные чужие Host/Origin отклоняются. Demo-поиск отдаёт приоритет профильному заголовку/ключевым словам вместо косвенного упоминания в чужой инструкции. Контекст профилей изолирован.
- **Harness:** SDK cleanup оборачивал ServiceError в ExceptionGroup и превращал ожидаемые FORBIDDEN/MCP_TIMEOUT в AI_UNAVAILABLE. Добавлен тот же классификатор boundary, что в runtime; регрессии проверяют реальный SDK/Flask путь. Поэтому рост общего structural score **частично исправление оценочной инфраструктуры**, не улучшение интеллекта модели.
- **Assessment-v4:** вместо переписывания цитаты модель выбирает ID заранее выделенного дословного фрагмента. Python восстанавливает текст/Unicode offsets; неизвестный ID не принимается, pass без фрагмента запрещён. В финале оба примера прошли за один вызов: dev-19 14,670 с, dev-20 6,472 с. Выбранный реальный фрагмент всё ещё может быть нерелевантным; для этих двух примеров смысл проверен отдельно, это не общая гарантия.
- **Chat:** два варианта расширения prompt/citation hints не дали устойчивого улучшения. Они сохранены как эксперименты и откатаны; финальная версия использует прежний onboarding-v2. Мы не ослабляли эталоны ради показателя и не выбирали лучший seed. Повторяемость/latency и пропуск инструментов остаются проблемой небольшой LLM.
- **Evidence regression:** отдельный тест нашёл потерю строк перед newline при разбиении ответа. Исправлен regex и проверены точные Unicode offsets с emoji. Для записанных v4 assessment-входов результат разбиения до/после совпадает; это проверено без нового LLM-прогона.

Первый запуск Ollama не смог создать Metal-контекст в ограниченной среде; до начала кейсов восстановлен локальный GPU-доступ. Этот preflight не является оценкой ответов. Серверы, поднятые для проверки, остановлены после прогона.

Raw-отчёты содержат git HEAD и SHA исходников на момент запуска, включая ещё не закоммиченные evaluation-файлы. Это честная привязка snapshot, не заявление, что git HEAD один полностью описывает их состояние. Все raw-ответы/промпты сохранены; код harness-v1 имел явно описанную ошибку cleanup. Промежуточный reviewed-отчёт chat-v4 и review-candidate-v4.json также сохранены, но не являются финальным решением.

Первая попытка до установки frontend dependencies завершилась отсутствием @eslint/js; исходники и lock-файлы Go/UI не менялись. Это не проверка реальных Go API/БД/онбординга и не заявление общего покрытия команды выше 80%.

Следующий приоритет — review эталонов наставником и сравнение более подходящих доступных моделей на development. Go HTTP adapter, реальный retrieval/ACL и полный путь сохранения/перехода ещё не проверены. Holdout нужен после заморозки и отдельного разрешения.
