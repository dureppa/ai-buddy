## Уточнение и побочная регрессия

В dev-02 исходный финальный ответ перечислял поля и выдумывал примеры «отпуск или отгул». После исправления реальный итог:

> Для оформления отсутствия нужны тип отсутствия, дата начала и дата окончания — пришлите их значения, пожалуйста. Автоматическая отправка заявки из чата не поддерживается.

Это явная просьба прислать значения; неподтверждённых примеров нет. Агент не отправлял операцию. System prompt, восстановление контекста и исправление цитаты больше не должны заменять уточнение описанием формы. Уже названные параметры повторно не запрашиваются.

Первое исправление добавило в ответ dev-13 лишний комментарий «Недостающих значений для ответа нет…». Причина — слишком общая подсказка в citation repair. Она заменена указанием исправлять только цитаты и сохранять смысл. Финальный dev-13 содержит только имя/контакт наставника. Регрессии проверяют обе цепочки; промежуточный trial сохранён без заявления полного semantic-pass.

## Вызовы и ограничения

- Во всех trial исполнены 25/25; blocked=0. Все 11 имён инструментов реально встретились в трассе, но их реальный Go/ACL/БД не проверялись. Synthetic permission access:submit выдан только dev-23.
- Исходный: 45 provider-запросов, 222 180 токенов; промежуточный: 44 / 221 541; финальный: 44 / 221 228. Всего 133 / 664 949 по usage провайдера. Денежная стоимость не вычислялась без сохранённого тарифа/cache billing.
- Финальный: 24 HTTP 200 и один ожидаемый MCP_TIMEOUT в dev-16. Доменный FORBIDDEN в dev-06 корректно объяснён HTTP 200 по текущему SDD 008. Других ошибок провайдера/таймаутов не наблюдалось.
- Оба assessment-кейса во всех trial совпали с эталонными verdicts/recommendation и обязательным review; этого недостаточно для общей точности оценки знаний.
- p50 HTTP-200 кейсов: исходный 2,535 с, промежуточный 2,512 с, финальный 2,696 с, N=24 каждый. Это отдельные диагностические выборки, не SLA или сравнение скорости под нагрузкой.
- Модель requested/returned deepseek-flash — alias без pinned snapshot. Источники demo.example и все данные синтетические. Отчёты содержат code/prompt/dataset/schema hashes; ключ/headers/reasoning и делегированный bearer в model trace не сохранены.

Выполнены Python Ruff/mypy/pytest, schema/hash validation и OpenSpec strict. Полный just check запускает также Go/фронтенд без изменения их исходников. На финальном коде полный just check прошёл: 578 pytest / покрытие Python 91,20%, Ruff/mypy, Go и frontend проверки успешны. Локальные DB-тесты без TEST_DATABASE_URL не являются проверкой живой PostgreSQL; её запускает CI. Git diff по исходному agent-v1, apps/, Go и публичным contracts/ пустой.

Реальное изменение этого блока — поведение уточнения в Python-агенте. На сайте оно появится после успешного развёртывания соответствующего Python-кода. Fixtures development не создают новых данных и кнопок: доступность пользовательского пути нужно отдельно проверять через Go/MCP/UI. Проверка навигации кнопок чата выполняется следующим самостоятельным блоком по запросу пользователя.
