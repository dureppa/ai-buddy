# Прямой цикл и LangChain create_agent

Дата: 13.11.2026. Локальный development smoke, шесть случаев × два подхода, один парный прогон с чередованием порядка. Это не production-агент и не статистическое исследование.

## Одинаковые условия

Qwen3 4B Q4_K_M, digest `2bfd38a7daaf4b1037efe517ccb73d1a3bbd4822cf89f1a82be1569050a114e0`, Ollama 0.40.16, Apple M2 / 8 GiB. Температура 0, seed 42, thinking=false, контекст 4096, максимум ответа 384 токена. System prompt и schemas/descriptions инструментов одинаковы; сценарии заданы до прогона. API-платежей и загрузки новых весов не было.

Два действующих инструмента search_knowledge/get_team_context работают через настоящий Python MCP client/server Streamable HTTP в ASGITransport и существующий Gateway. Корпоративный Go API и UI не использовались и не изменялись. Direct вызывает Ollama через HTTP без LangChain; create_agent — через ChatOllama и общий MCP-адаптер middleware. Разные SDK/сериализация остаются фактором сравнения. Tool calls, результаты, ответы, настройки и версии сохранены в [исходном JSON](comparison-results.json).

Поэтому 3/6 — результат конкретных строгих проверок, не универсальная оценка качества. Ручное чтение выявляет проблемы даже у формально прошедшего случая одобрения.

## Решение

В этом срезе create_agent не дал преимущества качества над прямым циклом. Он уже работает с нашим Gateway, поэтому вариант доступен для дальнейшей проверки. Однако добавлено 29 dev-пакетов, включая LangGraph, тогда как простой цикл обходится имеющимся httpx. Для короткого ограниченного read-only сценария разумно пока использовать прямой цикл как базу; окончательный production-выбор остаётся открытым. Если появятся сложные ветвления, сохранение выполнения или восстановление длинных процессов, основания для LangGraph нужно оценить отдельно.

До подключения пользователям нужны: контроль источников цитат по фактически полученным данным, безопасное представление недоверенного контента, уточнённый оценщик с семантическими вариантами, расширенный development/holdout, повторные парные прогоны и отдельное сравнение более сильных доступных LLM. Одного system prompt недостаточно для гарантии защиты от инъекций. Go по-прежнему проверяет роли и применяет переход только после решения наставника.

## Запуск и проверки

Из services/ai-python:

```bash
uv sync --locked
# Ollama должен уже работать локально; модель должна быть установлена.
uv run --locked python -m experiments.compare
uv run --locked pytest tests/test_agent_loops.py
```

Команда сравнения перезаписывает comparison-results.json, сохраняет прогресс после каждого случая; веса не скачивает, LangSmith tracing выключает. При ошибке старта MCP/прогрева CLI завершится ошибкой, уже записанные строки сохранятся. Для CI live-run не требуется: scripted-тесты проверяют оба цикла, лимиты модели/инструментов, неизвестный tool, неверные аргументы, FORBIDDEN, MCP timeout, общий deadline, пустой ответ и настоящий MCP-fixture. Покрытие с `--cov=.` включает экспериментальный Python-код, тесты и зависимости исключены. Итоговые проверки: 85 тестов прошли при остановленном Ollama, покрытие 93,54% (588 строк); Ruff format/check, строгий mypy и OpenSpec validate прошли. Отдельно проверен лимит шести одновременных попыток инструментов. Полный just check локально не запускался; Go/UI проверяет CI.

[create_agent](https://docs.langchain.com/oss/python/langchain/agents), [ChatOllama](https://docs.langchain.com/oss/python/integrations/chat/ollama), [нативный tool calling](https://docs.ollama.com/capabilities/tool-calling).
