# Agent-v1: 20 development и 10 candidate holdout

Подготовлен 13.11.2026. Это первый общий **кандидат в golden dataset**, статус `draft_requires_team_review`. Факты и оценки подготовлены, но человек ещё не утвердил разметку. ТЗ не требует именно числа 20/10 — это наш объём A-05.

- [Development](development.json): 20 кейсов для разработки и диагностики.
- [Holdout](holdout.json): 10 новых кейсов по отдельным scenario families; live не запускался и в промпты не включался.
- [Каталог](catalog.md): вопросы, факты и вызовы для чтения.
- [Manifest](manifest.json): версии, SHA-256 обоих файлов и схем текущих MCP-инструментов, статус review.
- [Порядок оценки](runbook.md): как получать оценки без смешения структурной проверки и качества модели.
- [Исследование дополнительных мер](../../../../docs/ai/quality-control.md).

## Что покрыто

У каждого из шести сервисов есть положительный и отрицательный/ограничивающий пример. Дополнительно включены свой наставник и неизвестный лид, пустой поиск, legacy-доступ вне области, вредоносный документ, старые ссылки из истории, неизвестный DOM, архивная инструкция, смешение результатов сервисов, MCP timeout, LLM 429 и оценка знаний. Набор включает multi-message history и зависимые цепочки будущих read-tools. Это начальная выборка основных групп, не исчерпывающая проверка каждого Scenario OpenSpec.

26 кейсов помечены `python_ready`: у них уже есть совместимый Python HTTP/MCP-контракт. **Это не означает, что модель их прошла.** Четыре кейса `dev-17`, `dev-18`, `hold-07`, `hold-08` заблокированы неподключёнными progress/task/evidence-инструментами и Go-интеграцией. Они остаются в полном наборе и не засчитываются как pass. Предложенные result fixtures этих tools — семантические примеры A-02, не утверждённые схемы Go.

Оценщик знаний и разговорный агент проверяются раздельно: 4 assessment-кейса имеют отдельные вход/эталонные verdicts; остальные 26 — chat-кейсы, включая 4 blocked. Компонентный [knowledge-v1](../knowledge-v1.json) сохранён; его 6/2 примера не являются новыми 20/10. Прежние шесть live Q&A-примеров тоже не подменяют этот набор.

## Источники и допущения

Все `demo.example`, имена, контакты, права профилей, доступность бенефитов, кнопки, статусы и данные моков **синтетические**. Это не действующие процедуры Авито. Реестр оснований — [sources-and-assumptions](../../../../openspec/changes/implement-python-agent/sources-and-assumptions.md): шесть категорий — TZ/DEC-01, чек-лист и исполнители — CL, агент оценивает/наставник одобряет — DEC-02. Конкретные поля/данные — наши A-01/A-02/A-03, не новые сведения из внешних источников. Указание диапазона CL — привязка demo-плана к исследованной версии, не дословная цитата строки.

`expected.facts[].support` содержит JSON Pointer в fixture/вход либо `policy:Requirement-ID`. Audit проверяет существование основания; он **не доказывает смысловое следование** утверждения из него. Это проверяет разметчик. Отсутствие материала, `null` и ошибка являются явными основаниями для отказа от неподтверждённого ответа, а не поводом выдумать данные.

## Формат

`input` — валидный TurnRequest либо AssessmentRequest. Только он и соответствующие результаты разрешённых инструментов могут попасть агенту. `expected`, `context` с оценочными метаданными, эталонные MCP-планы и запрещённые утверждения — данные проверяющего. В assessment поле `criteria.expected` во входе — сама рубрика знаний, а `expected.assessment.criteria` с pass/fail/unclear — скрытая от оценивающей модели gold-разметка.

`expected.calls` задаёт допустимые имена/число вызовов. Для поиска `arguments_example.query` — пример, не единственная допустимая строка; `query_intent` оценивает смысл, схема проверяет реальные аргументы. Для остальных tools аргументы точные. `min_calls=0` допускает корректный отказ/уточнение без поиска; это важно для явно запрещённого действия и неизвестной страницы. Неуказанный tool запрещён; повтор поиска допустим только в указанном бюджете и для того же намерения/прав. `ordered_tools` задаётся только при зависимости. `allowed_source_ids` — верхняя граница источников, `required_source_ids` — минимально нужные ссылки, `forbidden_source_ids` — запрет даже при наличии в истории/исключённом документе. Дополнительно человеческая проверка требует источник для каждого корпоративного утверждения.

Во всех кейсах агент не отправляет корпоративное действие и не переводит этап. Это не отрицание действий пользователя/наставника: будущая сквозная проверка должна отдельно наблюдать их запись в Go. `state_before/after` в blocked-кейсах задают ожидаемую неизменность за время **ответа агента**, а не результаты реального запуска Go. Успешная внешняя запись/перезагрузка/атомарный переход после одобрения, prepare/draft idempotency и полный UI-путь остаются отдельной acceptance-работой.

## Проверка без модели

Из `services/ai-python`:

```bash
uv run --locked python -m evals.golden
uv run --locked pytest tests/test_golden.py
```

Audit проверяет оба split, 20/10, уникальность ID/входов, отсутствие family overlap, ссылки на требования и основания, текущие HTTP/MCP-схемы, закрытые аргументы, допустимые source IDs, хеши и честную маркировку blocked. Тесты дополнительно пропускают реализованные fixtures через настоящий Gateway с тестовой Session. Это не сетевой Go MCP и не проверка выбора инструмента моделью.

По умолчанию `load_split()` загружает только development. Для holdout нужен явный `load_split("holdout")`. Просмотр файлов автором/ревьюером необходим для приёмки; набор не является внешним слепым benchmark. Семейства и точные входы разделены, но общий домен, схемы и ограничения неизбежно общие. Нельзя обещать статистическую независимость по одной проверке уникальности строк.

Общий [development harness](../HARNESS.md) теперь реализован отдельно; автоматический factual LLM-judge не подключён. Старые `experiments.compare` и `assessment_eval` используют свои прежние наборы, их запуск не является прогоном agent-v1. Development выполнен на 18 доступных кейсах с отдельным Codex-assisted review. [Результаты](../reports/README.md). На полном наборе 30 кейсов качество не измерено: holdout не запускался, четыре общих кейса всё ещё blocked.

Проверки блока: 35 новых тестов набора/fixtures, всего 240 pytest-тестов; Python coverage с evals и experiments — 89,82%, gate 85%. Ruff, mypy и OpenSpec strict validate прошли. Проверены 108 локальных ссылок и соответствие каталога всем 30 вопросам/фактам. Полный just check локально не запускался: код Go/UI/runtime агента не менялся, общие проверки оставлены CI. Это не результаты ответов LLM.
