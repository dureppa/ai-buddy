## Согласованные решения команды

- DEC-01: только шесть сервисов: absences, business_trips, hiring, dismissals, consents, benefits. Английские коды — наши предлагаемые идентификаторы, не идентификаторы Авито.
- DEC-02: агент оценивает, наставник одобряет, Go проверяет и сохраняет переход. Админка — интерфейс наставника, не самостоятельный субъект решения.
- DEC-03: три навигационных раздела «Старт», «Команда и план», «Профессия и продукт» — наша группировка. Исходные периоды и ответственные сохраняются; дата сама по себе не завершает задачу. Справка и помощь на поддерживаемой странице доступны постоянно.
- DEC-04: для действий вне шести API допускается подтверждение наставником либо явно предусмотренный самоотчёт; отсутствие интеграции не маскируется выдуманным фактом.
- DEC-05: найм и увольнения — справка/разрешённое чтение синтетических сведений, без агентских кадровых решений. Остальные изменения требуют отдельного подтверждения пользователя.

## Допущения, подлежащие согласованию

| ID | Предложение | Владелец и приёмка |
| --- | --- | --- |
| A-01 | Набор обязательных задач, зависимости и условия завершения | Наставник/команда утверждают demo-план с источниками до реализации |
| A-02 | Поля моков, состояния, виды согласий/льгот, согласующие | Go + UI + Python подтверждают OpenAPI и примеры; не объявлять реальным регламентом |
| A-03 | Знания проверяются по фиксированной рубрике; pass по всем обязательным критериям, unclear требует проверки | Команда утверждает вопросы и критерии; LLM не изменяет рубрику |
| A-04 | Начальные бюджеты хода: 25 с, LLM 15 с, MCP 5 с, 3 LLM-попытки и 6 tool-попыток, одна коррекция | Проверить на smoke; все повторы входят в общий бюджет, Go ждёт 30 с |
| A-05 | 20 development и 10 holdout-кейсов, Python line gate 85% | Наш начальный объём, не численное требование ТЗ; P0 без нарушений, качество/задержки измерить |
| A-06 | Фиксированный URL MCP, делегирование на 60 с, draft TTL до 10 минут по ответу Go | Проверить совместимость с Go; не переносить старый TTL API доступа на новые сервисы |

Не подтверждены источниками: реальные схемы шести API, правила льгот для стажёров, порядок подписания документов, универсальная модель оценки стажёров LLM и обязательность трёх последовательных этапов. В демо все такие сведения должны быть явно учебными.
