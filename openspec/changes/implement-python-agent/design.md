# Design

## Context

Онбординг — контекст работы агента по [источникам](sources-and-assumptions.md). Исходный чек-лист содержит задания разных исполнителей и периодов. Текущий Go baseline origin/main e1c8c27 содержит HTTP API и прежний каталог технических сервисов; наличие кода не означает готовность новых шести API, MCP или runtime-проверку. Go/UI и миграции не меняются; Python-каркас реализуется отдельным срезом.

## Goals / Non-Goals

Цель — описать поведение агента, взаимодействующего с чек-листом и шестью сервисами. Не проектируются полноценные HR-системы, новые LMS/IT/календарные интеграции, самостоятельная выдача доступа, автоматическое кадровое решение или переход по тексту LLM.

## Decisions

### D1. Ответственность

Go владеет субъектом, ACL, задачами, источниками фактов, историей, решениями наставника и переходами. Python + Flask — доверенный MCP-клиент, подготовка контекста/промптов, ограниченный LLM-цикл, проверка результата и оценка знаний. Отдельный Python MCP-сервер предоставляет tools и позднее вызывает обычный Go HTTP API; локальный demo уже использует учебный backend. UI показывает результат Go, принимает подтверждения стажёра и решения наставника. Факты моков и ручные подтверждения не подменяются самооценкой модели.

### D2. Контекст задания

Go предоставляет task_id, исходный лист/пункт/версию, исполнителя (trainee/mentor), период, обязательность, зависимости, допустимые способы проверки, task_version, rubric_version и доступные источники. Разделы onboarding — навигация DEC-03, не новые корпоративные сервисы. Закрытый источник может быть показан только разрешённому субъекту. Внутренние материалы, названные в чек-листе, не считаются загруженными только по наличию названия/ссылки.

Задания имеют todo/in_progress/needs_review/done. Подтверждение ознакомления допустимо только для задачи с явно заданным self_report. External_fact требует записи соответствующего сервиса; manual_review — решения уполномоченного наставника. Knowledge_check хранит ответ и рубрику отдельно от диалога обучения.

### D3. Доказательства и оценка

Go хранит evidence_id, task_id, source_type, source_record_id, source_version, observed_at и привязку к субъекту. Источник определяет Go. Evidence сообщает ровно свой смысл: заявка отправлена, а не одобрена; документ подтверждён, а не юридически подписан; встреча назначена, а не проведена. Если проверка недоступна, итог unknown, а не done.

Python получает выданный Go evaluation_id, версию ответа, задания, рубрики и контекста. Отдельный оценочный prompt возвращает по критериям pass/fail/unclear, краткое обоснование и ссылку на фрагмент ответа, затем recommendation. Скрытая цепочка рассуждений не требуется и не публикуется. Python валидирует структуру и передаёт результат внутренним API Go. Запись оценки не завершает задание и не повышает полномочия агента.

Текущий Python-срез: [assessment-scope](assessment-scope.md). Модель возвращает reason_code/quote; Python формирует verdict, краткое обоснование и recommendation. Go persistence/review не реализуются этим срезом, Qwen development не прошла.

### D4. Переход этапа

Состояния этапа: locked → in_progress → awaiting_review → completed. Go вычисляет готовность по обязательным заданиям и актуальной принятой оценке; наставник отдельно одобряет через UI. Перед атомарным переходом повторно проверяются полномочия наставника, версия плана и свежесть обязательных фактов. Отказ возвращает in_progress с замечаниями; конкурирующее/повторное решение не создаёт второй переход. Несвязанная справка не блокируется этапом.

Если LLM недоступна, ответ стажёра сохраняется и возможна ручная проверка знаний наставником с автором и причиной. Она не превращает отсутствующее согласие/разрешение в выполненное внешнее действие. Поздняя оценка модели не перезаписывает решение человека или новую версию ответа.

### D5. Корпоративные операции

Каталог — [MCP-контракты](mcp-contracts.md). Для шести API используется договорённый Go-адаптер; нет прямого доступа Python к таблицам моков. Чтение и подготовка черновиков доступны модели по ACL; отправка, согласия и решения наставника — отдельные аутентифицированные действия Go. Нельзя требовать от стажёра увольнения, командировки или заказа бенефита для прохождения адаптации. Для фактов вне этих API используется DEC-04.

До внешней записи Go сохраняет стабильный operation_id и snapshot аргументов/владельца. Retry использует тот же ключ; таймаут после записи требует сверки результата. Настоящая операция, возвращённый результат, отображение и сохранение проверяются отдельно. Обычный frontend toast не доказательство операции.

### D6. Внутренняя граница Python

Предлагаемый внутренний запрос содержит request_id, conversation_id и message, ограниченную историю, доверенную делегацию и при проверке знаний evaluation_id с версиями. Субъект задаётся Go вне аргументов LLM. JSON закрыт; body ≤64 KiB, message 1–4000 символов, история ≤20 сообщений user/assistant. Токены не передаются в prompt.

Предлагаемый результат: request_id и conversation_id из кода, безопасный текст/ссылки и структурированное предложение подтверждения либо оценка по соответствующему режиму. Схемы chat и assessment разделены. Предложение нового корпоративного черновика НЕ помещается в старый AccessRequestDraft. До реализации Go/UI/Python согласуют новый OpenAPI и версию; текущий публичный контракт остаётся legacy baseline. Неподдержанный режим даёт контролируемую недоступность, а не урезанный успешный ответ.

### D7. Бюджет, lifecycle и ошибки

Начальные пределы A-04: 25 с на весь ход с cleanup, одна дополнительная попытка временного сбоя, одна коррекция формата, максимум 3 LLM и 6 MCP попыток включая retries. Per-call timeout ограничен остатком общего монотонного deadline. SDK-retries входят в единый слой. Истечение не доказывает отмену внешней записи.

Сохраняется sync Flask view с одним ограниченным async run; клиенты создаются/закрываются на ход, не разделяют mutable user state или закрытый event loop. Долгое ожидание наставника хранится в Go; worker Python не удерживается. LLM-ошибки: AI_TIMEOUT, AI_UNAVAILABLE, AI_RATE_LIMITED, INVALID_MODEL_OUTPUT, AGENT_LIMIT_REACHED. Авторизация провайдера не повторяется. Нет молчаливого переключения на fake LLM. Детерминированное UI-состояние из Go работает без генерации.

### D8. Источники, prompts и диагностика

В ai_buddy/agent.py реализован версионированный system prompt чата, в assessment.py — knowledge-assessment-v3. Отдельные onboarding-help/service-help шаблоны ещё не выделены. Материалы и страницы — данные, а не инструкции, меняющие права. Для помощи на странице используется только явно переданный очищенный URL из разрешённого справочника; DOM, скриншоты и произвольная загрузка сайтов требуют отдельного контракта.

Логи: request_id, evaluation_id при наличии, версия prompt/model/corpus, инструмент, длительность, outcome и usage; без токенов, полных ответов стажёра, кадровых данных и provider error body. Readiness проверяет локальную конфигурацию без платного вызова, внешние зависимости проверяются отдельным smoke. Модель не выбрана; доступность и качество проверяются на development-наборе, решение версионируется.

## Migration Plan

1. Авторизован и реализован первый Python-срез [foundation-scope](foundation-scope.md); старые AG/MCP/QA требования draft-предложения заменены приведёнными сценариями. SVC-01…12 сохраняют общие гарантии, SVC-11 обновляет миграционную границу.
2. Согласовать реальные контракты Go, соответствие кодов шести сервисов, обязательные задачи и рубрики. Это блокирует новые write-tools до подтверждения совместимости.
3. Позже, по отдельному запросу: обновить OpenAPI/SDD/UI и реализацию, миграции и fixtures; старые маршруты доступа не удалять неявно.
4. Первый сквозной результат — чтение чек-листа → явное учебное согласие в mock → сохранённое доказательство → оценка/сводка агента → одобрение наставника → следующий этап. Проверки идут вместе с каждым срезом.
5. Архивировать change только после реализации и проверки. [Tasks](tasks.md) и [evaluation](evaluation-plan.md).

## Risks / Trade-offs

Недоступные источники не дают подтверждённых регламентов. Общий статус completed и текущая отметка PUT completion недостаточны для новых review/evidence гарантий. Публичный API ещё не поддерживает этот маршрут; реализация должна явно устранить разрыв. Все пороги и demo-правила перечислены как допущения, а не правила Авито.

Текущие реализации: [локальный Python MCP](mcp-demo-scope.md), [Go HTTP handoff](../../../docs/integrations/go-python-mcp.md), [development harness](eval-harness-scope.md). Go HTTP-адаптер/делегация не заменяются demo; full onboarding остаётся незавершённым.
