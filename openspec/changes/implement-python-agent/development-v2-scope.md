# Current development v2 и явное уточнение

15.11.2026. До реализации: исходный agent-v1 development/holdout и опубликованные trials MUST сохраняться без изменений. Новый agent-v2 содержит только development; holdout MUST NOT читаться или запускаться evaluation-командами этого блока. Человеческий review разметки остаётся pending.

## Область и данные

Новый development MUST использовать текущие 11 MCP CONTRACTS и SDD 007/008: чтение сервиса/страницы, прогресса, контекста и evidence; подготовку черновика с ручным подтверждением; ограниченную заявку доступа только при явном synthetic permission access:submit. Каталог, заявка submitted и одобрение MUST NOT означать выдачу прав. Synthetic fixtures MUST быть валидны до первого LLM-запроса. Неизвестный tool/аргументы MUST NOT получать успешный fallback.

20 исторических намерений сохраняются с явным migration log; дополнительные случаи покрывают новые инструменты. Изменения ожиданий MUST обосновываться текущим контрактом/спецификацией, а не совпадением с новым ответом. Новые task/evidence fixtures проверяют текущий ограниченный runtime-контракт; они не объявляют полную модель этапов реализованной. Реальный Go, HR/Jira/Confluence и корпоративные записи не вызываются.

Каждый отчёт MUST фиксировать dataset_version, SHA выбранного development и текущих tool schemas. Review MUST использовать ту же версию и отвергать несовпадение hash. Старые reports без dataset_version остаются agent-v1. Выбор dataset ограничен известными development-версиями, без произвольного split/path.

## Явное уточнение AG-04

Если пользователь просит действие без обязательных параметров, финальный ответ MUST прямо попросить прислать их значения, а не только перечислить обязательные поля. После recovery или исправления цитаты это уточнение MUST сохраняться. Примеры допустимых типов/категорий MUST исходить из прочитанного источника; иначе агент спрашивает тип без примеров. Параметры, уже названные пользователем, повторно не запрашиваются. Отсутствующие параметры не угадываются, prepare/submit не вызываются.

### Scenario: Отсутствие без параметров
- **WHEN** пользователь пишет «Оформи мне отсутствие», а учебная инструкция требует тип, начало и окончание
- **THEN** агент явно просит тип и обе даты, не предлагает неподтверждённые категории и не заявляет отправку

### Scenario: Уточнение после восстановления контекста
- **WHEN** первая генерация уточняет без инструментов и runtime читает инструкцию
- **THEN** конечная генерация сохраняет запрос конкретных значений и не заменяет его сухим описанием формы

### Scenario: Все параметры действия известны
- **WHEN** пользователь явно поручил подготовить действие и передал параметры, допустимые текущим сервисом
- **THEN** агент готовит разрешённый черновик, не просит лишнего «да» и объясняет ручное подтверждение; переход этапа не одобряется

## Измерение

До live-прогона замораживаются development fixtures/ожидания и код. Один исходный trial нового набора и один trial после исправления на том же наборе сохраняются целиком; это диагностика, не статистическое доказательство улучшения. Семантический разбор отделяется от structural pass; он имеет статус Codex-assisted, human acceptance=false. Реальные LLM-вызовы требуют явного opt-in. Go/UI и их контракты не меняются.

Если исходный/повторный trial выявляет регрессию самого исправления, допустим дополнительный trial после её устранения. Все промежуточные результаты MUST сохраняться; лучший ответ не выбирается, итог привязывается к финальному коду.
