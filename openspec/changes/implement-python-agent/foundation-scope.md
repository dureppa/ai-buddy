# Первый срез: Flask и MCP-клиент

Исторический первый срез; актуальное подключение реального runner описано в [flask-runner-scope](flask-runner-scope.md). Ниже сохранены границы исходного этапа.

Авторизован пользователем 13.11.2026. Область: ai-agent и документация; Go, UI, публичный OpenAPI не меняются.

## Внутренний контракт Python v1 (предложение для Go)

POST /internal/v1/turns с Authorization: Bearer AI_SERVICE_TOKEN и JSON body ≤64 KiB: request_id/conversation_id UUID, message 1–4000 символов, delegation_token 1–8192 без пробелов/управляющих, history до 20 сообщений user/assistant по 4000 символов, optional page_context.url (очищенный http/https URL). Все объекты закрыты. Идентификаторы и токен выдаёт Go. Ответ 200 содержит входные request_id/conversation_id и reply{text,references}; ошибка — безопасный error{code,message}. 400/401/413/415 проверяются до MCP; 503 означает отсутствие конфигурации/runner или контролируемый сбой. Это отдельный внутренний контракт, не изменение публичного ChatReply.

Application factory допускает внедрение runner/session factory для тестов. Производственный runner/LLM не подключён: валидный запрос даёт AI_UNAVAILABLE, readiness false. Тестовая подмена никогда не включается автоматически. Liveness отражает только процесс, readiness не выполняет сеть и платные вызовы.

MCP-клиент использует SDK 1.30.0, Streamable HTTP, отдельные клиенты на ход, делегированный bearer и request-id meta. В этом срезе доступны только search_knowledge и get_team_context с закрытыми аргументами/результатами. Новые progress/evidence и prepare-контракты остаются задачей совместного согласования, не поддерживаются скрыто. Discovery ограничен 4 страницами, результат 32 KiB, ответ транспорта 1 MiB; редиректы запрещены до повторной отправки credentials. Автоматических retries нет. До 6 tool-попыток в ходе, timeout 5 с на MCP и 25 с на ход с закрытием ресурсов. Остальные требования остаются невыполненными до следующих срезов.

Проверки: неавторизованный/повреждённый ввод не вызывает зависимости; output-schema и двойное JSON-представление проверяются; запрещённые инструменты не вызываются; отмена/таймаут закрывают клиентов; параллельные контексты не смешиваются; интеграция использует настоящий MCP-протокол на Python test-server без изменения Go. Состояние assessment, подтверждения и переходы не реализованы этим срезом.
