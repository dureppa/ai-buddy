## Что ещё не закрыто

1. **Связь клиентов с AI.** Go chat всё ещё использует UnavailableAssistant и возвращает 503. Go должен вызвать POST /internal/v1/turns, проверить владельца диалога, выдать делегацию и сохранить сообщения/ответ. Python endpoint готов, этот вызов коллегой пока не подключён.
2. **Настоящий Go MCP.** Нужны два read-tools с согласованными схемами, источниками, ACL и метаданными. При несовместимости Python намеренно не использует каталог. Синтетический Python MCP не заменяет эти работы.
3. **Личный следующий шаг.** Агент пока не читает индивидуальный прогресс и evidence. Он может отвечать по найденным инструкциям, но не определять подтверждённую готовность следующего этапа. Нужен контракт get_onboarding_progress/evidence с Go.
4. **Проверка знаний.** Python endpoint/runner с версиями, рубрикой, pass/fail/unclear и цитатами реализован. [Контракт](../../../docs/integrations/knowledge-assessment.md). Локальная Qwen не прошла development; выбор модели, утверждение рубрик, вызов из Go и сохранение оценки ещё нужны. Контрактные тесты не подтверждают качество оценки знаний.
5. **Решение наставника и переход.** Ожидание review, одобрение/возврат, проверка версий и атомарный переход должны появиться в Go/UI. Python должен только дать проверенную оценку, без записи перехода по решению LLM.
6. **Шесть корпоративных сервисов.** Нужны отсутствия, командировки, найм, увольнения, согласия и бенефиты. В проверенных текущих Go-сидах каталог пока Figma/Confluence/Grafana/Jira/Mattermost/Drive. Его число «шесть» не означает соответствия выбранным HR-сервисам. Моки/экраны в других ветках коллег могут быть впереди этого checkout.
7. **Полный результат действия.** В демонстрации ещё нужно показать действие в одном согласованном HR-моке, сохранённый факт, отображение после перезагрузки, оценку агента, решение наставника и переход. Текущий Q&A smoke не закрывает этот путь.
8. **Помощь в браузере.** URL передаётся как непроверенный контекст, сайт и DOM не читаются. Агент не знает, какая кнопка реально видна на странице; сценарий подсказки по конкретному сервису требует согласованного справочника/контекста.

## Ближайший совместный срез

Сначала подключить Go chat → Python и два Go MCP read-tools. Затем согласовать progress/evidence/assessment и один HR-мок для завершённого шага чек-листа. Маршрут приёмки: запрос стажёра → инструкция/черновик → явное действие пользователя → результат мока сохранён Go → проверка знаний агентом → одобрение наставника → переход Go. Остальные HR-темы можно добавить как справочные инструменты после этого среза.
