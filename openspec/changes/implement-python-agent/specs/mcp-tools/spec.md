# MCP tools

## ADDED Requirements

### Requirement: MCP-01 Доверие и каталог

Python MUST исполнять только согласованные имена из mcp-contracts.md после пересечения tools/list с allowlist; Go MUST проверять привязку субъекта и актуальную ACL каждого вызова.

#### Scenario: MCP-01-S1 Лишний инструмент
- **WHEN** discovery вернул advance_stage или prepare_access_request
- **THEN** инструмент не передаётся модели и не исполняется

#### Scenario: MCP-01-S2 Чужое evidence
- **WHEN** запрошено чужое задание
- **THEN** Go возвращает безопасный NOT_FOUND без чужих полей

### Requirement: MCP-02 Схемы и результаты

Входы и выходы MUST проверяться по закрытым схемам, размерам и договорённым enum. Схемы LLM и MCP MUST связываться явным адаптером.

#### Scenario: MCP-02-S1 Лишнее поле
- **WHEN** модель добавила subject_id
- **THEN** вызов отклоняется до исполнения

#### Scenario: MCP-02-S2 Повреждение
- **WHEN** isError=true или текст противоречит structuredContent
- **THEN** результат не становится успешным фактом

### Requirement: MCP-03 Чтение контекста

Read-tools MUST возвращать только разрешённые текущие сведения с версиями/источниками, не менять задачи или доказательства и не загружать URL произвольно.

#### Scenario: MCP-03-S1 Нет источника
- **WHEN** search вернул пустые документы
- **THEN** возвращается отсутствие данных, а не регламент

#### Scenario: MCP-03-S2 Несовместимый прогресс
- **WHEN** Go поддерживает только pending/completed без review
- **THEN** адаптер не выдумывает переходы; разрыв контракта показан явно

### Requirement: MCP-04 Черновики и подтверждение

Prepare-tools MUST создавать только привязанный черновик после валидации и текущей ACL. Подтверждение, согласия и кадровые решения MUST NOT выполняться моделью.

#### Scenario: MCP-04-S1 Успех подготовки
- **WHEN** валидный запрос разрешён
- **THEN** создан один draft без отправки и смены прогресса

#### Scenario: MCP-04-S2 Отзыв права
- **WHEN** права изменились перед подтверждением
- **THEN** Go отказывает и не выполняет операцию

#### Scenario: MCP-04-S3 Истечение
- **WHEN** TTL черновика закончился
- **THEN** первое подтверждение отклоняется, требуется новая явная подготовка

### Requirement: MCP-05 Повторы и неизвестный итог

Временный сбой MUST повторяться не более одного раза в общем бюджете; запись — только с тем же ключом при гарантированной идемпотентности. Таймаут MUST оставлять результат неизвестным до сверки Go.

#### Scenario: MCP-05-S1 Ответ потерян
- **WHEN** черновик сохранился, ответ не дошёл
- **THEN** повтор не создаёт второй черновик

#### Scenario: MCP-05-S2 Гарантий нет
- **WHEN** запись завершилась таймаутом без идемпотентного контракта
- **THEN** Python не повторяет и не утверждает отсутствие записи

### Requirement: MCP-06 Явный локальный Python demo

Python MCP demo MUST предоставлять только два существующих read-tools, требовать явного включения и bearer, сохранять схемы и изолировать профиль. Данные MUST быть синтетическими и версионированными. Host/Origin, тело, результат и время MUST быть ограничены. Demo MUST NOT автоматически заменять недоступный Go или объявлять HTTP-интеграцию выполненной.

#### Scenario: MCP-06-S1 Не включён demo
- **WHEN** не заданы явное включение и валидный локальный секрет
- **THEN** сервер не запускается, а не принимает запросы без авторизации

#### Scenario: MCP-06-S2 Параллельные профили
- **WHEN** два авторизованных клиента одновременно читают контекст
- **THEN** каждый получает сведения своего demo-профиля, аргументы модели не меняют субъекта

#### Scenario: MCP-06-S3 Отказ backend
- **WHEN** backend задержался, вернул неверную схему или слишком большой результат
- **THEN** возвращается безопасная ошибка без скрытого успеха, приватных деталей или записи данных
