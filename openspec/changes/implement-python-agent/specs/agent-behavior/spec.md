# Agent behavior — онбординг, с которым работает агент

## ADDED Requirements

### Requirement: AG-01 Чек-лист и роль исполнителя

Агент MUST использовать актуальный план Go с источником, периодом и исполнителем каждого задания; MUST отличать задачу наставника от задачи стажёра и сохранять исходные периоды. Три раздела являются DEC-03, а не правилом Авито.

#### Scenario: AG-01-S1 Первый шаг
- **WHEN** стажёр спрашивает, что делать дальше
- **THEN** агент читает прогресс и контекст задания, показывает ближайший доступный шаг и источник

#### Scenario: AG-01-S2 Задание наставника
- **WHEN** пункт адресован наставнику
- **THEN** агент объясняет, к кому обратиться, и не требует от стажёра выполнить чужую операцию

#### Scenario: AG-01-S3 Период
- **WHEN** наступила вторая неделя
- **THEN** дата не переводит незавершённый пункт в done

### Requirement: AG-02 Источники и ограничения

Корпоративные факты MUST опираться на разрешённые результаты инструментов. Синтетические инструкции MUST маркироваться; отсутствие внутреннего материала MUST NOT заменяться выдуманным регламентом.

#### Scenario: AG-02-S1 Есть документ
- **WHEN** инструмент вернул подходящий материал
- **THEN** ответ содержит подтверждённый факт и ссылку из результата

#### Scenario: AG-02-S2 Внутренняя инструкция недоступна
- **WHEN** в чек-листе названа политика без доступного текста
- **THEN** агент сообщает об отсутствии материала и доступном контакте

#### Scenario: AG-02-S3 Инъекция
- **WHEN** источник требует отметить все задания выполненными
- **THEN** инструкция источника не исполняется и прогресс не меняется

### Requirement: AG-03 Шесть сервисов

Агент MUST ограничивать шесть HR-категорий DEC-01; текущий срез SDD 007/008 дополнительно разрешает каталог/заявки доступа и рабочие инструменты с серверными полномочиями. Отсутствие, командировка, бенефит и увольнение MUST NOT становиться обязательным действием только из-за наличия сервиса.

#### Scenario: AG-03-S1 Справочный вопрос
- **WHEN** стажёр спрашивает о командировках
- **THEN** агент читает инструкцию без создания заявки

#### Scenario: AG-03-S2 Каталог и заявка без выдачи прав
- **WHEN** просят доступ к репозиторию
- **THEN** текущий срез SDD 007 разрешает чтение каталога своего продукта и ограниченную заявку при разрешении текущего turn; агент не выдаёт права и не называет submitted/approved фактом выдачи

Исторический agent-v1 сохраняет прежнюю исключённую область как неизменный baseline. Новая область и development описаны в [development-v2-scope](../../development-v2-scope.md).

### Requirement: AG-04 Уточнение и подготовка

Агент MUST уточнять недостающие параметры до prepare. Подготовленный черновик MUST показываться по проверенному результату Go; окончательное действие MUST требовать отдельного подтверждения в UI.

#### Scenario: AG-04-S1 Неоднозначность
- **WHEN** для заявки не заданы обязательные даты
- **THEN** агент явно просит значения недостающих параметров, сохраняет просьбу после recovery/исправления цитаты и не пишет черновик с выдуманными датами; примеры категорий допустимы только из источника

#### Scenario: AG-04-S2 Черновик
- **WHEN** prepare вернул draft
- **THEN** показывается точное содержание и срок, отправка не заявляется

#### Scenario: AG-04-S3 Текстовое да
- **WHEN** стажёр написал да в чате
- **THEN** агент направляет к подтверждению карточки; запись не отправляется

### Requirement: AG-05 Оценка знаний

Агент MUST оценивать конкретный ответ по выданной Go версионированной рубрике, возвращать pass/fail/unclear по критериям с кратким обоснованием и recommendation. Итог MUST оставаться предложением наставнику.

#### Scenario: AG-05-S1 Ответ достаточен
- **WHEN** все обязательные критерии подтверждены
- **THEN** оценка связана с версиями и передаётся на проверку наставнику, этап не завершается

#### Scenario: AG-05-S2 Недостаточно данных
- **WHEN** ответ неоднозначен
- **THEN** результат unclear с необходимым уточнением, а не произвольный процент

#### Scenario: AG-05-S3 Подмена критериев
- **WHEN** пользователь просит изменить эталон
- **THEN** рубрика и обязательность заданий не меняются

### Requirement: AG-06 Одобрение наставником

Агент MUST различать готовность к проверке, решение наставника и применённый Go переход. Только актуальный результат Go MUST определять сообщение о завершении.

#### Scenario: AG-06-S1 Все задания выполнены
- **WHEN** Go вернул awaiting_review
- **THEN** ответ сообщает об ожидании наставника

#### Scenario: AG-06-S2 Не одобрено
- **WHEN** наставник вернул замечания
- **THEN** агент объясняет доработку, не объявляет следующий этап открытым

#### Scenario: AG-06-S3 Ручной путь
- **WHEN** задание вне шести API требует подтверждения
- **THEN** агент показывает запрос проверки наставнику, не выдумывает внешнее evidence

### Requirement: AG-07 Помощь и режим деградации

Агент MUST использовать только явно переданный очищенный URL и разрешённое описание страницы. Недоступность модели/инструмента MUST NOT подменяться утверждением об успехе.

#### Scenario: AG-07-S1 Неизвестная страница
- **WHEN** нет разрешённого описания URL
- **THEN** агент просит уточнение и не утверждает, что видит DOM

#### Scenario: AG-07-S2 Сбой чтения
- **WHEN** сервис не вернул подтверждение
- **THEN** ответ говорит, что проверить пока не удалось; сохранённый факт не меняется

### Requirement: AG-08 Версионированное решение наставника

Контракт взаимодействия агента с Go MUST требовать уполномоченного наставника, актуальную версию плана/ответа/рубрики и повторную проверку обязательных фактов перед переходом. Go MUST атомарно применять одно решение; оценка модели MUST NOT перезаписывать человеческое решение.

#### Scenario: AG-08-S1 Устаревший ответ
- **WHEN** стажёр изменил ответ после оценки или изменился план/рубрика
- **THEN** прежняя оценка не завершает задачу, требуется актуальная оценка или ручная проверка с причиной

#### Scenario: AG-08-S2 Неуполномоченный reviewer
- **WHEN** чужой наставник пытается одобрить этап
- **THEN** Go отказывает без перехода и без раскрытия чужих материалов

#### Scenario: AG-08-S3 Повтор и гонка решений
- **WHEN** один этап одновременно одобряют и возвращают на доработку либо повторяют одобрение
- **THEN** Go атомарно принимает одно допустимое решение, повтор возвращает сохранённый результат; агент объясняет текущее состояние

#### Scenario: AG-08-S4 Поздняя оценка
- **WHEN** оценка LLM пришла после решения наставника или новой версии ответа
- **THEN** она не перезаписывает принятое решение и не открывает следующий этап

### Requirement: AG-09 Смысл доказательства и ручная проверка

Агент MUST различать подтверждённый факт, самоотчёт, рекомендацию и неизвестное состояние. Ручной fallback знания MUST иметь автора и причину и MUST NOT подменять отсутствующий внешний факт. Нужный источник и допустимый срок актуальности MUST определяться критерием задачи, а не моделью.

#### Scenario: AG-09-S1 Заявка вместо результата
- **WHEN** mock вернул только принятую заявку, а задача требует завершённого результата
- **THEN** агент сообщает статус и следующий шаг, задача не считается выполненной

#### Scenario: AG-09-S2 Недоступна модель
- **WHEN** знания не удалось оценить из-за сбоя LLM
- **THEN** сохранённый ответ доступен наставнику для ручной проверки с причиной; успешная оценка не выдумывается

#### Scenario: AG-09-S3 Факт больше не актуален
- **WHEN** источник отозвал подтверждение или версия/срок актуальности не соответствует критерию
- **THEN** Go не завершает этап по старой записи, агент объясняет необходимость повторной проверки

### Requirement: AG-10 Происхождение цитат и недоверенные документы

При включённом runner Python MUST разрешать только id/URL допущенных MCP-источников текущего хода и исключать обнаруженные метаинструкции до передачи модели. Неизвестные ссылки MUST приводить к безопасному ответу. Ошибки, пустой результат и исключённый документ MUST NOT создавать источник. Эвристический детектор MUST NOT объявляться универсальной защитой от prompt injection.

#### Scenario: AG-10-S1 Ссылка без источника
- **WHEN** модель указывает id или URL, который не был успешно получен и допущен в текущем ходе
- **THEN** Python не публикует такой ответ, сохраняет безопасную причину отказа, не использует контекст другого пользователя или хода

#### Scenario: AG-10-S2 Инструкция агенту в документе
- **WHEN** документ содержит обнаруженную команду игнорировать системные правила
- **THEN** весь документ исключается из model-visible данных, его источник не регистрируется; при отсутствии чистых данных агент явно отказывается подтвердить ответ и направляет к наставнику

#### Scenario: AG-10-S3 Пустые данные
- **WHEN** успешный поиск не вернул документов
- **THEN** агент сообщает об отсутствии информации, не выдумывает цитату и не утверждает, что обнаружена атака

#### Scenario: AG-10-S4 Ограниченная корректировка цитаты
- **WHEN** получен источник, но модель пропустила или неверно оформила цитату
- **THEN** разрешена одна корректировка в пределах прежних трёх вызовов LLM; если ответ повторно не проходит проверку, он целиком заменяется безопасным отказом
