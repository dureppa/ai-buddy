# Python AI service

## Purpose

Задать внутренний контракт Go → Python и наблюдаемые гарантии AI-сервиса: проверку входов, ограниченное выполнение агентного хода, безопасные ошибки, изоляцию запросов и явную миграцию публичного API. Точные предлагаемые поля и настройки приведены в [design.md](../../design.md).

## ADDED Requirements

### Requirement: SVC-01 Только доверенный вызов

Внутренняя обработка хода MUST требовать аутентифицированный вызов Go и ограниченный делегированный контекст MCP. Недоверенный вызов MUST быть отклонён до LLM/MCP. Идентификаторы пользователя и диалога MUST происходить из Go, который проверяет владение диалогом до вызова Python.

#### Scenario: SVC-01-S1 Нет сервисной авторизации
- **WHEN** запрос приходит без корректной авторизации Go → Python
- **THEN** сервис возвращает 401, а число вызовов LLM и MCP равно нулю

#### Scenario: SVC-01-S2 Нет делегированного контекста
- **WHEN** сервисная авторизация корректна, но контекст MCP отсутствует
- **THEN** сервис возвращает типизированную ошибку контекста без вызова LLM и инструментов

### Requirement: SVC-02 Ограниченный и проверенный вход

Сервис MUST проверять JSON, Content-Type, закрытую схему, длину сообщения, историю и размер тела до обработки. Неизвестные поля и роли истории MUST отклоняться. URL страницы MUST быть очищен от query и fragment. Лишний объём MUST NOT скрыто обрезать последнюю просьбу пользователя.

#### Scenario: SVC-02-S1 Некорректный запрос
- **WHEN** текст пуст, присутствует лишнее поле или роль history=system
- **THEN** возвращается 400 с безопасной ошибкой и без платного вызова модели

#### Scenario: SVC-02-S2 Превышение лимита
- **WHEN** тело превышает 64 KiB или текст превышает 4000 символов
- **THEN** возвращается 413 для тела или 400 для поля, без передачи превышения модели

### Requirement: SVC-03 Привязанный результат

Успех MUST возвращать request_id исходного хода и проверенный результат согласованного режима chat/assessment с тем же conversation_id. Эти идентификаторы MUST задаваться кодом из доверенного входа, а не LLM. В ответ MUST NOT попадать токены, внутренние инструкции и непроверенный tool output.

#### Scenario: SVC-03-S1 Подмена диалога моделью
- **WHEN** модель пытается вернуть другой conversation_id
- **THEN** её служебное поле отклоняется закрытой схемой model-output, а при формировании допустимого ответа итоговый идентификатор берётся из входа

#### Scenario: SVC-03-S2 Успешный ход
- **WHEN** агент сформировал допустимый результат
- **THEN** внутренний ответ 200 содержит request_id, conversation_id и проверенный результат своего режима: reply для chat либо assessment с evaluation_id и версиями для оценки

### Requirement: SVC-04 Общий срок выполнения

Сервис MUST применять единый монотонный deadline хода. Проверка входа, соединение, discovery, LLM, инструменты, повторы и завершение соединений MUST учитывать оставшееся время. По истечении бюджета MUST NOT запускаться новые действия. Значения по умолчанию MUST быть документированы и конфигурируемы.

#### Scenario: SVC-04-S1 Медленная модель
- **WHEN** ответ LLM не получен в оставшемся времени
- **THEN** сервис прекращает ожидание и возвращает AI_TIMEOUT без запуска последующих инструментов

#### Scenario: SVC-04-S2 Бюджет истёк перед записью
- **WHEN** после чтения источников времени на новый вызов не осталось
- **THEN** подготовка черновика не запускается

### Requirement: SVC-05 Лимит работы и коррекций

Сервис MUST ограничивать число фактических LLM-вызовов и вызовов инструментов, включая повторы. Коррекция аргументов или формата MUST происходить максимум один раз на ход и расходовать тот же бюджет. Повторяющееся решение без нового результата MUST NOT приводить к бесконечному циклу.

#### Scenario: SVC-05-S1 Зацикленная модель
- **WHEN** LLM повторяет один запрос без новых данных и достижения результата
- **THEN** выполнение завершается AGENT_LIMIT_REACHED до превышения лимита

#### Scenario: SVC-05-S2 Пакет превышает лимит
- **WHEN** модель предлагает больше вызовов, чем остаётся разрешённых
- **THEN** пакет не исполняется частично как успешный план и возвращается контролируемая ошибка лимита

### Requirement: SVC-06 Контролируемые сбои и повторы LLM

Сервис MUST преобразовывать таймаут, недоступность, rate limit, отказ провайдера и некорректный ответ в отдельные внутренние коды. Повтор LLM допустим максимум один раз при временном сбое и наличии бюджета. Ошибки авторизации провайдера и некорректные запросы MUST NOT бесконечно повторяться.

#### Scenario: SVC-06-S1 Rate limit
- **WHEN** провайдер отвечает 429 с ожиданием дольше оставшегося бюджета
- **THEN** сервис не ждёт сверх deadline и возвращает AI_RATE_LIMITED

#### Scenario: SVC-06-S2 Неверный ключ провайдера
- **WHEN** провайдер отвечает ошибкой авторизации
- **THEN** сервис возвращает безопасный AI_UNAVAILABLE без повторов, ключа и исходного тела ошибки

### Requirement: SVC-07 Жизненный цикл MCP

Асинхронные сессии MUST создаваться и завершаться в совместимом жизненном цикле выполнения. Объект MCP-сессии MUST NOT повторно использоваться в уже закрытом event loop. Завершение хода MUST закрывать его соединения и задачи; незавершённая внешняя операция MUST NOT считаться отменённой на стороне Go без подтверждения.

#### Scenario: SVC-07-S1 Два последовательных запроса
- **WHEN** Flask обрабатывает два хода с разными жизненными циклами
- **THEN** оба проходят без использования закрытой сессии и без утечки соединений

#### Scenario: SVC-07-S2 Исключение и закрытие
- **WHEN** выполнение инструмента прерывается таймаутом или исключением
- **THEN** соединения закрываются в ограниченном времени, секреты не логируются, результат записи остаётся неизвестным до проверенного ответа

### Requirement: SVC-08 Изоляция конкурентных диалогов

История, доказательства, токен MCP, ключ операции и счётчики MUST принадлежать одному ходу. Общая изменяемая глобальная память диалогов MUST NOT использоваться. Go MUST хранить историю, определять её владельца и сериализовать или контролировать конкурирующие ходы одного диалога.

#### Scenario: SVC-08-S1 Параллельные профили
- **WHEN** два профиля одновременно задают вопросы и ответы приходят в обратном порядке
- **THEN** каждый получает свои доказательства и результат без смешения токенов

#### Scenario: SVC-08-S2 Повтор одного хода
- **WHEN** Go получает повтор уже выполняемого request_id
- **THEN** Go объединяет запросы или возвращает сохранённый результат; повтор подготовки на MCP остаётся идемпотентным

### Requirement: SVC-09 Наблюдаемость без секретов

Сервис MUST записывать request_id, версию промпта, провайдера/модель, длительности, имена инструментов, исход и счётчики. Токены, полные промпты, произвольный текст документов и заголовки авторизации MUST NOT логироваться по умолчанию. Публичный ответ MUST NOT содержать chain-of-thought.

#### Scenario: SVC-09-S1 Ошибка с секретом в теле
- **WHEN** провайдер или инструмент прислал ошибку, содержащую токен
- **THEN** в лог и ответ попадают только безопасный код и разрешённые диагностические поля

#### Scenario: SVC-09-S2 Успех
- **WHEN** ход завершён
- **THEN** по request_id восстанавливается последовательность технических этапов и их длительности без содержимого секретов

### Requirement: SVC-10 Конфигурация и готовность

Сервис MUST валидировать обязательные настройки до приёма хода. Liveness MUST отражать работу процесса, readiness — корректность локальной конфигурации и возможность создать адаптеры, без платной генерации LLM. Readiness MUST NOT обещать доступность внешних зависимостей; MCP/LLM MUST дополнительно проверяться smoke-прогоном и при выполнении хода.

#### Scenario: SVC-10-S1 Нет модели или ключа
- **WHEN** обязательная настройка не задана
- **THEN** сервис не объявляет себя готовым и указывает безопасное имя отсутствующей настройки в служебной диагностике

#### Scenario: SVC-10-S2 LLM упала после проверки
- **WHEN** readiness ранее прошла, а провайдер стал недоступен
- **THEN** следующий ход получает контролируемую ошибку, а не зависание или ложный ответ

### Requirement: SVC-11 Явное согласование новых контрактов

Python и Go MUST различать текущий публичный OpenAPI и предложенный новый контракт онбординга. Корпоративный draft и assessment MUST NOT сериализоваться как прежний AccessRequestDraft или обходить валидацию. До реализации новые схемы MUST пройти согласование Go/UI/Python.

#### Scenario: SVC-11-S1 Старый клиент
- **WHEN** публичный контракт не поддерживает новый вид подтверждения
- **THEN** несовместимая операция не объявляется успешной; требуется обновление контракта и клиента

#### Scenario: SVC-11-S2 Сбой оценки
- **WHEN** Python не смог получить валидную оценку
- **THEN** Go сохраняет ответ и статус ожидания, клиент получает безопасную ошибку без смены этапа

### Requirement: SVC-12 Реакция интерфейса и состояние ожидания

Клиент MUST сразу показывать ожидание и оставаться доступным для взаимодействия во время AI-вызова. Длительность LLM MUST NOT подменять ориентир менее одной секунды для простых локальных действий из кейса. Python MUST завершать ход в бюджете; отдельный публичный streaming-протокол этим изменением не вводится.

#### Scenario: SVC-12-S1 Медленный ответ
- **WHEN** пользователь отправляет вопрос, на который модель отвечает несколько секунд
- **THEN** клиент показывает ожидание до ответа, а локальные действия не ждут завершения генерации

#### Scenario: SVC-12-S2 Корректная ошибка
- **WHEN** Go получает типизированный сбой Python
- **THEN** клиент завершает ожидание и показывает понятное сообщение и возможность нового запроса без утверждения об успехе

### Requirement: SVC-13 Прямой локальный runner

При явном включении и заданной модели Flask MUST создавать прямой Ollama runner без runtime-зависимости от экспериментов и LangChain. Модель/адрес MUST происходить из настроек, а не пользовательского сообщения. Один ход MUST иметь собственные MCP/LLM-клиенты и реестр источников. Технический отказ MUST давать безопасный типизированный HTTP-результат; отсутствие знаний и блокировка документа MUST отличаться от успеха действия.

#### Scenario: SVC-13-S1 Включённая конфигурация
- **WHEN** задано AI_AGENT_ENABLED=true и OLLAMA_MODEL при валидных service token и MCP URL
- **THEN** readiness проверяет локальную готовность без генерации, а валидный turn использует настоящий direct runner

#### Scenario: SVC-13-S2 Модель недоступна
- **WHEN** Ollama недоступна либо превышен модельный/общий deadline
- **THEN** возвращается AI_UNAVAILABLE либо AI_TIMEOUT без повторов и provider body, а ресурсы хода закрываются

#### Scenario: SVC-13-S3 Проверенные ссылки
- **WHEN** получен ответ по MCP-источнику
- **THEN** HTTP Reply содержит безопасный текст и только реально процитированные допущенные references; trace, сырые ответы и токены не публикуются
