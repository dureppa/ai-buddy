# Маршрут демонстрации для жюри

Это план проверки после реализации. Команды запуска, URL и способ входа появятся в [README](../README.md), когда будет готов первый работающий сценарий.

| Шаг | Что сделать | Что проверить |
| --- | --- | --- |
| 1. Первый день | Открыть веб-приложение под тестовым профилем и отметить один пункт чек-листа. | Buddy показывает ближайший шаг. После обновления страницы отметка сохранилась. |
| 2. Команда | Спросить «Кто мой лид и где почитать о продукте?» | Ответ относится к текущей команде, содержит доступный контакт и источник. |
| 3. Доступ | Попросить доступ к одному настроенному сервису, проверить черновик и нажать подтверждение. | Появились номер и статус заявки. После обновления запись видна в списке. |
| 4. Права | Повторить запрос под тестовым профилем без разрешения на этот сервис. | Buddy показывает отказ, список заявок этого профиля остаётся прежним. |

Когда будут готовы дополнительные части маршрута, шаг с доступом можно начать с вопроса питомцу на тестовой странице. В конце показать карточку экватора в веб-чате и переход к опросу. Справочные HR-вопросы добавляются в маршрут после проверки выбранной темы.

Для маршрута потребуются два синтетических профиля, чек-лист, сведения о команде и имитация сервиса доступов. Каталог [demo/fixtures](../demo/fixtures/) зарезервирован под эти материалы. Схему и содержимое данных команда добавит после появления модели хранения и загрузки данных.

Ожидаемые результаты подробнее описаны в [спецификации заявки](specs/001-access-request.md) и [спецификации онбординга](specs/002-onboarding-and-context.md).
