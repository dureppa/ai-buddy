# Архитектура AI Buddy

Стажёр работает в вебе. Go проверяет сессию и права, хранит диалог и черновики действий. Flask вызывает DeepSeek и Python MCP. MCP читает Go, а Go ходит в учебные API сервисов. Модель не записывает данные. Ссылка из ответа открывает `/actions/:id`, и только подтверждение человека отправляет одну попытку в сервис. Сейчас у агента до 13 инструментов, включая чтение рабочих инструментов направления.

Подробности действий: [service-actions](components/service-actions.md). Ответы на критерии кейса: [criteria](criteria.md).

| Компонент | Ответственность |
| --- | --- |
| [Веб](components/web.md) | Чат, чек-лист, кабинет наставника, страница подтверждения |
| [Расширение](components/extension.md) | Вопрос с контекстом страницы и переход в веб |
| [Go API](components/backend-go.md) | Сессия, права, диалог, черновики, вызов Flask и сервисов |
| [Python](components/ai-python.md) | Контекст запроса, DeepSeek, выбор инструментов, безопасные ошибки |
| [MCP](components/python-mcp.md) | Чтения и подготовка черновика по делегированному токену |
| Корпоративные сервисы и инструменты | Собственные процессы и базы. Buddy открывает их в браузере и читает через HTTP |

В Compose модель задаётся так: `AI_LLM_PROVIDER=deepseek`, модель `deepseek-flash`. MCP работает в режиме `go_http` и ходит в `http://go:8080`.

Чтения и подготовка черновика покрывают найм, увольнения, бенефиты, Jira и доступы. Отдельно агент читает команду, базу знаний, прогресс, каталог доступов, страницы Confluence и рабочие инструменты направления. Запись после подтверждения делает Go, не модель. Схемы — в `contracts/agent-tools.json`, поведение инструментов направления — в [SDD 009](specs/009-agent-role-tools.md).

Отметки встроенного ролевого чек-листа хранятся в Go и PostgreSQL. Пользовательские пункты и публикации наставника сохраняются в браузере. Диалог, черновик действия, результат подтверждения, ответы на опросы и прочтение уведомлений сохраняются в Go и PostgreSQL. В режиме веба без Go опросы и прочтение сохраняются в браузере.

Личный календарь также хранится в Go/PostgreSQL: веб и MCP читают одни события;
создание через агента требует подтверждения на `/actions/:id`. Старые локальные
записи импортируются с резервной копией. [Границы календаря](components/calendar.md).

Данные демонстрационные. Проверка прав — на каждом чтении и перед отправкой действия. Нет права или сервис не запущен — объяснение без записи. Заявка на доступ не выдаёт настоящие права: статус заявки не означает выданный доступ.

«[Разобрать пункт](specs/ask-agent-checklist.md)» открывает общую панель Buddy
с ограниченным контекстом локального пункта. Панель и полный чат используют
одну историю; контекст передаётся и в уточнениях. Прикреплённые страницы и
связанные материалы читаются прежними MCP-инструментами с ACL. Подписанный
режим read_only запрещает запись; локальный пункт не подменяет серверный прогресс.
Контракт selection сохраняется, универсальная панель выделения удалена.

Веб передаёт текущий пункт «В процессе» через проверяемый snapshot checklist.
Для общего вопроса о следующем шаге он имеет приоритет над серверным demo-планом.
При отметке из чата Go заново вычисляет текущий пункт ролевого плана по общему каталогу, сохранённым отметкам и анкетам.
[Контекст и правила общения](specs/current-checklist-and-dialogue.md).
