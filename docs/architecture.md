# Архитектура AI Buddy

Компоненты пока находятся на стадии каркаса. Ниже описано планируемое разделение ответственности.

| Компонент | Ответственность |
| --- | --- |
| [Веб-приложение](components/web.md) | Чат, чек-лист и прогресс адаптации, заявки и напоминания. |
| [Расширение](components/extension.md) | Быстрый вопрос с контекстом текущей страницы и переход в веб-приложение. |
| [Go-бэкенд](components/backend-go.md) | API для клиентов, проверка прав, бизнес-операции, хранение данных и имитация корпоративных сервисов. |
| [Python-сервис](components/ai-python.md) | Контекст запроса, вызов LLM, выбор инструментов и обработка сбоев AI. |

Веб-приложение и расширение рассчитаны на Go API. Текущий фронтенд-прототип работает через локальный demo-adapter. Для вопросов из расширения content script получает URL, заголовок и выделенный текст страницы и передаёт их service worker. После подключения сервисов Go сможет передавать сообщение и контекст в Python-сервис, а клиент покажет стажёру результат и статус.

Кабинет наставника и руководителя читает прогресс из того же локального адаптера. Аудитория опубликованных материалов определяется демоаккаунтом сотрудника и выбранными стажёрами. [Спецификация кабинета](specs/staff-workspace.md)

При реализации сценария документируйте фактические контракты между компонентами, статусы и поведение при ошибках. Для демонстрации используются синтетические или обезличенные данные.

Публичные HTTP-операции спроектированы в [черновике OpenAPI](../contracts/openapi.yaml). Подготовка черновика заявки идёт через MCP, явное подтверждение пользователя — через Go API. [Спецификация заявки на доступ](specs/001-access-request.md)
