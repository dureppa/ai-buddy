# Архитектура AI Buddy

> Целевой сценарий обновлён 13.11.2026: [онбординг агента](../openspec/README.md). Корпоративная область — только шесть сервисов; старое описание доступа ниже сохраняется как baseline. Новое поведение не объявляется реализованным.

Новый срез: Go-чат вызывает Flask, выбранная Ollama/DeepSeek вызывает Python MCP, MCP читает Go и подтверждения из HR-согласий. Оценка знаний и отдельный review наставника завершают учебное задание. [SDD 004](specs/004-agent-service-integration.md). Остальные HR-интеграции и глобальные этапы остаются целевыми.

Исходное состояние компонентов описано по ссылкам ниже. Python Flask выполняет прямой локальный LLM/MCP-цикл. Отдельный Python MCP поддерживает demo и Go HTTP-адаптер с проверкой делегации; адаптер проверен на моках. Живой маршрут прогресса и согласий подтверждён [HTTP-прогоном](integrations/agent-live-report.md); общий UI/e2e и остальные сервисы ещё не приняты. Ниже описано целевое разделение ответственности.

Подробный проект Python-агента, MCP-контрактов и тестирования оформлен в [OpenSpec](../openspec/README.md). Изменение `implement-python-agent` содержит предложенное поведение и план; реализован ограниченный read-only runtime-срез, полное изменение ещё не завершено и не архивировано. Публичный OpenAPI остаётся действующим целевым контрактом.

| Компонент | Ответственность |
| --- | --- |
| [Веб-приложение](components/web.md) | Чат, чек-лист и прогресс адаптации, заявки и напоминания. |
| [Расширение](components/extension.md) | Быстрый вопрос с контекстом текущей страницы и переход в веб-приложение. |
| [Go-бэкенд](components/backend-go.md) | API для клиентов, проверка прав, бизнес-операции, хранение данных и имитация корпоративных сервисов. |
| [Python-сервис](components/ai-python.md) | Контекст запроса, вызов LLM, выбор инструментов и обработка сбоев AI. |

Веб-приложение и расширение рассчитаны на Go API. Текущий фронтенд-прототип работает через локальный demo-adapter. Активный профиль закреплён [демосессией](specs/demo-session.md) на стороне браузера. Для вопросов из расширения content script получает URL, заголовок и выделенный текст страницы и передаёт их service worker. После подключения сервисов Go сможет передавать сообщение и контекст в Python-сервис, а клиент покажет стажёру результат и статус.

Кабинет наставника и руководителя читает прогресс из того же локального адаптера. Аудитория опубликованных материалов определяется демоаккаунтом сотрудника и выбранными стажёрами. [Спецификация кабинета](specs/staff-workspace.md)

При реализации сценария документируйте фактические контракты между компонентами, статусы и поведение при ошибках. Для демонстрации используются синтетические или обезличенные данные.

[Корпоративные демосайты](components/corporate-services.md) открываются по отдельным URL. Целевая интеграция проходит через API соответствующего сервиса. Каждый сервис владеет своими данными и проверяет права на операции. Внешние фронтенды пока используют синтетические данные.

Публичные HTTP-операции спроектированы в [черновике OpenAPI](../contracts/openapi.yaml). Подготовка черновика заявки идёт через MCP, явное подтверждение пользователя — через Go API. [Спецификация заявки на доступ](specs/001-access-request.md)

[Jira](components/jira.md) — отдельный Go/PostgreSQL-сервис с собственным React UI. Пользователи связаны с Buddy по profile_id; права на пространства и доски проверяет Jira. Агент и главная пока не подключены.
