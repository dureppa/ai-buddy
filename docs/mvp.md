# План MVP

AI Buddy помогает стажёру понять, что делать дальше, найти информацию о своей команде и выполнить первое рабочее действие. Веб-приложение показывает чат, чек-лист, заявки и напоминания. Браузерный питомец помогает на одной поддерживаемой странице и даёт переход в веб-приложение.

Текущий запуск для жюри — Docker Compose с DeepSeek, как в [README](../README.md). Вопросы о команде, чек-лист и подтверждённое действие в сервисе уже проходят через Go и агента. Отметка чек-листа и публикации наставника по-прежнему хранятся в браузере. Локальный `npm run dev` без API оставлен, чтобы открыть интерфейс без модели.

| Сценарий | Что должен увидеть стажёр | Очередь |
| --- | --- | --- |
| 1. Первый день | Приветствие, ближайший шаг и чек-лист стажировки по роли: общий блок и профессиональные пункты от первой недели до выпуска. Прогресс сохраняется. | Основной маршрут |
| 2. Команда и инструменты | Ответы о составе команды, ролях, контактах и инструментах с учётом профиля стажёра и его прав. | Основной маршрут |
| 3. Вход в профессию | Обзор продукта, первых задач и рабочих сервисов для своей роли. Для одного сервиса стажёр может [запросить доступ](specs/001-access-request.md) и увидеть сохранённую заявку. | Основной маршрут |
| 4. HR-вопросы | Шесть [внешних демосайтов](components/corporate-services.md) с интерактивными сценариями на синтетических данных. Первый кандидат для проверки справочных ответов в чате — вопрос про отгул. | После основного маршрута |
| 5. Помощь на странице | Питомец объясняет, где на одной поддерживаемой странице находится нужный раздел или кнопка, и предлагает перейти в AI Buddy. | После сквозной заявки |
| Напоминание | Системная карточка в веб-чате про экватор стажировки с переходом к опросу. | После сквозной заявки |

[Кабинет наставника и руководителя](specs/staff-workspace.md) добавляет сценарии проверки прогресса и публикации материалов в том же браузере.

На первой итерации команда доводит первые три сценария до сквозной проверки. Следом подключает питомца и одну карточку уведомления к тому же маршруту. Набор HR-тем для сдачи определяет по готовности справочных материалов и проверок. Для публичного описания сдачи перечисляйте реализованные и проверенные возможности.

Поведение помощника и ошибки описаны в [SDD-спецификации онбординга](specs/002-onboarding-and-context.md). Путь проверки собран в [маршруте демонстрации](demo.md). В основе плана — [кейс и чек-лист Авито](avito-sources.md).

## Ограничения MVP

Для [13 рабочих сервисов направлений](specs/009-agent-role-tools.md) агент
показывает каталог текущего стажёра, читает доступные записи и отвечает со
ссылками на источники. В рамках MVP через чат не выполняются:

- запуск SQL-запросов в Trino и запросов/коллекций Postman;
- отправка сообщений в Mattermost;
- изменение результатов тестовых прогонов и статусов дизайн-ревью.

Это принятая граница MVP. Текущие API этих сервисов предоставляют чтение
рабочих данных; локальные действия в их учебном UI не подтверждают серверное
сохранение. Агент сообщает об ограничении и может дать ссылку на сервис,
не заявляя о выполнении операции.

Ограничение относится к этим рабочим сервисам. Подключённые действия Jira,
HR-сервисов и заявки на доступ используют существующие контракты подтверждения.
Будущее расширение потребует API записи, проверки прав, подтверждения действий
и сохранения результатов в сервисах.
