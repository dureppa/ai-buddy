# Проверка текущего пункта и общения

16 ноября 2026. Ветка fix/current-task-and-friendly-dialogue, база main 6702761.

## Автоматические проверки

`just frontend-check`: формат/lint/типы, 242 теста Buddy, 10 расширения,
58 сайтов сервисов и сборки. Веб-покрытие: 91,21% строк.
`just python-check`: Ruff/mypy, 714 тестов, 91,55% строк. Go: gofmt, vet,
test и atomic coverage на отдельной PostgreSQL 17 на сервере, 90,8% операторов.
Тестовая БД/контейнер удалены, рабочие данные не использовались.
Полный `just check` локально остановился на отсутствии Go; race (нет gcc на
сервере) и независимые внешние Go-модули проверяются обязательным CI.

Контракты проверяют status/task, неизвестные поля, ACL/делегацию и совместимость
клиентов без нового контекста. Snapshot не делает обычные поручения read_only,
но явный разбор сохраняет прежний read_only. Python не допускает запись или
чтение старого серверного прогресса вместо локального текущего пункта.

## Браузер

Chromium, 1440×1000 и 390×844, HTTP-моки. Для четырёх профилей label в запросе
совпал со строкой «В процессе». После отметки отправился следующий пункт.
Карточка источника открыла именно его; завершённый план передал completed.
Горизонтального скролла и ошибок JavaScript нет. Отправка анкеты и недоступный
план отдельно покрыты компонентными тестами.

## Настоящий DeepSeek

Использованы ровно 6 разрешённых платных HTTP-запросов, production transport,
DirectRunner и синтетическая MCP session без бизнес-действий. Первые четыре
проверили текущий пункт аналитики, следующий после отметки, поддержку перед
первым днём и «Как дела?». Во всех случаях guards приняли ответ. Оба рабочих
ответа назвали нужный UI-пункт и вернули его конкретную ссылку; поддержка и
разговорный ответ не читали MCP и не вернули источники.

Первый ответ о следующем пункте лишний раз отправлял к наставнику из-за краткого
описания. Промпт уточнён: короткое описание не означает отсутствия инструкции,
допускается явно общий безопасный совет без выдуманных корпоративных правил.
Последние два запроса (генерация и исправление цитаты) повторно проверили первый
пункт на итоговом промпте. Следующий пункт после этой последней формулировки
живой LLM не повторялся; поддержка изменением не затрагивалась. Семантическая
точность всех формулировок, holdout и продуктовый эффект этим прогоном не измерены.
Полная серверная синхронизация ролевого чек-листа остаётся отдельной задачей.
