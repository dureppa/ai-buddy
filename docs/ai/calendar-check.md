# Проверка календаря, 16 ноября 2026

Ветка `feature/agent-calendar-events`, база `2d26fef`. Автотесты и покрытие:
[coverage](../coverage.md). Пользовательская проверка: [demo](../demo.md#календарь-в-чате).

С разрешения пользователя выполнены 6 попыток DeepSeek с локальным ключом;
провайдер вернул HTTP 401. Ключ отличается от серверного, его значение не
выводилось и не менялось. Эти попытки не подтверждают качество ответов.

После отдельного разрешения выполнены ещё 3 запроса с серверными настройками
DeepSeek. Новый Python-пакет загружен во временный процесс; работающее приложение
не заменялось. MCP-backend синтетический: одна встреча, дата сервера 2026-11-16,
Москва, `/events`; подготовка возвращает тестовую карточку, бизнес-записей нет.

| Вопрос | Наблюдаемый результат |
| --- | --- |
| «какие события у меня на этой неделе?» | get_service_context(calendar, week); встреча «Кофе с наставником» 17 ноября, 11:00 МСК, ссылка на календарь |
| «Покажи события с 2026-11-26 по 2026-11-28» | Обе даты переданы в инструмент; честный ответ об отсутствии событий, источник `/events` |
| «Создай созвон Разбор задачи завтра в 15:00» | Чтение tomorrow, затем create_calendar_event с title «Разбор задачи», kind «Созвон», starts_at `2026-11-17T15:00:00+03:00`; карточка подтверждения |

Во всех трёх случаях одна генерация, статус проверки источников accepted,
guard events пусты. В истории перед каждым вопросом был старый отказ о том,
что календарь недоступен; свежий инструмент имел приоритет. Это проверка трёх
синтетических примеров и формы вызовов, не оценка качества на holdout или
доказательство корректности всех формулировок. Запись/повтор/отмена проверены
автотестами на изолированной PostgreSQL, не на рабочих событиях.
