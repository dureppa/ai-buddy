# Аудит переходов из чата — 15 ноября 2026

Проверено по текущему main b6580ad и исправлению в ветке fix/chat-action-destinations. До этого отдельным PR #78 завершены development/уточнение Python; этот блок меняет навигацию и доступ к уже реализованным функциям.

## Найдено и исправлено

1. get_task_context всегда отдавал task-reference `/onboarding`. Для papers это открывало общий локальный чек-лист вместо документов, даже при наличии action_url. Go теперь использует task_id и настроенный публичный URL одновременно для action_url и источника.
2. У papers не было alias для чтения документов в get_task_evidence; неподдержанные задания ссылались на согласия. Теперь papers/documents читают один Documents API, остальные неподключённые evidence остаются пустыми со ссылкой на конкретное задание.
3. Старые `/resources?article=...` игнорировались страницей каталога. Известные article IDs преобразуются в действующий сервис/экран, неизвестные помечаются недоступными; переход не угадывается по тексту модели.
4. Старые task-карточки истории с `/onboarding` исправляются при чтении по текущим задачам владельца. Совпадение заголовка должно быть единственным; ошибки/неоднозначность не выдумывают цель и не меняют запись БД. Общая ссылка на план честно называется «Открыть план адаптации».
5. Не было экрана конкретного серверного задания. Добавлен `/onboarding/tasks/:taskId`: существующий авторизованный GET /api/v1/onboarding, инструкция и статус. Неизвестный task/сбой показывает ошибку и возврат в чат; автоотметок нет.
6. Ссылки внешних demo-сервисов теряли профиль при разных hostname/cookie. Известные origins получают только публичный demo-profile, query/якорь сохраняются. HR/рабочие сервисы и портал читают один проверенный profile из query, cookie Buddy имеет приоритет. Токены в URL не передаются, сессия/ACL остаются серверными.
7. «Мои заявки» вело на вкладку каталога портала. Источник теперь имеет `tab=requests`, портал открывает соответствующую вкладку. Отправка/отмена при открытии не выполняется.

## Фактическая проверка и границы

- Go-регрессии проходят реальный HTTP handler MCP bridge для papers и проверяют публичный URL источника. Отдельно проверяются alias/evidence, возврат unknown task, история владельца, неоднозначный title, ошибки progress/context и URL без смены чужого источника.
- Frontend-тесты: обе версии чата, все известные legacy article IDs, все девять корпоративных origins, query/anchor/profile, отсутствие профиля у чужого origin, небезопасные URL, неизвестная статья, чтение задания, ошибки/повтор и отсутствие бизнес-записи при открытии.
- Проверены read-only вход по query и приоритет cookie для HR/рабочих сервисов и вкладка запросов портала.
- В браузере изолированного локального стенда проверены: конкретная инструкция equipment, переход чат → документы на другом hostname с profile=olga, экран ошибки неизвестного задания. Использовались синтетический read-only API и local demo frontend; это не проверка production Go/БД/DeepSeek. Документы/согласия/заявки не изменялись. Временные серверы остановлены.
- Изменения не развёрнуты на пользовательском сайте автоматически: публикация через отдельный PR; слияние и успешный deploy требуются для сайта. Исходный agent-v1/holdout и Python-агент этим вторым блоком не менялись.

После согласования с main сохранена функция пояснения выделенного текста (SDD 010). Новая карточка серверного задания передаёт ей ограниченный data-agent-resource с task_id/заголовком/инструкцией; запрос отправляется только по нажатию пользователя, права/параметры действий не расширяются.

Сохранено предзаполнение заявки из SDD profile-resource-kits: регрессия проверяет template+profile как с cookie Buddy, так и без него. Сводка открывается без отправки; запись остаётся только по явной кнопке.

Источники внутри панели пояснения выделения также получают текущий profileId через AgentAnswer. Регрессия проверяет корпоративный URL с сохранением page/якоря; новые обращения к модели или бизнес-записи при переходе не добавлены.
