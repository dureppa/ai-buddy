# SDD 001. Заявка на доступ

> Актуальный запуск описан в [архитектуре](../architecture.md). В Compose подтверждённое действие открывается на `/actions/:id` и сохраняется на сервере. Локальный черновик заявки в браузере остаётся у запуска `npm run dev` без `VITE_API_ENABLED`. Статус `submitted` означает, что заявку приняли и сохранили. Выдача настоящих прав в прототипе не выполняется.

Спецификация ниже описывает подготовку заявки, проверку прав и подтверждение человеком.

## Основной путь

1. Стажёр просит доступ к рабочему сервису. Если сервис нельзя однозначно определить, Buddy уточняет название. Клиент отправляет уточнение в том же диалоге.
2. AI-сервис вызывает MCP-инструмент `prepare_access_request`. Вход — идентификатор сервиса. Go получает личность стажёра из доверенного контекста вызова, проверяет права и создаёт черновик, привязанный к стажёру и сервису. Результат — идентификатор черновика, название сервиса и срок подтверждения.
3. Buddy показывает, для какого сервиса подготовлена заявка. Пользователь подтверждает действие кнопкой. Клиент отправляет идентификатор черновика в Go API.
4. Go повторно проверяет права и срок подтверждения, выполняет операцию через имитацию корпоративного сервиса и сохраняет заявку в PostgreSQL. После записи клиент получает номер и статус. Заявка видна в списке пользователя после обновления страницы.

Согласованный HTTP-контракт будет описывать `POST /chat/messages`, `POST /access-requests/drafts/{draft_id}/confirm` и `GET /access-requests`. Go отвечает за проверку разрешений и сохранение, Python — за диалог и выбор инструмента. [Черновик OpenAPI](../../contracts/openapi.yaml)

## Приёмка

| Условие | Действие | Проверяемый результат |
| --- | --- | --- |
| Стажёр имеет право запросить доступ | Называет сервис и подтверждает черновик | Клиент показывает номер и `submitted`. После обновления та же заявка видна в списке. |
| Сервис указан неоднозначно | Стажёр пишет «Запроси мне доступ» | Buddy спрашивает, к какому сервису нужен доступ. Черновик появится после уточнения. |
| Стажёр имеет право, черновик подготовлен | Закрывает карточку или уходит со страницы | Список заявок остаётся прежним. |
| У стажёра нет разрешения на запрос | Просит доступ к тому же сервису | Buddy показывает отказ. Черновик и заявка отсутствуют. |
| Право было отозвано после подготовки | Стажёр подтверждает свой черновик | API возвращает `403`. Список заявок остаётся прежним. |
| Черновик принадлежит другому стажёру | Текущий стажёр отправляет его ID | API возвращает `404`. Данные черновика и владельца остаются закрыты. |
| Срок подтверждения истёк | Стажёр впервые подтверждает этот черновик | API возвращает `409`. Клиент предлагает заново подготовить заявку. |
| Та же заявка уже подтверждена | Клиент повторяет запрос под тем же профилем | Go возвращает ранее сохранённый номер без повторной операции. |
| Имитация сервиса недоступна | Стажёр подтверждает действующий черновик | UI показывает сбой и возможность повторить запрос. Успех показывается после сохранения. Повтор с тем же черновиком использует тот же ключ операции. |

Для демонстрации понадобятся два тестовых профиля с разными правами на один сервис. Их данные добавляются вместе с первой рабочей схемой хранения. [Маршрут проверки](../demo.md)
