# Демонстрационные HR-сервисы

В разделе «Корпоративные сервисы» и поиске AI Buddy доступны ссылки на шесть самостоятельных сайтов. Каждый сайт показывает один сервис, собственный синтетический демопрофиль и историю действий на своём origin.

Карточки HR-сервисов в разделе «Корпоративные сервисы» открывают сайт в новой вкладке, сохраняя текущую вкладку AI Buddy. Самостоятельные страницы сервисов, включая документы и мероприятия, не содержат кнопки «Вернуться в AI Buddy» ни в локальном, ни в серверном режиме. Если сайт недоступен, браузер показывает ошибку в новой вкладке.

| Сервис | Действие и проверки |
| --- | --- |
| Отсутствия | Выбрать период отпуска в календаре. Проверяются минимальный срок подачи, пересечения с записями и остаток календарных дней. |
| Командировки | Выбрать город и дату, указать смету. Проверяются право на поездку, срок подачи, открытая заявка и лимит сметы. |
| Найм | Порекомендовать кандидата на открытую вакансию. Проверяются лимит рекомендаций, формат имени и почты, а также повторная рекомендация на ту же вакансию. |
| Увольнения | Отметить шаги подготовки и сохранить черновик завершения работы. Проверяются обязательные шаги, срок уведомления и наличие черновика. Черновик остаётся в демо. |
| Согласия | Предоставить или отозвать согласие для выбранной цели. Обязательное для работы согласие отображается отдельно от двух управляемых. Повтор операции с тем же состоянием не создаёт запись. |
| Бенефиты | Запросить компенсацию на доступную программу. Проверяются право участия, остаток бюджета и повторная заявка на программу. |

Успешное действие обновляет историю и рассчитанные лимиты. При ошибке страница показывает причину, состояние сохраняет предыдущие значения. История действий хранится локально на сайте и доступна после перезагрузки. Настройки профилей описаны в JSON-фикстуре, а в интерфейсе используется фиксированный демопрофиль. При серверной интеграции сайт и инструмент агента должны читать и обновлять данные через API соответствующего сервиса.

При VITE_API_ENABLED=true согласия используют Go API и PostgreSQL, включая
версию updated_at для evidence. Повторное присвоение того же значения сохраняет
версию. Найм, увольнения и бенефиты также читают каталог, лимиты и историю
из Go API и записывают действия через него. Сохранённое действие видно после
повторного входа с тем же демопрофилем. Во время записи формы блокируются.
При отказе API интерфейс показывает ошибку и сохраняет введённые данные.
Если запись прошла, а перечитать данные не удалось, интерфейс сообщает
о сохранении и предлагает обновить страницу.

### Серверный экран согласий

При включённом API сохраняется оформление HR-сайтов: заголовок с описанием,
карточки согласий и боковая карточка выбранного профиля со счётчиком.
Аккаунт автоматически берётся из сессии Buddy; повторного выбора нет.
Состояния загрузки и ошибки показываются внутри общего оформления; при ошибке
счётчик неизвестен и действия заблокированы. Боковая панель показывает текущее
состояние API, а не выдуманную историю. После перезагрузки данные читаются с сервера.

### Вход без Buddy

Каждый из восьми HR-сервисов выдаёт собственную демосессию через
`POST /api/v1/demo/sessions`. Сессия действует только в сервисе, который её
выдал. При входе с активным профилем Buddy сайт выбирает его автоматически.
Без активного профиля пользователь выбирает учебный аккаунт на странице
сервиса. Запросы от Buddy по-прежнему проверяются сервером по подписанному
токену. Сервис подключается своей ролью к собственной базе PostgreSQL.

### Открытие формы из чата

Вопрос об оформлении отгула/отпуска передаётся LLM без контекста ранее выбранного пункта. Одновременно показывается известная ссылка «Отсутствия»; она остаётся доступной при сбое модели. Готовый ответ от имени агента не подставляется. Это навигация: выбор дат и отправка происходят в сервисе. Отдельный тип «отгул» в демо отсутствует, реализован календарь отпуска. Смена темы не отмечает чек-лист выполненным.

Поиск знаний считает «отгул» поисковым синонимом «отпуск», сохраняя ограничения длины, ACL и limit. Это расширяет поиск опубликованного материала, а не подтверждает наличие отдельного типа отсутствия или права на него.
