# Остальные сервисы: чтение и действия с подтверждением

## Границы

Найм, увольнения, бенефиты и Jira подключаются через Go к существующим API.
Python MCP предоставляет два инструмента: get_service_context и
prepare_service_action. Профиль берётся из проверенной делегации, не из аргументов.
Короткий ответ остаётся ограничен вопросом пользователя; произвольные URL,
чужие профили, команды из документов и подмена идентичности не поддерживаются.

- Найм: вакансии, остаток рекомендаций и свои рекомендации; подготовка рекомендации.
- Увольнения: срок уведомления, шаги, отметки и собственный черновик; подготовка отметки шага/даты черновика. Это не увольнение сотрудника и не одобрение этапа.
- Бенефиты: доступные варианты, бюджет и свои заявки; подготовка заявки на выбранный вариант. Сохранение заявки не означает выплату.
- Jira: видимые пространства/доски, свои задачи, чтение конкретной доски/задачи; подготовка создания и частичного изменения задачи. Jira проверяет ACL; версия защищает изменение от перезаписи чужих правок.

## Подтверждение

prepare_service_action только проверяет данные и сохраняет неизменяемый черновик
в PostgreSQL Buddy на 10 минут. Возвращается ссылка /actions/{id}. По ней
пользователь видит операцию и точные параметры, затем нажимает «Подтвердить»
или «Отменить». В тексте чата не заявляется успех до выполнения операции.
MCP не имеет инструмента выполнения/подтверждения черновика.

Публичные GET/confirm/cancel требуют сессию владельца. Перед выполнением Go
повторно проверяет сервис/ресурс и версию. Одна атомарная смена prepared→executing
разрешает только одну попытку HTTP-записи; повторные подтверждения возвращают
сохранённое состояние. Аналогичный активный черновик переиспользуется, а не
дублируется при повторе tool call. Отмена/истечение срока исключают выполнение.

Если сервис подтвердил успех, сохраняется receipt. Если запись могла состояться,
но ответ потерян/некорректен, состояние uncertain; автоматической повторной
записи нет. Пользователь проверяет результат в сервисе. После рестарта executing
также не выполняется повторно. Это гарантия одной попытки отправки, не обещание
распределённой exactly-once транзакции. Известный отказ/конфликт возвращается
как failed, без заявления об успехе. Результат Jira update не пересогласовывается
на новой версии автоматически.

## Сеть и ошибки

Go использует только настроенные origins, ограничивает время/размер и не следует
redirect. В HR выпускается короткий профильный JWT, в Jira — JWT с её issuer и
audience; токены делегации и сервиса не пересылаются в корпоративные API.
Неизвестный ресурс/чужая задача — NOT_FOUND/FORBIDDEN, неверные данные —
INVALID_ARGUMENTS, недоступность — TEMPORARILY_UNAVAILABLE. Недоступный сервис
не заменяется локальными демонстрационными данными. Списки ограничены, усечение
показывается явно. Тексты результата проходят прежний screening до модели.

## Приёмка

Проверить четыре чтения и шесть типов действий, владельца/ACL, неизвестные
поля/идентификаторы, отсутствие записи при prepare, отмену/TTL, два одновременных
confirm, timeout/неопределённый исход, конфликт Jira version и сохранение состояния
после повторного открытия ссылки. Проверки бизнес-записи используют изолированные
данные/HTTP fixtures; реальные пользовательские операции не выполняются автоматически.
