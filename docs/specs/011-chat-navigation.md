# Ссылки и действия из чата

Карточка источника открывает материал/сервис, которому принадлежит источник, а не общий чек-лист с названием конкретной задачи. Назначение определяется Go task_id/source_id и настроенным публичным URL, не текстом, придуманным моделью.

## Назначения

| Источник | Переход |
| --- | --- |
| papers / documents | Настроенный публичный сервис документов |
| consent-news | Сервис согласий |
| events | Сервис мероприятий |
| Задание с action_url | Безопасный адрес действия; известные старые article-ссылки открывают соответствующий экран |
| Задание без действия | Карточка `/onboarding/tasks/:taskId` с фактической инструкцией Go для текущего профиля |
| Личный прогресс | Общий `/onboarding` с честным названием «Открыть план адаптации» |
| Команда | `/team` |
| Старые product / contacts / timeoff article URL | `/product-guide`, `/team`, сервис отсутствий |
| Старые equipment / learning article URL | Карточки серверных заданий equipment / safety |
| Каталог/заявки доступа, Confluence | Публичные сервисы, tab=requests для списка, сохранённые request/page query |
| Service action | `/actions/:id`; только кнопка подтверждения на странице выполняет действие |
| Jira и инструменты направлений | Настроенные публичные страницы с query/якорем записи; read-only ограничения SDD 009 сохраняются |

Внешние demo-ссылки известных настроенных сервисов сохраняют текущий demo-профиль без токенов. Произвольные внешние источники не получают профиль. HR-страницы принимают один известный demo-profile из query, если cookie Buddy отсутствует; активный cookie имеет приоритет. Это выбор публичного demo-аккаунта, не авторизация вместо серверной сессии/ACL. Неизвестные/небезопасные URL не превращаются в исполняемые ссылки. Модель не получает новых полномочий.

Карточка задания читает существующий GET /api/v1/onboarding с сессией владельца. Открытие ничего не завершает. Ошибка/неизвестное задание дают понятное сообщение и возможность вернуться в чат, без подстановки локального вымышленного задания. Внешняя ссылка открывает сервис, а не выполняет его операцию. Отметка документов — учебное чтение, не юридическая подпись и не одобрение наставника.

Проверка evidence для papers использует тот же учебный Documents API, что documents. Неизвестное задание не получает ложную ссылку на согласия; без подключённого evidence подтверждений нет. Агент не отмечает документ и не переводит этап.

Проверки: все типы ссылок инструментов, алиасы task/source, работа с query/якорем, защита URL, профиль только для известных сервисов, полная/быстрая версия чата, успех/ошибка/отсутствие серверного задания. Действия HR/Jira/access используют прежние контракты и отдельное подтверждение человека; новые операции не добавляются только ради наличия кнопки.

Одинаковые правила назначения и demo-profile действуют для источников в основной/быстрой версии чата и панели пояснения выделения.
