# SDD 004. DeepSeek и живые сервисы

`AI_LLM_PROVIDER=deepseek` выбирает облачный Chat Completions через существующий
httpx; ollama остаётся вариантом по умолчанию. Обязателен DEEPSEEK_API_KEY,
DEEPSEEK_MODEL=deepseek-flash, фиксированный HTTPS DEEPSEEK_BASE_URL.
Ключи, история и сырые ответы не логируются. Thinking выключен. Каждый tool
result связан с исходным tool_call_id. Assessment использует JSON mode и
существующую локальную проверку схемы. Нет повторов и fallback.
401/403/5xx → AI_UNAVAILABLE, 429 → AI_RATE_LIMITED, timeout → AI_TIMEOUT,
невалидный/пустой/усечённый ответ → AI_INVALID_RESPONSE. Deadline и лимиты прежние.

Go проверяет сессию и владение диалогом, сохраняет вопрос, вызывает Flask,
сохраняет ответ. История ограничена 20 сообщениями. Диалог читает только владелец.
URL очищается от query/fragment. Ошибка AI не становится успешным ответом.
MCP resolve получает отдельный service token и делегацию на 60 секунд,
привязанную к профилю, диалогу и request ID. Resource token имеет другую audience.
Чтения проверяют TTL, request ID, актуальный профиль. Все источники синтетические.

Новые tools: get_onboarding_progress (задачи и следующий шаг),
get_task_context(task_id) (инструкция), get_task_evidence(task_id) (актуальное
подтверждение из сервиса согласий для consent-news). Отметка baseline-чеклиста
не является подтверждением HR-действия. Агент не изменяет согласия. Пользователь
действует явно на сайте; сайт и агент используют один Go HR API с проверкой JWT.
При сбое сервиса возвращается ошибка, локальное состояние не подставляется.

Приёмка: provider mock (tools/JSON/ошибки/таймауты), Go → Flask mock
(сохранение/история/чужой диалог), SDK MCP → Go HTTP, реальный короткий DeepSeek
запрос отдельно от CI. Согласие переживает перезагрузку; отзыв перестаёт быть
актуальным подтверждением. Новые тесты включены в существующие CI jobs.

Базовый Go demo-вход выдаёт только стажёров; отдельное состояние и права
учебного review определены ниже. HR-действие не равно одобрению этапа.

## Учебный review

Для consent-news добавляется отдельное состояние: not_started → evaluating →
awaiting_review / needs_revision → completed. Стажёр отправляет только свой
ответ; Go задаёт рубрику, версии и подтверждение. Результат Flask сохраняется
только для актуального evaluation_id и совпадающих версий/hash ответа.
При ошибке оценки остаётся needs_revision, перехода нет. Все обязательные
критерии должны иметь pass. Оценка не завершает задачу.

В DEMO_MODE доступен отдельный вход mentor/lead, токен с audience staff-review.
Наставник видит olga/sasha, руководитель — также maria. Staff-токен не даёт
доступ к API стажёра; сессионный токен стажёра не даёт права review.
Наставник одобряет или возвращает последнюю оценку с ожидаемым evaluation_id.
Перед одобрением Go повторно читает HR-подтверждение, сравнивает его версию и
в транзакции проверяет актуальную оценку, сохраняет решение, completion и
состояние completed. Это переход учебного задания; глобальные этапы стажировки
и обязательные условия других этапов этим срезом не определяются.
Отзыв согласия до review блокирует одобрение. После завершения задания отзыв
добровольного согласия не отменяет факт пройденного обучения.
