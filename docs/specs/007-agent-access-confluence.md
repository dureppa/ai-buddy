# Серверные заявки агента и база знаний Confluence

Портал доступов переводится с localStorage на Go/PostgreSQL. Форма и подтверждённое действие `request_access` вызывают одну
бизнес-операцию; заявки видны из разных
браузеров. Устаревшие локальные записи не импортируются и не выдаются за серверные.
Идентичность, продукт, команда и специальность берутся из серверных profiles (team_id/job_role/can_review_access) по
проверенной сессии, не из текста/аргументов агента. Каталог, допустимые права,
ресурсы и дополнительные поля проверяются сервером. Ресурс должен принадлежать
продукту пользователя, шаблон — подходить специальности. Базовые common-ресурсы
Jira, VPN, Confluence, календарь, почта, мессенджер, Grafana и PaaS доступны всем стажёрам. Чужие заявки и страницы возвращают 404/403 без данных.

По просьбе «Запроси/оформи доступ…» агент читает свежий get_access_catalog,
включая уточнения с параметрами без повторного слова «доступ». Он использует
template.id, system, catalog.version и точные resources[].resource_key из
каталога, уточняет обязательные параметры и вызывает prepare_service_action
с operation=request_access. Работают все шаблоны каталога, разрешённые текущему
профилю. Недоступный ресурс или роль не заменяются ресурсом другой команды.
Вопрос «как запросить» даёт инструкцию, а не действие. Прежний прямой
submit_access_request не выдаётся MCP-делегации; отправка из чата отключена.

Подготовка сохраняет только неизменяемый черновик на 10 минут и ссылку
/actions/:id, как для Jira. Пользователь проверяет систему, ресурс, права,
срок, обоснование и дополнительные поля. Только кнопка «Подтвердить» отправляет
одну попытку в существующий портал. Перед отправкой каталог и права проверяются
заново. Открытие, обновление страницы, отмена и истечение срока ничего не
отправляют. При успехе сохраняется номер заявки; повтор подтверждения возвращает
тот же результат. При неопределённом исходе повторной отправки нет: статус
проверяется в портале. Read-only разбор пункта не может подготовить действие.
Профиль, продукт, статус и согласующий определяются сервером, не аргументами.

Успех означает только submitted и номер в БД. Подтверждение результата строится
из сохранённой записи, не из текста LLM. Повтор одного turn или активной заявки
на тот же ресурс/уровень возвращает ту же запись. После сбоя ответа созданная
заявка остаётся в списке; повтор не дублирует её. Продление и новые права требуют
новой заявки. Список заявок доступен автору. Автор может отменить отправленную заявку.
Согласование заявки руководителем отключено. [Спецификация инструментов](intern-tools.md).

Confluence — самостоятельный сайт на 5191 из «Инструментов и доступов», рядом
с Jira. Использует Go API и таблицу confluence_pages в существующей PostgreSQL
Buddy. Есть пространство продукта, страница команды, страницы четырёх
специальностей, гайды по заявкам, уровням прав, статусам и первым шагам. Данные
учебные, не внутренние инструкции реального Авито. Страницы продукта видны
только его участникам; общие роли/гайды видны всем. Поиск и get_knowledge_page
проверяют тот же ACL. Агент search_knowledge использует эти же сохранённые
страницы с цитируемыми id/версиями/URL; текст страниц не является инструкцией
для выполнения операций. UI read-only, без загрузки произвольного HTML.

Ошибки: 400 некорректные поля, 401 сессия/делегация, 403 политика, 404 отсутствующий
или чужой объект, 409 устаревшее решение, 503 БД. Повреждённая схема/отказ API
не подменяются демоданными. Тесты покрывают запрет записи без ручного подтверждения,
разделение пользователей/продуктов, валидацию уровней/ресурсов, идемпотентность,
конкурентную отправку, ошибки хранилища и выдачу подтверждённого номера.

## Портал на HTTP-сервере

Страница управления доступами открывается и по обычному HTTP удалённого демо.
Ключ операции создаётся через доступный там crypto.getRandomValues, без вызова
требующего secure context crypto.randomUUID. Криптографический источник не
заменяется Math.random. Отсутствие randomUUID не мешает начальному рендеру каталога.

Ключ сохраняется на повторных рендерах и при повторной отправке после ошибки;
смена ключа допускается при выборе новой формы и после подтверждённого успеха.
Проверяются загрузка страницы без randomUUID, открытие формы, сводка, повтор
после сбоя с тем же Idempotency-Key и новая операция с новым ключом. Права,
подтверждение формы и серверная дедупликация не меняются.

### Самостоятельный запуск Confluence

В серверной конфигурации сайт на 5191 обращается к отдельному Go-процессу
Confluence. Он использует свою БД `buddy_tool_confluence` и работает при
выключенном Buddy. В деморежиме посетитель может выбрать учебный профиль
и получить сессию у Confluence. Сервис определяет продукт по профилю и
возвращает 404 для страниц другого продукта. Обновление сохраняет ID,
версии и даты уже перенесённых страниц. Buddy получает страницы и результаты
поиска через HTTP и сохраняет ссылки на исходные страницы.
