# Календарь: общий источник для веба и агента

«События» (`/events`) и главная читают личный календарь Go/PostgreSQL по
проверенной сессии. MCP `get_service_context(service=calendar)` читает тот же
календарь по делегированному профилю. Профиль/владелец не принимается от модели.
Это личные встречи, созвоны и напоминания Buddy; каталог корпоративных мероприятий
и HR-сводка остаются отдельными источниками и не подменяют календарь.

Чтение принимает `period=today|tomorrow|week|next_week|month` (по умолчанию
текущая неделя, понедельник–воскресенье) либо пару `start_date`/`end_date`.
Даты включительны, интервал не больше 366 дней, границы считаются по Москве.
Ответ содержит дату сервера, timezone, границы периода, отсортированные события,
`has_more` и источник `/events`. Агент отвечает только о запрошенном периоде;
пустой календарь не означает запрет доступа и не отправляет к наставнику.
При ошибке показывает ссылку на календарь и сообщает о недоступности чтения.

`prepare_service_action(create_calendar_event)` принимает название, тип
«Встреча»/«Созвон»/«Напоминание», `starts_at` с часовым поясом и описание.
Тип по умолчанию «Встреча», описание пустое. Название и дата/время обязательны:
агент уточняет их, не придумывает. Серверная текущая дата и Москва используются
для «завтра/в пятницу»; при неоднозначности времени агент уточняет.
Событие соответствует существующей форме: один момент начала, без участников,
рассылки приглашений и синхронизации с внешним календарём.

Подготовка сохраняет только черновик на 10 минут и ссылку `/actions/:id`.
Создание происходит после ручного подтверждения владельцем, с повторной
проверкой будущей даты. Отмена, TTL, чужой профиль и повторное подтверждение
не создают событие. ID события равен ID черновика: повтор операции не дублирует
его даже при неопределённом исходе. Ссылка ведёт в `/events`; обновление/переход
и фокус страницы перечитывают календарь. UI создаёт, редактирует и удаляет
события через тот же Go API и показывает ошибки без локальной подмены успеха.

Фраза модели о готовности черновика принимается только при успешном prepare
в текущем ходе; ссылка календаря этого не подтверждает. Без результата
runtime запрашивает исправление, затем честно сообщает об отсутствии карточки
при исчерпании лимита. [Правила проверки результата](action-result-proof.md).

Старые записи браузера импортируются идемпотентно для текущего профиля, до чтения
веба. Уникальные записи другого старого браузера также переносятся. Пустой
старый календарь заменяет только начальные демозаписи. Импорт атомарен, не перезаписывает
серверные пользовательские изменения и не воскрешает удалённые события. После
успеха старый ключ этого профиля переносится в `.backup`; если резервную копию
сохранить нельзя, исходный ключ остаётся. Без Go сохраняется локальный
режим. Демо-встречи создаются сервером один раз, а не заново при каждом чтении.

Проверки: понедельник/воскресенье, Москва/UTC и переход месяца/года; произвольный
период, границы и усечение; текущий профиль и отказ без сессии; подтверждение,
отмена/TTL/дубли/прошедшая дата; импорт, пустой календарь, удаление и смена
браузера; вопросы со скриншота после старого отказа; ссылки и отказ источника;
контракты Go/MCP/Python/TypeScript. Автоматические тесты подменяют LLM.
