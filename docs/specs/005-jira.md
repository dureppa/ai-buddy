# Jira: самостоятельный трекер задач

Переход из «Корпоративных сервисов» открывает Jira в новой вкладке на 5189.
В URL передаётся только идентификатор демопрофиля, не токен. Собственные
демосессии Jira: HS256, audience/issuer jira, срок 8 часов. Demo-вход включается
только DEMO_MODE=true; это учебная среда без корпоративного SSO.

Go API (8189) использует отдельную PostgreSQL `jira`, роль и том. Схема: users,
spaces → space_members, boards → board_members, issues. Составные внешние ключи
гарантируют, что участник доски состоит в пространстве, исполнитель состоит
в доске, автор — пользователь Jira. Пользователь видит только свои пространства
и доски; запрос задач и «Мои задачи» также проверяет членство на сервере.

Интерфейс: пространства, доски, канбан (К выполнению / В работе / На проверке /
Готово), поиск по ключу/заголовку, фильтр «Только мои», карточка задачи. Участник
создаёт и редактирует заголовок, описание, статус, исполнителя, приоритет и срок.
Изменение проверяет version. Выбор доски и задачи хранится в URL.

Ошибки: 400 — некорректные поля/исполнитель, 401 — нет действующей сессии,
404 — чужой или отсутствующий объект, 409 — устаревшая версия, 503 — сбой БД.
Интерфейс показывает загрузку, пустое состояние, ошибку и повтор запроса.
Ошибки API не подменяются локальными данными.

Сиды: четыре продуктовых пространства, стажёры и наставники, доски с задачами
разных статусов и закрытая доска в своём пространстве для проверки изоляции.
Повтор сида сохраняет пользовательские правки. Управление пространствами,
досками и членством — через SQL. Админ-UI, спринты, комментарии и вложения
вне первой версии.

Контракт contracts/jira.openapi.yaml. GET /api/v1/me/issues подготовлен для
будущей главной и MCP; подключение агента и блока на главной — следующие задачи.
Будущий адаптер обязан передавать проверенную личность, не произвольный profile_id.

Серверный overlay включает Jira без отдельного профиля. CD собирает API,
сохраняет резервную копию существующей jira-db до переключения и проверяет
вход/задачи через nginx gate на 5189. Первая установка не требует старой Jira-БД.
Обновление доверенного root-owned worker выполняется администратором сервера
однократно; исходники PR не могут сами подменять доверенный deployment-код.
