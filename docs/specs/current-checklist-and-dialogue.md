# Текущий пункт адаптации и общение Buddy

## Единый выбор пункта

Веб показывает «В процессе» у первого незавершённого пункта ролевого чек-листа
с учётом отметок, опубликованных пунктов и отправленных анкет. Один общий селектор
используется экраном и контекстом чата. Это вычисляемый статус, не ручной выбор.

Каждый запрос веб-чата передаёт ограниченный `page_context.checklist`:
`status=in_progress` и `task` в существующей task-схеме либо `status=completed`
без task. При ошибке чтения отметок или анкет передаётся status=unavailable без task:
агент предлагает обновить план, не выдумывает текущую задачу или завершение.
Контекст пересчитывается при отправке, а не берётся из истории.
Go и Python проверяют форму, длины и согласованность. Личность только из сессии.
Это сведения текущего интерфейса, не доказательство выполнения серверного этапа.

Для общих вопросов «С чего начать сегодня?», «Что делать дальше?», «Какая задача дальше?», «Что дальше по плану?» и о текущем
пункте агент называет именно этот пункт и один полезный первый шаг. Ссылка ведёт
в его карточку адаптации; прикреплённые Confluence-страницы читаются с прежними
правами. Отдельный серверный next_task_id не подменяет пункт веба. При отсутствии
незавершённых пунктов агент не выдумывает новую задачу. Клиенты без checklist
сохраняют прежний серверный маршрут. «Разобрать пункт» и уточнения о явно выбранном
пункте сохраняют свой контекст. Ошибка API не подменяется локальным ответом.

Фраза «какая задача сейчас?» также выбирает текущий пункт плана.
Кнопка подсказки и такой же текстовый вопрос используют одинаковый свежий
контекст. Общий вопрос о текущем/следующем задании снимает прежний выбранный
пункт, даже если ранее открывался «Разобрать пункт». Python также отдаёт
приоритет checklist над переданным selection для такого вопроса. Завершённый
или недоступный план не подменяется выбранной ранее задачей. Уточнения
«С чего начать этот пункт?» и «Какие материалы нужны?» продолжают разбор
выбранного пункта. Проверяются переход от старого выбранного пункта к текущему,
совпадение кнопки/ввода и отсутствие записи или завершения задачи.

Чат с этим контекстом читает план. Самостоятельная отметка встроенного пункта
отправляется отдельным запросом с ID показанной задачи. Для
рекомендации следующего пункта доступны только чтения материалов; заявки и
изменения остаются отдельными поручениями с прежним подтверждением.

## Общение

Buddy говорит на «ты», спокойно, тепло и без канцелярита. На обычный рабочий
вопрос отвечает по делу; на переживания стажёра может кратко поддержать и предложить
посильный следующий шаг. Для явно разговорных реплик и поддержки корпоративный
поиск не нужен. Приветствие остаётся коротким, поддержка допускает 2–3 предложения.

Запрещены унижение, дискриминация, грубость, манипуляции и обещания, которых агент
не может выполнить. Buddy не выдаёт себя за человека или официального наставника,
не ставит диагнозы и не отменяет корпоративные процедуры. Проверка источников,
прав, инъекций, конфиденциальности и подтверждение операций сохраняются. Реплика
с корпоративным вопросом не становится разговорной только из-за приветствия
или слов о волнении. Для составного вопроса требуются реальные данные.

Самостоятельное приветствие, включая «hello», «нихао», «ni hao» и «你好»,
обрабатывается в разговорном режиме без MCP и устаревшего контекста. Регистр,
варианты пунктуации и распространённые транслитерации не меняют намерение.
Приветствие перед вопросом о текущем пункте или наставнике сохраняет обычное
чтение соответствующих данных.

## Ошибки и проверка

Неверный status/task, чужие поля, превышение длин или неподдерживаемый ресурс —
400/INVALID_REQUEST на соответствующей границе. Подозрительные инструкции в
контексте не выполняются. Недоступный MCP/LLM сохраняет прежнюю доменную ошибку.

Проверяются совпадение UI/запроса для четырёх профилей, смена текущего пункта после
отметки и анкеты, завершённый план, материалы, пользовательские пункты, повтор
запроса и выбор другого пункта для разбора. На Python: приоритет текущего пункта
над старой историей/серверным papers, безопасная ссылка, отсутствие write-tools,
поддержка без поиска и сохранение guards для рабочих вопросов.

## Подтверждение выполнения в чате

После разбора или ответа о текущем пункте в ряду подсказок появляется
«Отметить текущую задачу выполненной», если пункт доступен для самостоятельной
отметки и ещё не завершён. Анкеты заполняются через их форму. Серверные статусы,
корпоративные операции и решения наставника остаются за пределами этого действия.
Кнопка отправляет ID показанного пункта на сервер. При ошибке веб перечитывает
прогресс. Повтор доступен, пока пункт остаётся текущим. После успеха кнопка
исчезает, а кеш и вопросы обновляются. Повторное подтверждение не отмечает другой пункт.

## Подсказки вопросов

Блок «С чего начать» и кнопки над полем ввода берут вопросы из одного
ранжированного списка. Компактный чат показывает первые элементы того же списка.
Веб использует ролевой чек-лист, опубликованные пункты и подтверждённые отметки
анкет из того же состояния, из которого строится контекст чата. Запросов за
подсказками нет. После сохранения отметки или анкеты список пересчитывается.

В открытом разборе приоритет у выбранного незавершённого пункта. В общем чате
первым идёт вопрос о начале, продолжении плана или выполнении активного пункта.
Вопрос о материалах появляется, если в контексте пункта есть распознанные
страницы Confluence. После закрытия чек-листа в приоритете рабочие инструменты
и документы. При загрузке, ошибке или отсутствии плана остаются вопросы
о наставнике, инструментах и документах без предположений о прогрессе.

Кнопка отправляет тот же текст тем же обработчиком, что ручной ввод.
Для вопросов о конкретном пункте обработчик использует существующий контекст
разбора. Подсказка сама по себе не отправляет заявку и не меняет прогресс.
У ролевого чек-листа нет общего статуса «ожидает наставника» и признака
обязательности. Серверная проверка согласий не подменяет эти статусы.

### Продолжение разговора

Обе группы подсказок учитывают последний вопрос пользователя и исключают
недавние повторы. Тема календаря, инструментов, документов, доступов или команды
получает вопросы по этой теме. При смене темы старый разбор пункта сбрасывается.
Для незнакомой темы и пустой истории применяются правила чек-листа. Вопросы
по пункту зависят от его типа и прочитанных материалов. Подсказки вычисляются
без дополнительных запросов к модели.

Промпт разбора требует отвечать на последний вопрос. Для вопроса о препятствиях
нужно назвать возможные препятствия и при необходимости коротко подсказать,
как их проверить. Полный разбор даётся по явному запросу. Правила чтения,
проверки источников и ограничения действий сохраняются.


Активный разбор хранится в общей сессии веба и доступен в компактном и полном
чате. История после перезагрузки сама по себе не восстанавливает выделение.
Выделение используется при явном выборе пункта и связанных с ним уточнениях.
Независимый вопрос сбрасывает выделение и цель отметки. Контекст текущего
чек-листа передаётся отдельно и не меняет основную тему вопроса.

### Текущий пункт и серверное подтверждение

Разбор и уточнения используют selection только для чтения. Подсказка отметки
использует идентификатор первого незавершённого пункта ролевого плана.
Go определяет его по общему порядку пунктов, сохранённым отметкам и анкетам.
Обновление с условием «текущий пункт» атомарно проверяет ID и способ отметки.
Если показанный пункт устарел, запрос возвращает 409 и веб перечитывает прогресс.
При разборе другого пункта короткое «готово» требует явного выбора подсказки.
Анкеты сохраняются через свой API. Локальные пользовательские пункты и старый
серверный демоплан используют отдельные механизмы. При первом обращении можно
перенести ранее сохранённые в браузере отметки встроенных пунктов. Импорт
проверяет ID по каталогу и сохраняет уже записанные серверные отметки.
