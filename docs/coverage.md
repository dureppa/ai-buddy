# Покрытие и проверки

Дата измерения: 16 ноября 2026, ветка `feature/agent-calendar-events` поверх
main `2d26fef`. Все три прикладных контура измерены в этой задаче.
Порог прикладного контура — больше 80%. Проценты не усредняются.
Go считает операторы, Python и веб — строки. Зависимости, сгенерированный код
и тесты исключены. Сырые отчёты не коммитятся.

## Веб Buddy

Из корня: `npm run test:coverage --workspace=@ai-buddy/web`.
Vitest/V8 измеряет `web/frontend/src`, исключая `*.test.*` и `*.d.ts`.
Node 24.22.2, порог команды — 85% строк.

| Показатель | Результат |
| --- | --- |
| Тесты | 309, все прошли |
| Строки | 91,97% (1650 из 1794) |
| Операторы | 90,07% (1851 из 2055) |

Добавлены проверки серверного чтения/изменения/удаления календаря, переноса
старых и пустых записей, ошибок API, сохранения исходного ключа при ошибке,
приоритета текущего профиля, карточки создания и ссылки `/events`. UI-тест
моделирует потерю ответа после записи: повтор использует тот же ID и не
создаёт второй экземпляр. Старый локальный режим также проверяется.

Проверены одинаковый контекст кнопки «С чего начать сегодня?» и текста
«какая задача сейчас?», переход от старого выбранного пункта к текущему
для четырёх профилей и сохранение выбранного пункта для уточнения «этот пункт».
Вопросы не меняют отметки выполнения. Полный frontend-check также проверяет расширение
(10 тестов) и сайты сервисов (58 тестов), типы, формат, lint и сборки.
Эти два набора не включены в процент веба Buddy.

## Python-агент

Из `ai-agent`:

```bash
uv run --locked pytest --cov=. --cov=../ops/deploy --cov-report=term-missing --cov-fail-under=80
```

pytest-cov измеряет `ai_buddy`, `evals`, `experiments` и `ops/deploy`, исключая
тесты. Это общий контур Python, не отдельный замер runtime-пакета.

| Показатель | Результат |
| --- | --- |
| Тесты | 820, все прошли |
| Строки | 91,65% (3204 из 3496; 292 без покрытия) |

Ruff и mypy прошли. Регрессии проверяют точную фразу пользователя,
приоритет свежего плана над старым selection и историей, завершённый
и недоступный план, сохранение контекста явного разбора пункта и запрет
инструментов записи/подмены веб-плана серверным. Включены прежние контрактные,
Flask и MCP-тесты. HTTP модели заменён тестовым transport; живой DeepSeek
в этом прогоне не вызывался.

Добавлены 11 регрессий календаря: выбор инструмента после старого отказа,
неделя/завтра/месяц и явные даты, параметры периода и профиль, RFC3339 с часовым
поясом, источник календаря и подготовка подтверждения без выполнения операции.
Прежние регрессии Jira и доступов также прошли. Полный Python-прогон: 28,30 с.
Отдельно выполнены три разрешённых запроса живой DeepSeek на синтетических
данных: [результаты и ограничения](ai/calendar-check.md).

## Go API

На отдельной локальной PostgreSQL 18.4 с локалью C.utf8 применены все
`migrations/*.up.sql`, включая 14, и `seeds/demo.sql`. Go 1.26.11.
Дополнительно календарные PostgreSQL-тесты повторены с `-count=1` на временной
PostgreSQL 17 из закреплённого образа. Пользовательские базы не использовались.
CI использует PostgreSQL 17. Из `web/backend`:

```bash
TEST_DATABASE_URL=postgres://USER@127.0.0.1:5432/aibuddy_test?sslmode=disable go test -race -count=1 ./...
TEST_DATABASE_URL=postgres://USER@127.0.0.1:5432/aibuddy_test?sslmode=disable go test -coverprofile=coverage.out -covermode=atomic ./...
go tool cover -func=coverage.out
```

Пакеты Go прошли без пропусков PostgreSQL-проверок. Проверены все шаблоны каталога через
HTTP-клиент, разрешённые каталоги четырёх профилей и BI `delivery-bi`.
Подготовка/открытие ничего не отправляют; чужой профиль и отозванный ресурс
отклоняются. Реальный PostgreSQL проверяет подтверждение BI, шесть параллельных
подтверждений, один сохранённый номер, повтор и отмену.

Календарь: границы недели по Москве, смена года/високосная дата, включительные
даты и лимит 366 дней; SQL-фильтрация и сортировка, начальные записи один раз,
импорт из разных браузеров, пустой календарь, приоритет серверных изменений
и удалений, ограничение 500 активных событий. Проверены подготовка без записи,
подтверждение в PostgreSQL, отсутствие дубля, отмена/TTL/чужой профиль,
ограничение MCP-ответа 12 KiB. Настоящий HTTP сервер проверяет вход, PUT/GET/DELETE
личного календаря; общий race-прогон прошёл.

## Общий прогон

`just check` прошёл полностью: service-go-check, frontend-check, python-check,
go-check (gofmt, vet, тесты, race и atomic coverage), repository-check и
compose-check. Внешние Go-модули проверены с PostgreSQL и race; их имитации
в `corporate-services/` и `tools/` не входят в порог прикладного Go API.
`just external-check` с запуском всех 24 API в этом изменении не выполнялся.
Браузерная приёмка с живой моделью остаётся отдельной проверкой пользователя.
