# Confluence: учебная база знаний

Самостоятельный React-сайт на 5191. Открывается новой вкладкой из «Инструментов» на странице команды рядом с Jira. VITE_CONFLUENCE_URL задаёт ссылку веба,
CONFLUENCE_PUBLIC_URL — цитируемые ссылки Go; сервер использует PUBLIC_HR_ORIGIN:5191.

Демонстрационный каталог содержит 37 страниц. К описаниям продуктов, команд,
специальностей и базовым гайдам добавлены 19 практических материалов:

- Первый результат, работа с чек-листом и вопрос наставнику при блокере.
- Поиск доски Jira, создание задачи и правка при конфликте версий.
- Параметры доступа BI и DWH, отсутствующий ресурс и проверка статуса заявки.
- Сверка Redash и Trino, мониторинг Grafana и релизы PaaS, подготовка ревью
  в Bitbucket, проверка в Postman и TMS, передача макета на дизайн-ревью.
- Сквозные примеры DEL-1 и TRV-1 из данных своих продуктов.

Блок «Связанные материалы» открывает родительскую страницу, дочерние и соседние
страницы из списка, уже разрешённого текущему профилю. Примеры DEL-1 и TRV-1
доступны соответственно участникам Доставки и Путешествий. Общие инструкции
описывают демонстрационный процесс. Точные правила реального ревью, внутренние
SLA и алерты, выдача рабочих доступов и схемы реальных таблиц требуют источника
команды. Текст рендерится без HTML.

## Хранение и агент

Confluence запускается отдельным Go-процессом в Compose. Он читает таблицу
`confluence_pages` в базе `buddy_tool_confluence` под ролью `buddy_confluence`.
Миграция сохраняет страницы и версии, которые уже есть в этой базе.
Если в основной базе остались более новые версии, миграция переносит их.
Недостающие страницы добавляются из начального каталога.

Buddy обращается к Confluence по `CONFLUENCE_API_URL`. Для чтения и поиска
он выдаёт короткий токен с профилем и назначением `confluence`. Confluence
проверяет токен локально и фильтрует результаты по продукту. Ссылки в чате
указывают на `CONFLUENCE_PUBLIC_URL` и сохраняют параметр `page`.

[HTTP-контракт](../../contracts/confluence.openapi.yaml) и
[спецификация](../specs/007-agent-access-confluence.md).

## Запуск и проверки

```bash
docker compose --profile hr up -d --build --wait confluence hr-web
```

Сайт открывается на 5191. Из открытой сессии Buddy используется её профиль.
Для самостоятельного входа выбери демопрофиль на странице Confluence.
API принимает выданные Confluence сессии и позволяет читать страницы при
выключенном Buddy. Для разработки API доступен на 8191 и проксируется Vite.

`COMPOSE_CONFLUENCE_DB_PASSWORD` задаёт пароль базы,
`COMPOSE_CONFLUENCE_SESSION_SECRET` подписывает демосессии, а
`COMPOSE_CONFLUENCE_DELEGATION_SECRET` связывает только Buddy и Confluence.
Для серверного запуска задай отдельные значения в `.env`.

## Проверка поиска для агента

`TestInternGuidesThroughMCPBridge` отправляет 19 вопросов через маршруты
`search_knowledge` и `get_knowledge_page`. Он проверяет наличие нужных
страниц в первой пятёрке, ссылки на страницы, чтение полного текста и
изоляцию продуктовых примеров. Вопросы DEL-1 и TRV-1 требуют двух материалов.
Набор выполняется с `TEST_DATABASE_URL`. Для прогона через отдельный сервис
можно задать `TEST_CONFLUENCE_URL` и `TEST_CONFLUENCE_DELEGATION_SECRET`.
Для этого режима тестовая таблица Confluence должна содержать текущий seed.

На локальном стенде весь набор прошёл с отдельным Confluence. В трёх
сквозных вопросах к DeepSeek проверены Redash + Trino, Grafana + PaaS и
Postman + TMS. При уже добавленных страницах старый маршрут читал только
одну рабочую запись в каждом случае, и ссылок на Confluence было 0 из 3.
С дополнительным поиском и уточнённым форматом цитирования он дал
ссылки на подходящие страницы во всех трёх ответах. Это выборочная
проверка живой модели.

## Пояснение выделенного текста

При разборе пункта Buddy читает прикреплённые страницы через MCP с прежней проверкой доступа. Карточка источника открывает конкретную страницу Confluence. На сайте Confluence нет отдельной панели по выделению текста.
