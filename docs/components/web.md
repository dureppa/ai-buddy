# Веб-приложение

В [apps/web](../../apps/web/) зафиксированы React, React Router, TanStack Query и Zod. Исходники и frontend-конфигурация находятся в [apps/web/frontend](../../apps/web/frontend/). Общие TypeScript и Vite подключены в корневом npm workspace. [Манифест веба](../../apps/web/package.json), [версии и установка](../stack.md)

Веб-приложение реализует стартовый экран выбора продукта и аккаунта и шесть связанных экранов рабочего пространства: главную, адаптацию, команду, инструменты и доступы, корпоративные сервисы и чат Buddy. Текущая версия использует локальный demo-adapter в `src/demo.ts`, поэтому показывает прогресс, заявки, права и ответы без Go API и Python-сервиса. Позже adapter можно заменить API-клиентом по [контракту OpenAPI](../../contracts/openapi.yaml).

Кабинет по адресу `/staff` открывается при выборе наставника или руководителя внутри продукта. Оба видят стажёра своей команды и публикуют для него материалы. Стажёр видит адресованные ему публикации в разделе «Корпоративные сервисы». [Спецификация кабинета](../specs/staff-workspace.md)

### Карта фронтенда

- `frontend/src/StartScreen.tsx` и `start.css` задают двухшаговый вход и переход между карточкой продукта и шапкой команды. `LiquidBackdrop.tsx` рисует фон и отключает движение по системной настройке.
- `frontend/src/demo-accounts.ts` содержит четыре продукта, команды и двенадцать демоаккаунтов.
- `frontend/src/data.ts` содержит задачи, сервисы и материалы. Путеводитель по продукту и контакты подставляются по активному аккаунту.
- `frontend/src/demo-session.ts` управляет активным профилем. Выбор доступен на стартовом экране после выхода.
- `frontend/src/demo.ts` содержит локальное хранилище, прогресс, права и сценарий заявки на доступ. Он не имитирует полноценную серверную бизнес-логику.
- `frontend/src/App.tsx` собирает маршруты, профиль, уведомления, модальные окна, toast-сообщения и демонстрационный чат. Кнопка «Задать вопрос по работе сервиса» в боковом меню открывает форму; быстрый чат по-прежнему открывает плавающая кнопка Buddy.
- `frontend/src/service-questions.ts` записывает отправленный вопрос в `localStorage` по ключу `ai-buddy.service-questions`. На сайте список вопросов не показывается. Серверное хранение ещё не подключено.
- `frontend/src/screens.tsx` содержит шесть экранов и повторно использует карточки, фильтры, статусы и задачи.
- `frontend/src/Chat.tsx` содержит полноэкранный и быстрый чат, состояния ожидания, уточнения, черновика заявки и результата.
- `frontend/src/StaffWorkspace.tsx` содержит кабинет и карточки материалов для стажёров, а `staff-data.ts` собирает прогресс и управляет локальными публикациями.
- `frontend/src/ui.tsx` содержит иконки, Buddy, модальное окно, аватар и пустое состояние.
- `frontend/src/styles.css` содержит токены, палитру из ТЗ, адаптивные брейкпоинты, motion и reduced-motion режим.
- `frontend/src/assets/avatars/` содержит портреты WebP для всех двенадцати демоаккаунтов.
- `frontend/src/assets/buddy.webp` — оригинальный прозрачный персонаж AI-buddy для интерфейса.

Основная демонстрационная цепочка — «чек-лист первого дня → вопрос о команде или сервисе → черновик заявки → явное подтверждение → сохранённый статус». Состояния доступны и после обновления страницы в том же браузере.

## Дизайн и компоненты

1. Начни с веб-библиотеки дизайн-системы Авито в Figma, если её предоставили организаторы. Бери согласованные цвета, типографику, отступы и варианты компонентов из веб-спецификаций. [Устройство Figma-библиотеки Авито](https://habr.com/ru/companies/avito/articles/543450/)
2. Как справочный макет используй Avito UI’23 из опубликованного дизайн-челленджа. Figma вернула 403 в рабочей среде. При отсутствии доступа ориентируйся на опубликованные примеры веб-компонентов и собирай макеты проекта в Figma. [Публикация AvitoTech](https://t.me/s/avitotech?after=1671), [UI-кит Avito UI’23](https://www.figma.com/file/5w7rTOCKS7wIs5l7xrKFfY/Avito-UI%E2%80%9923?node-id=0%3A1)
3. Реализуй повторяющиеся кнопки, поля ввода, карточки, списки и диалоги как общие React-компоненты веба. Вынеси значения цвета, типографики и отступов в общие токены CSS. Согласуй названия и состояния с макетами. Для форм и чата опиши состояния ожидания, ошибки, успеха и пустого списка. [Спецификации и состояния в дизайн-системе Авито](https://habr.com/ru/companies/avito/articles/543450/)

При реализации обновляй этот документ. Укажи точку входа, карту экранов и компонентов, расположение API-клиента и тестов, ссылку на макеты и команды запуска и проверки.
