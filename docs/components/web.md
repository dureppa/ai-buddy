# Веб-приложение

`/actions/:id` открывает сохранённое действие из карточки источника чата. ServiceActionPage.tsx показывает параметры, подтверждение, отмену и результат; service-actions.ts проверяет ответы через Zod. Открытие страницы ничего не выполняет. [Подробности](service-actions.md).

## Подключение живого чата и review

VITE_API_ENABLED=true включает backend.ts: вход выбранного демопрофиля,
Go-чат, карточки источников и повторное чтение диалога после перезагрузки.
При сбое сервера demo-ответ не подставляется. Vite проксирует /api на localhost:8080;
в Compose флаг включён при сборке, nginx направляет API в Go.
Опросы стажировки и уведомления используют Go API при включённом флаге. Отметки встроенных пунктов ролевого чек-листа используют Go API. Публикации наставника используют локальный адаптер.

Постоянная форма учебного задания согласий убрана из чата. API оценки знаний
сохранён для отдельного сценария.


В [web](../../web/) зафиксированы React, React Router, TanStack Query и Zod. Исходники находятся в [web/frontend](../../web/frontend/). [Манифест](../../web/package.json), [версии](../stack.md)

Веб-приложение открывает выбор продукта и аккаунта, затем главную, адаптацию, команду, инструменты, корпоративные сервисы и чат. В сборке Compose `VITE_API_ENABLED=true`: чат, опросы, уведомления и страница `/actions/:id` ходят в Go. При включённом API стажёр и кабинет руководителя используют серверный снимок ролевого плана, включая добавленные пункты и анкеты. Публикации и привязки материалов хранятся в браузере. Команда `npm run dev` без этого флага показывает локальные ответы и не вызывает модель.

Кабинет по адресу `/staff` открывается при выборе наставника или руководителя внутри продукта. Оба видят прогресс стажёров своей команды. В демоданных на продукт приходится один стажёр, для которого доступны публикации. Стажёр видит адресованные ему публикации в разделе «Корпоративные сервисы». [Спецификация кабинета](../specs/staff-workspace.md)

### Карта фронтенда

- `frontend/src/ProductGuide.tsx` открывает внутреннюю страницу «Путеводитель по продукту» с главной. Сценарии демокоманд лежат в `product-guide-data.ts`, раздел об Авито основан на слайдах 16–18 кейса Hack&Change.
- `frontend/src/StartScreen.tsx` и `start.css` задают двухшаговый вход и переход между карточкой продукта и шапкой команды. `LiquidBackdrop.tsx` рисует фон и отключает движение по системной настройке.
- `frontend/src/demo-accounts.ts` содержит четыре продукта, команды, двенадцать демоаккаунтов и по три коллеги для каждого стажёра. В «Моей команде» и поиске доступны профили и контакты участников команды текущего стажёра.
- `frontend/src/checklist.ts` содержит этапы и задачи адаптации. Заголовок блока на главной берётся из `homeSectionTitle`: «Ближайшие задачи» до финала и «Итоги адаптации» только на финале. Общий блок одинаковый для всех ролей. Профессиональный блок бэкенда взят из чек-листа стажёра, а для аналитика, тестировщика и дизайнера заменены инструменты, курсы и книги. `data.ts` отдаёт этот список наружу вместе с сервисами и материалами. Путеводитель по продукту и контакты подставляются по активному аккаунту. Порядок встроенных пунктов общий для веба и Go. Старый серверный демоплан доступен отдельным API.
- `frontend/src/demo-session.ts` управляет активным профилем. Выбор доступен на стартовом экране после выхода.
- `frontend/src/demo.ts` содержит локальное хранилище, прогресс, права и сценарий заявки на доступ. Он не имитирует полноценную серверную бизнес-логику.
- `frontend/src/App.tsx` собирает маршруты, профиль, уведомления, модальные окна, toast-сообщения и демонстрационный чат. Настройки открываются кнопкой «Профиль» в верхней панели. Кнопка «Задать вопрос по работе сервиса» в боковом меню открывает форму; быстрый чат по-прежнему открывает плавающая кнопка Buddy.
- `frontend/src/InternshipSurvey.tsx` показывает вопросы по одному, хранит введённые ответы до подтверждения и предлагает повтор при ошибке. `surveys.ts` содержит анкеты, методы API и браузерное хранилище для режима без Go. [Спецификация](../specs/internship-surveys.md).
- `TaskRow` в `screens.tsx` передаёт сохранённое состояние опроса в `data-checked` индикатора; `styles.css` оформляет завершённый опрос той же зелёной галочкой, что и обычную задачу. Индикатор опроса недоступен для ручного переключения и не меняет вид при наведении.
- `frontend/src/service-questions.ts` записывает отправленный вопрос в `localStorage` по ключу `ai-buddy.service-questions`. На сайте список вопросов не показывается. Серверное хранение ещё не подключено.
- `frontend/src/screens.tsx` содержит шесть экранов и повторно использует карточки, фильтры, статусы и задачи.
- `frontend/src/Chat.tsx` содержит полноэкранный и быстрый чат, состояния ожидания, уточнения, черновика заявки и результата.
- `frontend/src/StaffWorkspace.tsx` содержит кабинет и карточки материалов для стажёров, а `staff-data.ts` отображает серверный прогресс и управляет локальными публикациями.
- `frontend/src/InternChecklist.tsx` открывает пункты чек-листа из кабинета, а `TaskMaterialPicker.tsx` показывает каталог по группам прямо в карточке пункта. `TaskMaterials.test.tsx` проверяет выбор в кабинете и показ вложений стажёру.
- `frontend/src/ui.tsx` содержит иконки, Buddy, модальное окно, всплывающее уведомление, аватар и пустое состояние.
- Модальное окно закрывается по собственному событию `cancel`, но не по отмене выбора файла во вложенном поле. Кнопка файла в форме материала оформлена в общей палитре через `staff.css`; введённые данные сохраняются при отмене системного выбора.
- `frontend/src/styles.css` содержит токены, палитру из ТЗ, адаптивные брейкпоинты, motion и reduced-motion режим.
- `frontend/src/assets/avatars/` содержит портреты WebP для всех двенадцати демоаккаунтов.
- `frontend/src/assets/buddy.webp` — исходный прозрачный персонаж AI-buddy и форма на экваторе. На главной питомец меняет форму по этапу профиля и отметкам чек-листа. Для начала и финала используются `buddy-baby.webp` и `buddy-adult.webp`.

Основная демонстрационная цепочка — «чек-лист первого дня → вопрос о команде или сервисе → черновик заявки → явное подтверждение → сохранённый статус». Состояния доступны и после обновления страницы в том же браузере.

## Внешние корпоративные сервисы

Раздел «Корпоративные сервисы» и глобальный поиск содержат ссылки на [внешние корпоративные демосайты](corporate-services.md). Их адреса задаются в `frontend/.env`. Экраны этих сайтов лежат в `corporate-services/<сервис>/frontend`.

- `frontend/src/CorporateDirectory.tsx` выводит внешние ссылки из `corporate-links.ts`; карточки открывают сервисы в новой вкладке.

Серверные демосессии есть у `olga`, `sasha`, `timur` и `maria`. Серверное одобрение учебной оценки принимает только `mentor` и `lead` и не покрывает все карточки наставников в кабинете. Публикации кабинета хранятся в браузере.

При включённом API раздел команды запрашивает генерацию при открытии страницы и читает результат из Go. В локальном деморежиме используются статические карточки. [Спецификация путеводителя](../specs/product-guide.md).

В «Инструментах» первыми идут три карточки под профиль, затем Jira,
Confluence и Mattermost. `tool-links.ts` задаёт состав карточек и ссылки для
панели и глобального поиска. Jira и Confluence открываются в новой вкладке с
текущим демопрофилем, Confluence — на странице команды. Другие карточки открывают
инструкции по ресурсам. Статусы и заявки ведёт отдельный портал. [Спецификация](../specs/intern-tools.md).

«События» (`/events`) позволяет создавать, переносить и удалять личные встречи, созвоны и напоминания. При включённом API расписание сохраняется в Go/PostgreSQL отдельно для каждого стажёра и читается агентом. Старые записи браузера импортируются идемпотентно с резервной копией. Главная отображает до трёх ближайших записей с учётом местного времени. Без API сохраняется браузерный режим. [Календарь](calendar.md).
`eventTones` в `schedule.ts` задаёт единые цвета типов: созвон — синий,
встреча — зелёный, напоминание — фиолетовый. Они применяются к новым,
отредактированным и ранее сохранённым событиям, включая календарь и главную.

Главная и расписание получают отпуска и командировки через Go API. [Спецификация](../specs/schedule-hr.md).

Корпоративный каталог содержит ссылку «Управление доступами» (VITE_ACCESS_URL, по умолчанию http://localhost:5190/). Ссылка передаёт текущий демопрофиль без токена. [Компонент](access-portal.md).

App.tsx синхронизирует текущий аккаунт и выход с host-only cookie для
автоматического открытия сервисов на соседних портах; см. demo-session.md.

AgentAnswer.tsx оформляет ответы и историю без новых зависимостей: выделение,
абзацы/переносы, списки, код и ссылки только на references. HTML остаётся текстом.
Источники выводятся отдельными карточками; повторные URL объединяются.

## Общая панель Buddy

BuddyPanel.tsx открывает общий ChatWindow справа от текущей страницы.
WorkspaceShell в App.tsx владеет единой историей, ожиданием, ошибкой и активным
контекстом пункта; полный ChatPage использует то же состояние. «Разобрать пункт»
передаёт контекст через checklist-question.ts и backend.ts во всех уточнениях.
В панели видны прикреплённые материалы; источники ответа оформляет AgentAnswer.
«Общий вопрос» снимает контекст. Повтор ошибки использует последний запрос,
не добавляя вторую пользовательскую реплику. WorkspaceShell пересоздаётся при
смене аккаунта: поздний ответ не переносится другому пользователю.

«Спросить Buddy» на главной, в адаптации и плавающая кнопка открывают эту же панель без
автоотправки. Панель немодальная: можно выбрать другой пункт. Escape закрывает
её, ссылка «Открыть полный чат» сохраняет историю/контекст. В узком окне панель
занимает ширину экрана. Универсальная кнопка выделения, SelectionAssistant и
отдельная история удалены; selection-context.ts сохраняет схему контекста.
Новых зависимостей нет. [Сценарий](../specs/ask-agent-checklist.md).

## Карточки и переходы чата

[SDD 011](../specs/011-chat-navigation.md), [аудит назначений](../ai/chat-navigation-audit.md). chat-links.ts преобразует только известные legacy article URL, сохраняет query/якорь и demo-profile для известных сервисов. AgentAnswer использует те же назначения для карточек и встроенных проверенных ссылок.

OnboardingTaskPage и onboarding-task.ts открывают конкретное задание Go через существующий GET /api/v1/onboarding; экран читает инструкцию/статус и не завершает задачу. Ошибка или неизвестный id не подменяются локальным заданием. ServiceSession и портал принимают проверенный demo-profile из ссылки, cookie Buddy имеет приоритет. Это не заменяет серверную сессию или ACL. «Мои заявки» открывает вкладку requests.

Стартовые наборы четырёх профилей: двенадцать чатов, доступы по специальности
и общие сервисы, пять материалов продукта/команды/роли. Наставник и руководитель видят тот же набор и
добавляют свои ссылки через существующие публикации. Ссылка доступа открывает
проверенную серверным каталогом заполненную сводку на 30 дней; отправка только
по кнопке. [Поведение](../specs/profile-resource-kits.md). Публикации остаются локальными в браузере.

Все 15 инструментов видны каждому профилю и ранжируются по специальности.
Самостоятельные сервисы и Go-каталог содержат записи всех четырёх продуктов:
карточки после первых двух рядов также открывают пространство текущей команды.
[Порядок и границы](../specs/role-tool-ranking.md).

## Текущий пункт для Buddy

`current-task.ts` выбирает первый незавершённый пункт из `checklistFor` и
`workspace.completed`. Тот же селектор определяет «В процессе» и snapshot
`page_context.checklist` при каждой отправке чата. Отметки, пользовательские
пункты и отправленные анкеты учитываются; история не фиксирует старую задачу.
При ошибке чтения анкет snapshot имеет status=unavailable. Явно выбранный пункт
разбора передаётся отдельно и имеет приоритет в своём режиме. Ссылка источника
открывает конкретную карточку, включая опубликованный наставником пункт.
[Поведение](../specs/current-checklist-and-dialogue.md).

Вопросы «Какая задача дальше?» и «Что дальше по плану?» используют тот же актуальный пункт веб-чек-листа, что карточка отметки; после выполнения контекст следующего запроса пересчитывается.

Самостоятельная отметка доступна как кнопка в ряду подсказок после обсуждения
незавершённого пункта. Она использует существующий `completeTask` и исчезает
после сохранения. Сбой оставляет возможность повтора. Для анкет сохраняется
отдельная форма. Отметка меняет только пользовательский чек-лист.

Вопрос об оформлении отпуска/отгула продолжает отправляться LLM. Клиент снимает контекст прежнего пункта и показывает отдельную ссылку «Отсутствия», доступную даже при ошибке ответа. Кнопка не отправляет заявку и не подтверждает чек-лист.

Общий вопрос «какая задача сейчас?» или «С чего начать сегодня?» выбирает
свежий пункт «В процессе», даже после разбора другого задания. Старый selection
снимается; уточнение «С чего начать этот пункт?» сохраняет выбранный пункт.
Кнопка подсказки и текст используют один контекст.

Подсказки чата определяет `chat-suggestions.ts` по актуальному пункту,
отметкам ролевого чек-листа и страницам Confluence, которые можно прочитать
при разборе пункта. Полный чат и панель Buddy получают один список через
`WorkspaceShell`; над полем ввода отображаются первые вопросы из этого списка.
Сохранение отметки или анкеты обновляет существующий кеш и подсказки.
При недоступном плане показываются вопросы о наставнике, инструментах и документах.
[Правила и ограничения](../specs/current-checklist-and-dialogue.md#подсказки-вопросов).

Подсказки учитывают тему последней реплики пользователя и исключают недавние
повторы. При смене темы активный разбор сбрасывается если очередной вопрос не относится к выбранному пункту. Неизвестные формулировки используют обычные правила чек-листа.

Каталог `demo-accounts.ts` содержит по три стажёра каждой команды. `teamInterns` задаёт список получателей; `primaryProfile` выбирает общий шаблон специальности. Прогресс и записи остаются привязаны к собственному ID. Кабинет передаёт ID выбранного стажёра в добавление/удаление пунктов и привязку материалов; публикация может иметь несколько получателей своей команды.
