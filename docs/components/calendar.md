# Личный календарь

Веб `/events`, ближайшие события главной и агент используют один календарь
Go/PostgreSQL. Это личные встречи, созвоны и напоминания; каталог HR-мероприятий
и сводка отпусков/поездок за сегодня остаются самостоятельными источниками.
[Спецификация](../specs/agent-calendar.md).

`internal/calendar` содержит валидацию событий и московских периодов,
PostgreSQL-репозиторий и HTTP-маршруты. Миграция `14_calendar` добавляет
`calendar_events`, состояние переноса и значение calendar для черновиков.
Дополнительных сервисов, библиотек и переменных окружения нет.

Публичные маршруты Go требуют сессию текущего профиля:

- `GET /api/v1/schedule/events` — до 500 личных событий, по времени.
- `PUT /api/v1/schedule/events/{id}` — создать/изменить одну запись.
- `DELETE /api/v1/schedule/events/{id}` — удалить свою запись.
- `POST /api/v1/schedule/import` — идемпотентно перенести старые записи браузера.

Сервер вычисляет цвет по типу. Новое время должно быть будущим; у прошедшей
записи можно менять название/тип, сохранив прежнее время. Календарь ограничен
500 активными записями. Серверные пользовательские изменения и удалённые записи
имеют приоритет при импорте; начальные демозаписи удаляются только при первом
импорте. Уникальные записи из другого старого браузера также переносятся.
Старый ключ браузера сохраняется в `.backup` перед удалением. При ошибке
переноса или сохранения резервной копии исходный ключ остаётся.

MCP использует существующий `get_service_context(service=calendar)`,
`period` либо обе даты `start_date`/`end_date`. Неделя — понедельник–воскресенье,
даты включительны, timezone Europe/Moscow. Ответ ограничен 30 записями и
12 KiB, `has_more` сообщает о неполноте. `today` задаёт текущую серверную дату
для относительных сроков. Источник — `/events`.

`prepare_service_action(create_calendar_event)` готовит черновик; только
подтверждение владельца сохраняет событие. Его ID равен ID черновика, повторное
выполнение с другим содержимым отклоняется. У модели нет confirm-инструмента.
Карточка показывает московские дату/время и ссылку на календарь.

Веб: `schedule-api.ts` проверяет данные Zod, переносит старые записи и отправляет
одну операцию; `App.tsx` использует TanStack Query с перечитыванием при фокусе
и раз в 30 секунд; `EventsPage.tsx` ждёт сохранения и сохраняет ID между
повторными попытками. Без Go работает прежний браузерный режим.

Проверки: `just check`; для PostgreSQL-тестов задать отдельный
`TEST_DATABASE_URL`. Календарные тесты создают свою схему и применяют миграции
с сидом; пользовательская БД не подходит. CI go предоставляет тестовую БД.
Python-регрессии — `tests/test_calendar.py`, веб — `schedule-api.test.ts`,
`App.test.tsx`, `service-actions.test.tsx`.

MVP: записи с одним временем начала, без участников, приглашений, повторения,
длительности и синхронизации с внешним корпоративным календарём.
