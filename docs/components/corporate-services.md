# Корпоративные демосайты

Найм, увольнения и бенефиты подключены к агенту через свои API. Подготовка рекомендации/отметки/черновика/заявки не изменяет HR: пользователь подтверждает операцию в Buddy. [Подключение](service-actions.md). При `VITE_API_ENABLED=true` эти три страницы также отправляют действия в Go через `/hr-api/` и перечитывают статус из PostgreSQL.

## Согласия через настоящий API

При VITE_API_ENABLED=true страница согласий использует `corporate-services/consents/frontend/ConsentApi.tsx` и Go HR API,
а не localStorage. Аккаунт определяется автоматически по активной сессии Buddy. /api проксируется
в Go для демосессии; /hr-api на каждом из этих сайтов идёт в API именно этого сервиса. Ошибка не подменяется локальными
данными. Повтор установки того же значения не меняет updated_at; поле становится
версией подтверждения для проверки знаний и review. Без `VITE_API_ENABLED` сайт может оставить прежнее сохранение в браузере. Настройки: [SDD 004](../specs/004-agent-service-integration.md).


Серверный экран согласий сохраняет общее оформление HR-сайтов: заголовок,
карточки действий, текущий аккаунт и счётчик. Боковая панель
показывает текущее состояние API; при ошибке счётчик неизвестен.

AI Buddy открывает восемь самостоятельных сайтов по карточкам и результатам поиска. Документы и мероприятия хранят отметки в своих базах `hr_documents` и `hr_events`. При включённом API страница пишет только в свой Go-сервис. Без API остаётся прежнее сохранение в `localStorage` этого сайта. Экран и данные каждого сайта лежат в `corporate-services/<сервис>/frontend`, рядом с Go-кодом этого сервиса. Общие стили, демоадаптер и сборка восьми сайтов остаются в npm workspace `ops/service-sites`.

| Сайт | Адрес по умолчанию | Переменная в `web/frontend/.env` | Сборка в `ops/service-sites/dist/` |
| --- | --- | --- | --- |
| Отсутствия | http://localhost:5181/ | `VITE_ABSENCES_URL` | `absences/` |
| Командировки | http://localhost:5182/ | `VITE_TRIPS_URL` | `trips/` |
| Найм | http://localhost:5183/ | `VITE_HIRING_URL` | `hiring/` |
| Увольнения | http://localhost:5184/ | `VITE_OFFBOARDING_URL` | `offboarding/` |
| Согласия | http://localhost:5185/ | `VITE_CONSENTS_URL` | `consents/` |
| Бенефиты | http://localhost:5186/ | `VITE_BENEFITS_URL` | `benefits/` |
| Документы и инструкции | http://localhost:5187/ | `VITE_DOCUMENTS_URL` | `documents/` |
| Корпоративные мероприятия | http://localhost:5188/ | `VITE_EVENTS_URL` | `events/` |

Запуск всех сайтов из корня репозитория после `npm ci`

```bash
npm run dev --workspace=@ai-buddy/corporate-services
```

Для одного сайта передай его идентификатор, например `npm run dev --workspace=@ai-buddy/corporate-services -- absences`. Сборка всех сайтов выполняется командой `npm run build --workspace=@ai-buddy/corporate-services`. Каждый каталог сборки можно опубликовать отдельно. Сайты не содержат ссылки возврата в AI Buddy.

- `sites.mjs` запускает и собирает сайты по карте `frontend/service-ports.json`.
- `frontend/src/main.tsx` выбирает страницу для конкретной сборки. Сами экраны лежат в `corporate-services/<сервис>/frontend`, общая оболочка HR-страниц — в `HrPages.tsx`.
- `hr-demo.ts` проверяет действия и хранит демозаписи в `localStorage` текущего сайта. `hr-profiles.json` содержит синтетические начальные настройки.
- `npm test --workspace=@ai-buddy/corporate-services` запускает проверки правил, истории и профилей. CI выполняет их в общей job `frontend`.

Профиль [Docker Compose `hr`](docker-compose.md#внешние-корпоративные-сервисы) запускает демосайты и существующие Go API.

## Подключение серверов

У каждого сайта предусмотрен отдельный будущий API. Спецификация перечисляет [сценарии и правила сервисов](../specs/003-hr-services.md). При интеграции публичный контракт уточняется с владельцем соответствующего Go-мока. Сайт и инструмент агента будут обращаться к одному API, а сервис будет проверять личность сотрудника, права и состояние своих данных. Внешние ссылки передают адрес страницы. Общий вход и серверные API подключаются отдельной задачей.

Предлагаемые операции для первого подключения перечислены ниже. Пути относятся к API соответствующего сайта. Каждый API определяет сотрудника по серверной сессии или токену.

| Сервис | Чтение для страницы и агента | Действие |
| --- | --- | --- |
| Отсутствия | `GET /api/v1/me/absence-summary` — баланс, ближайшая дата, заявки | `POST /api/v1/me/absence-requests` — даты начала и окончания |
| Командировки | `GET /api/v1/me/travel-summary` — право на поездку, лимит, заявки | `POST /api/v1/me/trip-requests` — город, дата, смета |
| Найм | `GET /api/v1/me/referral-summary` — вакансии, лимит, рекомендации | `POST /api/v1/me/referrals` — вакансия, имя и почта кандидата |
| Увольнения | `GET /api/v1/me/offboarding` — шаги, срок уведомления, черновик | `PUT /api/v1/me/offboarding/checklist/{step}` — отметка шага, `POST /api/v1/me/offboarding/draft` — дата для черновика |
| Согласия | `GET /api/v1/me/consents` — цели и текущие состояния | `PUT /api/v1/me/consents/{purpose}` — предоставить или отозвать согласие |
| Бенефиты | `GET /api/v1/me/benefit-summary` — доступные программы, бюджет, заявки | `POST /api/v1/me/benefit-requests` — программа компенсации |

При включённом API страницы отсутствий и командировок создают заявки в соответствующих HR-сервисах. В локальном деморежиме используется браузерное хранилище. [Спецификация расписания](../specs/schedule-hr.md).

## Самостоятельный инструмент Jira

Jira доступна из «Инструментов и доступов» и не входит в каталог корпоративных сервисов. На порту 5189 собирается отдельный [трекер задач](jira.md) из tools/jira/frontend; backend и БД запускаются профилем jira. Он всегда использует API, не localStorage.

## Управление доступами

На порту 5190 собирается самостоятельный [демофронт](access-portal.md) с каталогом и формой заявки. Он открывается в новой вкладке с текущим демопрофилем. VITE_ACCESS_URL переопределяет адрес.

ServiceSession.tsx получает текущий аккаунт из общей для портов cookie Buddy.
Повторный выбор профиля убран из HR-сайтов и Jira. Без активного аккаунта
запросы не выполняются; чужой профиль по умолчанию не используется.

Confluence на 5191 добавлен в общую сборку/hr-web. Ссылка находится в «Инструментах и доступах», рядом с Jira. Портал доступов на 5190 теперь использует Go/PostgreSQL; [описание](access-portal.md).


### Вход и базы при выключенном Buddy

В Compose восемь Go-сервисов сами выдают демосессии. На странице можно
выбрать профиль, если браузер ещё не получил профиль из Buddy. Запусти
`docker compose --profile hr up -d --build --wait hr-web hr-absences`,
чтобы проверить отпуск без запуска Buddy. Для остальных сервисов укажи
их имена из `docker-compose.yml`. Jira использует свой профиль Compose.

Контейнер `hr-databases` создаёт роли и отдельные базы. Каждый API получает
пароль только своей БД и отдельный ключ демосессии. Настройки
`COMPOSE_HR_<СЕРВИС>_DB_PASSWORD` и `COMPOSE_HR_<СЕРВИС>_SESSION_SECRET`
перечислены в `.env.example`. При первом обновлении с общей настройкой
пароля базы переключаются на новые учётные данные.

`just external-check` запускает локально ту же проверку, что и CI. Она поднимает 24 внешних сервиса без Buddy, выдаёт
демосессии и читает записи через публичные HTTP-маршруты.

Тесты Go лежат в каталогах сервисов рядом с `main.go`. `just service-go-check` проверяет все девять модулей. При заданном `TEST_DATABASE_URL` тесты проверяют операции и изоляцию на PostgreSQL.

## Пояснение выделенного текста

Отдельной панели выделения на корпоративных сайтах нет. Разбор пункта запускается в Buddy и открывает материалы/сервисы по ссылкам. ServiceSession сохраняет синхронизацию профиля; совместимый /buddy-api/ proxy остаётся отдельно от API сервиса.

[Сценарий и ограничения](../specs/010-selection-explanation.md).

Источники панели пояснения с относительными путями Buddy открываются по `VITE_BUDDY_URL` (по умолчанию http://127.0.0.1:5173/). Для npm-разработки настройка лежит в `ops/service-sites/frontend/.env`. Compose подставляет существующий `PUBLIC_WEB_ORIGIN`; общий build-stage задаёт корпоративные URL из `PUBLIC_HR_ORIGIN` и для Buddy, и для HR, чтобы старые article-ссылки не отправляли на localhost пользователя. Адрес Buddy должен быть http(s) origin без пути/query/credentials.
