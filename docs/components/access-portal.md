# Управление доступами

Самостоятельный портал на 5190 из «Корпоративных сервисов». React/TypeScript/Zod,
Go и PostgreSQL. Девять конфигурируемых шаблонов для аналитиков (DWH, BI),
бэкендеров (репозитории, dev/stage, логи), тестировщиков (тестовые данные,
окружения), дизайнеров (Figma); Jira и VPN общие. [Текущее поведение](../specs/007-agent-access-confluence.md).

## Данные и API

Форма и агент используют одну серверную операцию. `internal/portal/catalog.json`
— общая конфигурация Go и UI; `portal_resources` хранит разрешённые ключи продукта,
`portal_access_requests` — заявки, источник, решение и ключ идемпотентности.
Миграция 09 добавляет данные о специальности в profiles. Контекст
берётся из проверенной сессии; LLM не задаёт владельца, продукт или согласующего.
Go проверяет специальность, права, срок 1–90 дней, обязательные/лишние поля и
привязанные к ресурсу namespace/URL. Повтор turn или активной заявки не создаёт дубль.

[Публичный API](../../contracts/access-portal.openapi.yaml): каталог, список,
отправка с Idempotency-Key и отмена. Стажёр видит и отменяет свои заявки.
Запросы на одобрение и отклонение возвращают 400. Старые решения доступны
автору в истории. Миграция 10 обновляет формулировки в существующих гайдах. Старые записи localStorage не импортируются.
Baseline-заявки SDD 001 остаются отдельным механизмом.

Агент читает get_access_catalog, уточняет поля и по явной просьбе вызывает
submit_access_request. Короткая делегация Go даёт запись только текущему turn.
Вопрос «как запросить» или текст документа её не разрешает. Ответ с номером
строится из записи БД. get_access_requests показывает статусы. Недостающие поля
и бизнес-ошибки требуют уточнения, а не выдуманных ресурсов.

## Запуск и файлы

`npm run dev --workspace=@ai-buddy/corporate-services -- access` — Vite 5190,
API проксируется в Go 8080. `npm run build --workspace=@ai-buddy/corporate-services`
создаёт dist/access. Compose: `docker compose --profile hr up --build -d`;
серверный CD пересобирает Go и hr-web. VITE_ACCESS_URL задаёт ссылку веба,
ACCESS_PUBLIC_URL — ссылки в источниках агента (на сервере PUBLIC_HR_ORIGIN:5190).
Cookie Buddy выбирает демопрофиль; API получает настоящую серверную демосессию.
Это демонстрационный вход, не production-аутентификация.

- `corporate-services/access/frontend/api.ts`: сессия, HTTP, Zod и ошибки без локального fallback.
- `page.tsx/style.css`: каталог, форма, сводка и личные заявки; обновление каждые 15 секунд/при фокусе.
- `catalog.ts`: типы и рекомендации, импорт общей конфигурации Go.
- `model.ts`: схема формы; старые локальные helpers оставлены для совместимости тестов, UI их не использует.
- `web/backend/internal/portal`: бизнес-операции, API и scoped knowledge.

## Проверки

Corporate Vitest покрывает API/валидацию/ошибки и веб-ссылку. PostgreSQL-тесты
portal покрывают роли, чужие ресурсы, поля, решения, повторы, конкурентную отправку,
HTTP и сбой БД; Go bridge — делегацию записи. Python — MCP-схемы и сохранённый
receipt. Всё входит в frontend/python/go jobs CI, PostgreSQL через TEST_DATABASE_URL.

Для HTTP-демо ключи Idempotency-Key создаются в `operation-key.ts` через
crypto.getRandomValues (без secure-context randomUUID). Ключ хранится в состоянии
формы, сохраняется при ошибке/повторе и меняется после успеха или выбора новой формы.
`page.test.tsx` проверяет загрузку без randomUUID и цикл отправки/повтора.


## Отдельный API и переход со старого стенда

`docker compose --profile hr up -d --build --wait access hr-web` запускает
портал на 5190 с собственным Go API. При выключенном Buddy выбери демопрофиль
на самом портале. При запуске из Buddy используется его активный профиль.
Сервис пишет в `buddy_access` под выделенной ролью. Прямой локальный API
доступен на 8190. Buddy передаёт агентские операции по HTTP с коротким
токеном, который действует только для API доступа.

При первом обновлении с предыдущего релиза CD останавливает прежний Go
Buddy перед резервной копией и переносом. Для ручного обновления останови
прежний `go` самостоятельно. Миграция копирует каталог и заявки из старой
базы, сохраняет UUID, номера, статусы и историю. После перехода новые заявки
попадают в `buddy_access`. При автоматическом откате первого релиза CD останавливает новых писателей,
переносит добавленные и изменённые заявки обратно, затем запускает прежний Go.
Для ручного отката выполни `docker compose stop go access`, затем
`docker compose run --rm --no-deps --entrypoint sh access-migrate /data/rollback.sh`
перед запуском прежнего Go.
