# Python-сервис AI Buddy

Flask принимает ход от Go, вызывает DeepSeek и инструменты MCP, возвращает текст и ссылки. Модель не выполняет запись в корпоративный сервис. Черновик готовит `prepare_service_action`, человек подтверждает его в вебе. Контракты: [service-actions](service-actions.md), [SDD 004](../specs/004-agent-service-integration.md), [SDD 008](../specs/008-remaining-agent-services.md).

## Календарь

`Trace.action_receipt` подтверждает подготовку только успешным результатом
инструмента с действующим источником текущего хода. Для распознанного поручения
проверка характерных заявлений о готовности выполняется перед исправлением
цитат: чтение календаря не доказывает наличие карточки. Повторная генерация
должна подготовить действие или запросить параметры. На лимите — честное
сообщение о неполученной карточке, без ложного успеха и обращения к наставнику.
Финальный ответ о подготовке берётся из receipt и содержит `/actions/{id}`.
[Спецификация](../specs/action-result-proof.md), [проверки](../ai/action-proof-check.md).

Вопросы о событиях за неделю/период читают личный календарь через
`get_service_context(service=calendar)`, не поиск учебных страниц. Ответ содержит
события запрошенного периода и источник `/events`; пустой список не является
отказом доступа. Сервер возвращает today/timezone для «завтра». Создание —
`prepare_service_action(create_calendar_event)` с обязательными названием и
временем начала; при нехватке данных агент уточняет. Максимум 10 событий в
ответе, остальные доступны по ссылке. [Спецификация](../specs/agent-calendar.md).

## Запуск

В Compose сервис `agent` стартует с `AI_LLM_PROVIDER=deepseek`, моделью `deepseek-flash` и `MCP_URL=http://127.0.0.1:8002/mcp`. Ключ берётся из `DEEPSEEK_API_KEY`. Без ключа или при ошибке провайдера ход завершается безопасной ошибкой, учебный ответ не подставляется.

Локально из `ai-agent` после `uv sync --locked`:

```bash
AI_AGENT_ENABLED=true \
AI_LLM_PROVIDER=deepseek \
DEEPSEEK_API_KEY=ключ \
DEEPSEEK_MODEL=deepseek-flash \
DEEPSEEK_BASE_URL=https://api.deepseek.com \
AI_SERVICE_TOKEN=local-service-token \
MCP_URL=http://127.0.0.1:8002/mcp \
uv run --locked flask --app ai_buddy:create_app run --host 127.0.0.1 --port 8001
```

Рядом должен работать MCP в режиме `go_http`, как в [python-mcp](python-mcp.md). Это development server.

`GET /health/live` проверяет процесс. `GET /health/ready` проверяет настройки выбранного провайдера и наличие runner, без сетевого вызова модели.

## Ход

`POST /internal/v1/turns`, `Authorization: Bearer AI_SERVICE_TOKEN`. Go до этого вызова проверяет пользователя и владельца диалога. В модель не передаются служебный bearer и токен делегации.

Ответ 200 содержит `reply.text` и ссылки, собранные из реально полученных источников. Сырой ответ модели, цепочка рассуждений и вывод инструментов наружу не отдаются.

После начала обработки сбой возвращается как 503 с безопасным кодом: `NOT_READY`, `AI_UNAVAILABLE`, `AI_TIMEOUT`, `AI_RATE_LIMITED`, `AI_INVALID_RESPONSE`, `MCP_UNAVAILABLE`, `MCP_TIMEOUT`, `AGENT_LIMIT_REACHED` и другие коды границы MCP. Автоматических сетевых повторов нет. Общий бюджет хода — до 25 секунд, до 3 генераций и 6 попыток инструментов.

## Файлы

- `app.py` — Flask, авторизация, выбор runner.
- `agent.py`, `runner.py` — цикл, лимиты, карточки источников.
- `deepseek.py`, `provider.py` — вызов DeepSeek.
- `mcp_client.py`, `mcp_server.py`, `go_http.py` — MCP и HTTP к Go.
- `answer_policy.py` — проверка источников.
- `service_schemas.py` — схемы чтений и черновиков.
- `assessment.py` — отдельная оценка учебного ответа, не шаг основного чата.

Каталог инструментов направления читается через `get_work_tools` и `get_work_tool_context`. Эти вызовы только читают данные. [SDD 009](../specs/009-agent-role-tools.md).

Проверки: `just python-check` из корня или команды Ruff, mypy и pytest из [engineering](../engineering.md). Покрытие этого контура — в [coverage](../coverage.md).

## Приветствия

Чистые приветствия, включая «салам алейкум», благодарности и прощания получают
короткий ответ LLM без MCP и карточек источников. Старый диалог и выбранный пункт
не запускают поиск для такой реплики. Приветствие вместе с вопросом о компании
обрабатывается обычным способом с проверкой источников. Ошибки модели не
подменяются локальным ответом. [Спецификация](../specs/conversational-messages.md).

## Контекстный разбор пункта

Режим пояснения получает PageContext.selection, читает конкретный материал через прежние MCP tools и отвечает краткими пунктами. Write-tools исключены, неподдерживаемый вызов отвергается. Пустой поиск допускает явно общее объяснение термина; правила обычного чата и проверки цитат сохраняются.

[Сценарий и ограничения](../specs/010-selection-explanation.md).

## Development и уточнение

[Agent-v2](../../ai-agent/evals/agent-v2/README.md) сохраняет 25 development-кейсов с 11 контрактами исходного snapshot. Новые get_work_tools/get_work_tool_context из SDD 009 не объявляются покрытыми этим историческим набором. Manifest фиксирует свой набор схем, отчёт отдельно фиксирует весь текущий runtime-каталог.

Runtime onboarding-v5.1-clarify прямо просит значения недостающих параметров, сохраняет уточнение после recovery и исправляет только цитаты при repair. На сайте изменение доступно после успешного деплоя Python; fixtures не подключают данные Go/UI. [Сохранённые trials](../../ai-agent/evals/reports/development-v2-20261115.md) относятся к snapshots до реорганизации; их hashes/ответы не переписываются.

[Спецификация уточнения и development](../specs/010-agent-clarification-and-development.md).

## Пункт адаптации

«Разобрать пункт» передаёт название, описание, ответственного и прикреплённые
Confluence page_ids через PageContext.selection. Для task агент также читает
команду и каталог инструментов. Ответ: смысл/назначение, первые шаги, материалы
или страницы сервисов. Контакт добавляется только при необходимости. Уточнения
получают тот же контекст из общей панели/полного чата. Запись и изменение
прогресса запрещены. [Сценарий](../specs/ask-agent-checklist.md).

## Текущая задача и тон общения

Для вопросов о следующем/текущем шаге используется свежий веб-checklist snapshot,
если он передан, а не отдельный серверный demo next_task_id. Ответ называет один
пункт в процессе и первый шаг; ссылка относится к этому пункту. Для такого хода
доступны чтения материалов, исключены серверный прогресс и операции. Без snapshot
сохраняется прежний MCP-маршрут. Явный разбор другого пункта остаётся отдельным.

Основной промпт задаёт дружелюбный тон на «ты», уважительную поддержку без
канцелярита, грубости и обещаний. Короткие разговорные вопросы и просьбы о
поддержке не требуют корпоративного поиска. Составные рабочие вопросы, источники,
права и подтверждение операций сохраняют прежние проверки.
[Спецификация](../specs/current-checklist-and-dialogue.md).

## Сохранённый development snapshot после PR #67

[Отчёт DeepSeek от 15 ноября](../../ai-agent/evals/reports/deepseek-development-20261115.md)
сохраняет trial agent-v1: 18 выполнены, 2 blocked, structural 12/18,
Codex-assisted 11/18. Это измерение того snapshot, не актуального runtime
после исправлений диалога и чек-листа. Исходные JSON и SHA не менялись;
новых LLM-запросов и holdout при переносе отчёта не выполнялось.

Обычные реплики о связи, настроении и возможностях обрабатываются разговорным режимом с генерацией LLM; корпоративный поиск для них не нужен. Приветствия распознаются как целые фразы с учётом регистра, пунктуации и распространённых транслитераций. В разговорный режим не передаются история и контекст страницы. Содержательные дополнения и поручения сохраняют прежние проверки.

Заявки на доступ используют `prepare_service_action(request_access)` и
ручное подтверждение на сайте, как Jira. После ответа с параметрами агент
заново читает каталог текущего профиля и использует точный `resource_key`;
прямой submit в Go-контуре запрещён. Регрессионные тесты находятся в
`tests/test_access_actions.py`; поведение описано в [SDD 007](../specs/007-agent-access-confluence.md).

Общий вопрос «какая задача сейчас?» или «С чего начать сегодня?» выбирает
свежий пункт «В процессе», даже после разбора другого задания. Старый selection
снимается; уточнение «С чего начать этот пункт?» сохраняет выбранный пункт.
Кнопка подсказки и текст используют один контекст.

Для списка задач команды в Jira агент сначала читает доступные доски, затем
задачи этих досок через `get_service_context`. Личный список используется для
«моих задач»; пустота личного списка не является отказом доступа к команде.
Явный новый вопрос о сервисе прекращает продолжение старой заявки на доступ.
Чтение списка исключает инструменты записи и каталог доступов; неполнота
отмечается при лимите или ошибке чтения доски. Контракты и ACL прежние.
Регрессии, включая Flask/DeepSeek HTTP boundary без платных вызовов:
`tests/test_jira_task_lists.py`. [Поведение](../specs/008-remaining-agent-services.md#список-задач-jira-в-чате).

В режиме разбора узкое уточнение получает короткий ответ на последний вопрос.
Промпт предлагает полный разбор только по явному запросу. Для возможных
препятствий сохраняются проверки источников, а гипотезы обозначаются как риски.
