# AI Buddy

Прототип помощника для стажёра Авито. Стажёр спрашивает о команде и инструментах, видит этап адаптации и следующий шаг, а действие в корпоративном сервисе выполняется только после его подтверждения. Ответы на критерии кейса собраны в [docs/criteria.md](docs/criteria.md). Маршрут проверки — в [docs/demo.md](docs/demo.md).

Все имена, инструкции и сервисы в прототипе учебные. Это не регламенты Авито.

## Структура

`web/` содержит интерфейс и Go API Buddy, `ai-agent/` — Flask и MCP,
`extension/` — расширение Chromium. Девять корпоративных сервисов лежат
в `corporate-services/`, пятнадцать инструментов — в `tools/`.
У каждого свой Go-процесс и своя база PostgreSQL. Общие сборка и проверки
находятся в `ops/`.

Тесты Go лежат рядом с проверяемым кодом. `just service-go-check` проверяет
внешние модули, а `just external-check` запускает все 24 API в Docker.
[Как устроены проверки](docs/engineering.md).

## Запуск для проверки

Все команды ниже выполняй из корня клонированного репозитория `ai-buddy`.
Для полного стенда нужны запущенный Docker Desktop (или Docker Engine с Compose)
и ключ DeepSeek. Node.js, Go и Python на хосте для этого режима не нужны:
зависимости собираются в контейнерах.

Сначала проверь, что Docker запущен и доступен:

```bash
docker info
docker compose version
```

Если `docker info` сообщает, что не может подключиться к Docker API, запусти
Docker Desktop и дождись готовности движка. Для первого запуска создай корневой
`.env`; если он уже есть, отредактируй его, не перезаписывая настройки.

```bash
cp .env.example .env
```

В `.env` заполни `DEEPSEEK_API_KEY`. Модель и адрес уже заданы: `DEEPSEEK_MODEL=deepseek-flash`, `DEEPSEEK_BASE_URL=https://api.deepseek.com`.

```bash
docker compose --profile hr --profile jira config --quiet
COMPOSE_PARALLEL_LIMIT=1 docker compose --profile hr --profile jira up -d --build --wait --wait-timeout 900
```

Лимит параллельности нужен при сборке сервисов, которые используют один тег образа.
Первая сборка скачивает образы и зависимости. `--wait-timeout 900` ограничивает
ожидание готовности контейнеров, а не всю сборку.

Проверь состояние и доступность веба:

```bash
docker compose --profile hr --profile jira ps
curl -fsS -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:5173/
```

Ожидается HTTP 200. Одноразовые миграции завершаются с кодом 0; это нормально.

Открой [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Чат идёт по цепочке веб → Go → Flask → DeepSeek → MCP → API сервиса. При сбое модели чат показывает ошибку и не подставляет учебный ответ.
С пустым ключом агент не проходит проверку готовности: команда с `--wait`
завершится ошибкой, даже если веб и другие контейнеры уже запустились. Заполни
ключ и повтори команду запуска. Проверка готовности не делает платный запрос
и не проверяет баланс ключа — работу модели проверь вопросом в чате.

Остановка: `docker compose --profile hr --profile jira down`. Том базы сохраняется. `down -v` удаляет данные.

Прямой платный запрос к агенту: `sh ops/docker/check-agent.sh`. Для обычной проверки достаточно интерфейса.

### Только веб без серверов

Нужны Node.js **24.22.2** (версия также в `.nvmrc`) и npm **11**. Если используешь
nvm, выполни `nvm install` и `nvm use` из корня проекта. Проверь версии перед
установкой зависимостей:

```bash
node --version
npm --version
```

Затем запусти веб на локальных данных браузера:

```bash
npm ci
npm run dev --workspace=@ai-buddy/web -- --host 127.0.0.1 --strictPort
```

Открой http://127.0.0.1:5173/. Если порт занят, сначала останови другой экземпляр
веба или Compose; `--strictPort` не даст незаметно перейти на другой адрес.
Остановка dev-сервера — Ctrl+C. `VITE_API_ENABLED` должен быть выключен
(по умолчанию он выключен); не включай его для режима без серверов.

Этот режим не вызывает модель. Ответы на опросы и прочтение уведомлений сохраняются в браузере. При запуске через Compose они сохраняются в PostgreSQL. Для сценария с подтверждением действия нужен Compose выше.

## Порядок проверки

1. Войди как Ольга Соколова в «Авито Доставке».
2. На главной посмотри этап и ближайший шаг. Открой «Мою адаптацию» и найди три опроса с обводкой. Напоминание в колокольчике открывает опрос текущего этапа. После отправки анкета отмечается выполненной. [Как проверить опросы](docs/demo.md#опросы-стажировки-и-уведомления).
3. В чате спроси, кто наставник. Дождись ответа: кнопка отправки на время запроса отключена. В ответе есть источник. При ошибке модели появляется сообщение, что Buddy временно недоступен.
4. Попроси Buddy оформить доступ к BI и уточни параметры. Открой карточку, подтверди отправку и найди тот же номер в «Моих заявках». [Шаги проверки заявки](docs/demo.md#заявка-на-доступ-из-чата).
5. Войди как Александр Ким и запроси доступ к тому же ресурсу Доставки. Buddy объяснит отказ, запись не появится.
6. Под тем же продуктом войди наставником и открой прогресс стажёра.

Календарь: в чате спроси «Какие события у меня на этой неделе?» либо задай
обе даты периода. Попроси «Создай созвон Разбор задачи завтра в 15:00»:
проверь карточку и подтверди — запись появится в «Событиях» (`/events`).
Веб и агент читают один серверный календарь. [Проверка и границы MVP](docs/demo.md#календарь-в-чате).
У подготовленного действия должна быть ссылка `/actions/:id`: сообщение «готово»
со ссылкой только на календарь не считается подготовкой и проверяется runtime.

Подробные шаги и ожидаемый результат — в [docs/demo.md](docs/demo.md).

## Тесты и покрытие

Полная проверка: `just check`. По частям: `just frontend-check`, `just python-check`, `just go-check`.

Порог покрытия — выше 80% отдельно для веба, Go API и Python-агента, без усреднения. Последний замер: веб 91,97% строк, Python и Go выше порога. Команды, точные числа и методика для Go — в [отчёте покрытия](docs/coverage.md).

## Состав

| Путь | Что внутри |
| --- | --- |
| `web/frontend/`, `web/backend/` | Веб Buddy и Go API |
| `ai-agent/` | Flask, цикл агента и MCP |
| `corporate-services/` | Учебные HR-сервисы, у каждого свой процесс и база |
| `tools/` | Jira, Confluence и рабочие инструменты |
| `extension/` | Расширение Chromium: вопрос с контекстом страницы |
| `contracts/` | OpenAPI и схемы MCP |
| `docs/specs/` | SDD: поведение агента и инструментов |
| `ops/` | Docker, nginx, сборка сайтов и развёртывание |

Корпоративные сайты в Compose открываются на портах 5181–5192. Jira — [http://127.0.0.1:5189/](http://127.0.0.1:5189/), управление доступами — 5190, Confluence — 5191. Перед переходом войди в Buddy: соседний порт подхватывает текущий профиль.

Расширение: `npm run build --workspace=@ai-buddy/extension`, затем загрузи `extension/dist/` в Chromium как unpacked extension.

Buddy отвечает на текущий вопрос: контакт наставника, один следующий шаг или инструкция. Каталог инструментов направления он читает через `get_work_tools` и `get_work_tool_context`. [Ограничения](docs/specs/009-agent-role-tools.md).

[Ограничения MVP](docs/mvp.md#ограничения-mvp): агент читает данные 13 рабочих сервисов; запуск SQL/Postman, отправка сообщений и изменение прогонов/дизайн-ревью через чат остаются за рамками MVP.

## Разобрать пункт адаптации

В «Моей адаптации» нажми «Разобрать пункт»: рядом откроется панель Buddy с
объяснением смысла пункта, первыми шагами и ссылками на материалы или страницы
сервисов. Уточнения сохраняют контекст пункта. «Спросить Buddy» и плавающая
кнопка открывают ту же панель для общего вопроса. Полный чат использует ту же
историю; переход доступен из панели и навигации. Разбор разрешает только чтение
и не меняет прогресс. [Сценарий и ограничения](docs/specs/ask-agent-checklist.md).

Чистые приветствия (например, «салам алейкум») получают короткий ответ без поиска
и карточек источников. Приветствие вместе с корпоративным вопросом сохраняет
проверку данных. [Поведение](docs/specs/conversational-messages.md).

На вопрос о следующем шаге Buddy использует пункт «В процессе» из видимой адаптации.
После отметки или отправленной анкеты контекст обновляется. С Buddy можно говорить
на «ты» и просить поддержки; корпоративные факты и операции сохраняют проверки.
[Поведение и ограничения](docs/specs/current-checklist-and-dialogue.md).
