# AI Buddy

Агент читает найм, увольнения, бенефиты и Jira и готовит действия с ручным подтверждением по ссылке из чата. [Возможности и проверки](docs/components/service-actions.md).

[Continuous delivery](docs/components/continuous-delivery.md).

[Серверное развёртывание с паролем](docs/components/server-deployment.md).

Живая AI-интеграция и настройки DeepSeek: [SDD 004](docs/specs/004-agent-service-integration.md), [запуск Compose](docs/components/docker-compose.md).

Прототип помощника для стажёров Авито. В веб-сервисе стажёр сможет следить за онбордингом, общаться с Buddy и получать напоминания. Браузерное расширение даст быстрый доступ к Buddy и позволит задать вопрос о текущей странице.

В репозитории есть пользовательский demo-фронтенд, Go API и отдельный Python AI-сервис; текущее состояние компонентов различается. Для него используй `npm ci` из корня, затем `npm run dev --workspace=@ai-buddy/web`. Demo-adapter хранит прогресс, заявки и ответы Buddy в `localStorage`, поэтому веб-приложение можно показать без Go и Python сервисов. Версии инструментов и локальное окружение описаны в [стеке проекта](docs/stack.md). Состояния backend и AI описаны в документации компонентов.

## Структура репозитория

| Путь | Что внутри |
| --- | --- |
| `web/frontend/`, `web/backend/` | Веб Buddy и Go API |
| `extension/` | Расширение Chromium |
| `corporate-services/` | Девять разделов каталога, включая управление доступами |
| `tools/jira/`, `tools/confluence/` | Jira и Confluence. API остальных инструментов пока подключается в `web/backend/internal/worktools/` |
| `ai-agent/` | Python-сервис, MCP и оценка ответов |
| `ops/` | Сборка демосайтов, Docker, nginx и развёртывание |

## Запуск через Docker Compose

Из корня репозитория с запущенным Docker:

```bash
docker compose up -d --build --wait --wait-timeout 900
```

Открой [AI Buddy](http://127.0.0.1:5173/). PostgreSQL, Go, веб, Flask и Python MCP поднимаются из одной конфигурации. Веб-чат использует прежние демоданные. Для прямой проверки Python-агента выполни `sh ops/docker/check-agent.sh`. Чтобы добавить корпоративные сайты и их Go API, запусти ту же команду с `docker compose --profile hr`. [Настройки, проверка и остановка](docs/components/docker-compose.md)

## Фронтенд

```bash
npm ci
npm run dev --workspace=@ai-buddy/web
```

Открой `http://localhost:5173/`. На стартовом экране выбери продукт, затем аккаунт стажёра, наставника или руководителя. В четырёх командах показаны первый день, экватор и финал стажировки. Стажёр попадёт на `/home`, наставник и руководитель — в кабинет `/staff`. Чтобы выбрать другой аккаунт, нажми «Выйти из аккаунта».

В кабинете наставник и руководитель видят прогресс стажёра своей команды и могут опубликовать для него ссылку или файл. Публикации сохраняются в браузере и видны стажёру в «Корпоративных сервисах».

Расширение собирается командой `npm run build --workspace=@ai-buddy/extension`, после чего каталог `extension/dist/` можно загрузить в Chromium как unpacked extension. После установки питомец появляется справа внизу на обычных веб-страницах, а при наведении показывает действие «Задать вопрос». Chrome запрашивает доступ к сайтам при установке расширения один раз.

Полный локальный набор проверок запускается командой `just check`. Отдельные проверки frontend, Python и Go доступны через `just frontend-check`, `just python-check` и `just go-check`.

`npm run test:coverage --workspace=@ai-buddy/web` запускает тесты веб-приложения, проверяет порог покрытия строк 85% и записывает отчёт в `web/coverage/lcov.info`. В CI отчёт доступен в артефакте `web-coverage`.

## Корпоративные демосайты

В разделе «Корпоративные сервисы» и поиске есть ссылки на девять внешних демосайтов. Запусти внешние сайты во втором терминале.

```bash
npm run dev --workspace=@ai-buddy/corporate-services
```

Сайты открываются на портах `5181–5188`. Каждый показывает синтетический демопрофиль. Для других адресов скопируй `web/frontend/.env.example` и `ops/service-sites/frontend/.env.example` в `.env` рядом с примерами. Команда `npm run build --workspace=@ai-buddy/corporate-services` создаёт отдельную сборку для каждого сайта в `ops/service-sites/dist/`. [Карта адресов и запуск одного сайта](docs/components/corporate-services.md)

### Jira: доски и задачи

`docker compose --profile hr --profile jira up --build -d` запускает самостоятельный Jira-клон с отдельной PostgreSQL. Открой карточку Jira в «Инструментах и доступах» или http://localhost:5189/. Доступны пространства, доски, создание и редактирование задач. [Настройки, API и проверки](docs/components/jira.md).

«Управление доступами» доступно из корпоративных сервисов на порту 5190: каталог, гибкие формы и демосогласование. [Описание и ограничения](docs/components/access-portal.md).

Корпоративные сайты на портах того же хоста автоматически используют активный
аккаунт Buddy без повторного выбора профиля. Перед открытием сервиса войдите в Buddy.

Confluence: самостоятельная учебная база на 5191 из «Инструментов и доступов». Агент может читать её и отправлять серверные заявки по явной просьбе; [поведение и ограничения](docs/specs/007-agent-access-confluence.md). Портал доступов 5190 и чат используют общую PostgreSQL; согласование не выдаёт реальные права.

Чат не содержит постоянной формы учебного задания согласий. Если модель
пропускает MCP на содержательном вопросе, runtime получает свежий контекст
и повторяет ответ в пределах прежнего лимита вызовов.

Ответы Buddy оформляются абзацами и списками, источники показаны отдельными
карточками. [Каких данных пока не хватает агенту](docs/ai/answer-gaps.md).

Buddy отвечает на текущий вопрос: контакт наставника, один следующий шаг
или инструкция, без автоматической сводки команды и всего чек-листа.

Агент читает каталог инструментов направления и записи 13 рабочих сервисов
через get_work_tools/get_work_tool_context. [Контракты и ограничения](docs/specs/009-agent-role-tools.md).

[Ограничения MVP](docs/mvp.md#ограничения-mvp): агент читает данные 13 рабочих
сервисов; запуск SQL/Postman, отправка сообщений и изменение прогонов/дизайн-ревью
через чат остаются за рамками MVP.
