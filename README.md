# AI Buddy

Прототип помощника для стажёра Авито. Стажёр спрашивает о команде и инструментах, видит этап адаптации и следующий шаг, а действие в корпоративном сервисе выполняется только после его подтверждения. Ответы на критерии кейса собраны в [docs/criteria.md](docs/criteria.md). Маршрут проверки — в [docs/demo.md](docs/demo.md).

Все имена, инструкции и сервисы в прототипе учебные. Это не регламенты Авито.

## Структура

`web/` содержит интерфейс и Go API Buddy, `ai-agent/` — Flask и MCP,
`extension/` — расширение Chromium. Девять корпоративных сервисов лежат
в `corporate-services/`, пятнадцать инструментов — в `tools/`.
У каждого свой Go-процесс и своя база PostgreSQL. Общие сборка и проверки
находятся в `ops/`.

Тесты Go лежат рядом с проверяемым кодом. `just service-go-check` проверяет
внешние модули, а `just external-check` запускает все 24 API в Docker.
[Как устроены проверки](docs/engineering.md).

## Локальный запуск для проверки

Для проверки чата и действий агента понадобятся Docker Desktop (либо Docker
Engine с Compose) и действующий ключ DeepSeek. Устанавливать Go, Python и Node.js
для этого способа запуска не нужно: Docker запустит веб-интерфейс, серверы,
базы данных и учебные корпоративные сервисы.

Основные команды Docker Compose можно выполнять в PowerShell или терминале
Linux/macOS — `sh` для них не нужен. Docker должен работать с Linux-контейнерами.
Для первой сборки и ответов DeepSeek нужен доступ к интернету.

Сначала получите исходники (для приватного репозитория нужен доступ):

```bash
git clone https://github.com/dureppa/ai-buddy.git
cd ai-buddy
```

Если проект уже скачан, откройте его папку. Вместо Git можно скачать ZIP
репозитория и распаковать архив. Все следующие команды выполняются из папки
`ai-buddy`, где находятся `README.md` и `docker-compose.yml`.

1. Запустите Docker и проверьте `docker info` и `docker compose version`.
   Обе команды должны завершиться без ошибки.
2. Скопируйте файл `.env.example` в той же папке и назовите копию `.env`
   (без расширения `.txt`). Если `.env` уже существует, сохраните его настройки.

3. Откройте `.env` в текстовом редакторе и укажите свой ключ после
   `DEEPSEEK_API_KEY=`. Через этот ключ агент получает ответы модели. Модель
   `deepseek-flash` и адрес API уже настроены; остальные значения можно оставить
   без изменений.
4. Соберите проект командой ниже. Сервисы могут собираться одновременно,
   поэтому Docker должно быть выделено достаточно памяти. На конфигурации
   с **4 ГБ** используйте дополнительный последовательный вариант ниже.

```bash
docker compose --profile hr --profile jira build
```

После **успешной сборки** запустите сервисы и дождитесь их готовности:

```bash
docker compose --profile hr --profile jira up -d --no-build --wait --wait-timeout 900
```

5. Откройте [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Выберите
   «Авито Доставка», затем Ольгу Соколову. При локальном запуске пароль не нужен.
6. Перейдите к [порядку проверки](#порядок-проверки) ниже. Для первой проверки
   чата спросите: «Кто мой наставник?». Ответ должен содержать имя и источник.

На первый запуск ориентировочно закладывайте **10–20 минут**: Docker скачивает
образы и собирает сервисы. Это оценка для планирования, а не замер на каждом
компьютере: время зависит от интернета, процессора и доступной памяти.
Повторная сборка использует кэш и не скачивает заново неизменившиеся зависимости.
Если исходники и настройки не менялись, для запуска уже собранного стенда
достаточно повторить команду запуска из шага 4; пересборка не требуется.

### Запуск при небольшом объёме памяти

Если Docker выделено мало памяти или общая сборка завершается ошибкой
`cannot allocate memory`, используйте отдельный сборщик Docker с ограничением
одновременно выполняемых шагов. Настройка уже находится в
`ops/docker/buildkitd-low-memory.toml`; редактировать её не нужно.
Файл `.env` подготовьте так же, как описано выше. Проверьте наличие Buildx
командой `docker buildx version`. Этот способ проверен на Docker с **4 ГБ**
памяти, Compose 5.3.1 и Buildx 0.35.0.

Один раз создайте сборщик из корня проекта:

```bash
docker buildx create --name ai-buddy-low-memory --driver docker-container --driver-opt default-load=true --buildkitd-config ops/docker/buildkitd-low-memory.toml --bootstrap
```

Затем соберите проект через него:

```bash
docker compose --profile hr --profile jira build --builder ai-buddy-low-memory
```

После успешной сборки остановите сборщик, чтобы освободить память, и запустите
сервисы обычной командой:

```bash
docker buildx stop ai-buddy-low-memory
docker compose --profile hr --profile jira up -d --no-build --wait --wait-timeout 900
```

Эти команды не требуют `sh` и подходят для PowerShell и терминалов Linux/macOS.
При повторной сборке используйте то же имя: заново создавать сборщик не нужно.
Его кэш хранится отдельно, поэтому первая сборка этим способом скачает зависимости
заново. Текущий сборщик Docker по умолчанию не переключается.

### Проверка и остановка

Ключ DeepSeek используется для ответов агента; запросы оплачиваются по тарифу
вашего аккаунта. Без ключа запуск не завершится успешно. При ошибке ключа или
недоступности DeepSeek чат покажет сообщение о сбое.

Если запуск не удался:

- При сообщении о недоступном Docker убедитесь, что Docker запущен:
  `docker info`.
- Стенд использует порты 5173, 5181–5192, 8181–8188 и 8190–8191. При ошибке
  `address already in use` остановите приложение, занимающее указанный порт.
- Если не запускается AI-сервис, проверьте, что ключ указан в `.env` в корне
  проекта, и повторите команду запуска.
- [Дополнительная диагностика и состав сервисов](docs/components/docker-compose.md).

Чтобы остановить проект, выполните в той же папке:

```bash
docker compose --profile hr --profile jira down
```

Сохранённые данные останутся для следующего запуска.

### Просмотр интерфейса без AI

Этот способ подходит для знакомства с экранами. Чат с LLM и отправка заявок
через сервер в нём недоступны. Нужны Node.js **24.22.2** и npm **11**.
Если используете nvm, выберите версию проекта командами `nvm install` и `nvm use`.

Из папки проекта выполните:

```bash
npm ci
npm run dev --workspace=@ai-buddy/web -- --host 127.0.0.1 --strictPort
```

Откройте [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Остановка — Ctrl+C
в терминале. Не запускайте этот режим одновременно с Docker-версией: они
используют один порт. Для этого режима оставьте `VITE_API_ENABLED` выключенным
(значение по умолчанию).

## Порядок проверки

1. Войди как Ольга Соколова в «Авито Доставке».
2. На главной посмотри этап и ближайший шаг. Открой «Мою адаптацию» и найди три опроса с обводкой. Напоминание в колокольчике открывает опрос текущего этапа. После отправки анкета отмечается выполненной. [Как проверить опросы](docs/demo.md#опросы-стажировки-и-уведомления).
3. В чате спроси, кто наставник. Дождись ответа: кнопка отправки на время запроса отключена. В ответе есть источник. При ошибке модели появляется сообщение, что Buddy временно недоступен.
4. Попроси Buddy оформить доступ к BI и уточни параметры. Открой карточку, подтверди отправку и найди тот же номер в «Моих заявках». [Шаги проверки заявки](docs/demo.md#заявка-на-доступ-из-чата).
5. Войди как Александр Ким и запроси доступ к тому же ресурсу Доставки. Buddy объяснит отказ, запись не появится.
6. Под тем же продуктом войди наставником и открой прогресс стажёра.

Календарь: в чате спроси «Какие события у меня на этой неделе?» либо задай
обе даты периода. Попроси «Создай созвон Разбор задачи завтра в 15:00»:
проверь карточку и подтверди — запись появится в «Событиях» (`/events`).
Веб и агент читают один серверный календарь. [Проверка и границы MVP](docs/demo.md#календарь-в-чате).
У подготовленного действия должна быть ссылка `/actions/:id`: сообщение «готово»
со ссылкой только на календарь не считается подготовкой и проверяется runtime.

Подробные шаги и ожидаемый результат — в [docs/demo.md](docs/demo.md).

## Тесты и покрытие

Полная проверка: `just check`. По частям: `just frontend-check`, `just python-check`, `just go-check`.

Нагрузочные тесты frontend, Go и Python без обращений к LLM: `just load-test 120 8`
или `just load-test 1000 16`. Только frontend: `just load-frontend 1000 16`.
Сервисы и ключ модели не нужны. RPS, p50/p95/p99 и границы замера описаны в
[инструкции](docs/load-testing.md). Go benchmark: `just load-bench`.

Порог покрытия — выше 80% отдельно для веба, Go API и Python-агента, без усреднения. Последний замер: веб 92,30% строк, Python и Go выше порога. Команды, точные числа и методика для Go — в [отчёте покрытия](docs/coverage.md).

## Состав

| Путь | Что внутри |
| --- | --- |
| `web/frontend/`, `web/backend/` | Веб Buddy и Go API |
| `ai-agent/` | Flask, цикл агента и MCP |
| `corporate-services/` | Учебные HR-сервисы, у каждого свой процесс и база |
| `tools/` | Jira, Confluence и рабочие инструменты |
| `extension/` | Расширение Chromium: вопрос с контекстом страницы |
| `contracts/` | OpenAPI и схемы MCP |
| `docs/specs/` | SDD: поведение агента и инструментов |
| `ops/` | Docker, nginx, сборка сайтов и развёртывание |

Корпоративные сайты в Compose открываются на портах 5181–5192. Jira — [http://127.0.0.1:5189/](http://127.0.0.1:5189/), управление доступами — 5190, Confluence — 5191. Перед переходом войди в Buddy: соседний порт подхватывает текущий профиль.

Расширение — необязательная отдельная сборка. Для неё нужны Node.js 24.22.2
и npm 11 на компьютере, даже если веб запущен через Docker. Из корня проекта:

```bash
npm ci
npm run build --workspace=@ai-buddy/extension
```

В Chromium откройте `chrome://extensions`, включите режим разработчика и загрузите
папку `extension/dist/` кнопкой «Загрузить распакованное расширение».
Мини-чат расширения сейчас использует локальные ответы; полный сценарий
с LLM и заявками проверяется в веб-приложении. [Описание расширения](docs/components/extension.md).

Buddy отвечает на текущий вопрос: контакт наставника, один следующий шаг или инструкция. Каталог инструментов направления он читает через `get_work_tools` и `get_work_tool_context`. [Ограничения](docs/specs/009-agent-role-tools.md).

[Ограничения MVP](docs/mvp.md#ограничения-mvp): агент читает данные 13 рабочих сервисов; запуск SQL/Postman, отправка сообщений и изменение прогонов/дизайн-ревью через чат остаются за рамками MVP.

## Разобрать пункт адаптации

В «Моей адаптации» нажми «Разобрать пункт»: рядом откроется панель Buddy с
объяснением смысла пункта, первыми шагами и ссылками на материалы или страницы
сервисов. Уточнения сохраняют контекст пункта. «Спросить Buddy» и плавающая
кнопка открывают ту же панель для общего вопроса. Полный чат использует ту же
историю; переход доступен из панели и навигации. Разбор разрешает только чтение
и не меняет прогресс. [Сценарий и ограничения](docs/specs/ask-agent-checklist.md).

Чистые приветствия (например, «салам алейкум») получают короткий ответ без поиска
и карточек источников. Приветствие вместе с корпоративным вопросом сохраняет
проверку данных. [Поведение](docs/specs/conversational-messages.md).

На вопрос о следующем шаге Buddy использует пункт «В процессе» из видимой адаптации.
После отметки или отправленной анкеты контекст обновляется. С Buddy можно говорить
на «ты» и просить поддержки; корпоративные факты и операции сохраняют проверки.
[Поведение и ограничения](docs/specs/current-checklist-and-dialogue.md).
